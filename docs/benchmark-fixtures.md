# Benchmark fixtures

The Expo, bare React Native and Exact fixtures live in one repository,
[`appandflow/stim-benchmarks`](https://github.com/appandflow/stim-benchmarks).
The standalone native fixtures (Xcode, SwiftPM, Gradle) are generated by
`scripts/agent-benchmark/native-fixtures.mjs` and are not in that repository.
Trailhead, the Expo app earlier recordings used, keeps its own repository; the
driver serves it when the benchmark root sets no `FIXTURE_DIR`.

```text
stim-benchmarks/
  expo/                      Expo calculator, development build, ios/ and android/ committed
  bare/                      the same calculator on a bare React Native project
  exact/fixture.json         Exact descriptor
  exact/stim-bench-exact/    the Exact app, in the folder Exact requires
```

Each fixture directory is a complete project with its own lockfile. A benchmark
root serves one fixture directory; the golden state, targets and results of a
root belong to its fixture.

## Pins

```text
FIXTURES_COMMIT=<40-hex commit of the stim-benchmarks checkout>
FIXTURE_DIR=expo|bare
```

The fixtures were validated at `a1de1c29d5a49305287590e4ab00301c356fdc05`.

`STIM_BENCH_FIXTURE` names a clean checkout of the repository root, its own
clone (not a worktree of another repository, whose warm would carry from that
repository). The driver reads `<checkout>/<FIXTURE_DIR>/fixture.json`, runs Stim
and the control tools in that directory, and creates worktrees of the whole
repository; the prompt tells the agent which directory holds the app. Without
`FIXTURE_DIR` the driver checks `TRAILHEAD_FIXTURE_COMMIT` and uses Trailhead's
names. The Exact root sets only `FIXTURES_COMMIT`.

## React Native fixture contract

`fixture.json`, with paths relative to the fixture directory:

| Field                                      | Use                                                                                                                                                                                                                         |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schemaVersion`                            | `1`                                                                                                                                                                                                                         |
| `kind`                                     | `expo` or `bare`: the matrix row and the control Metro warm-up (`expo export` or `react-native bundle`)                                                                                                                     |
| `name`                                     | Control device names (`<name> <run-id>`, `<name>_<run-id>`) and the native-change marker                                                                                                                                    |
| `ios.bundleId`, `ios.product`              | `agent-device open`, the watcher's process match `<product>.app/<product>`                                                                                                                                                  |
| `android.applicationId`                    | `agent-device open`, `pidof`, the installed APK label                                                                                                                                                                       |
| `ios.nativeChange`, `android.nativeChange` | `file` and `anchor` where the native-change task edits; preflight refuses a fixture where the anchor is not exactly once in the file                                                                                        |
| `rootComponent`                            | `file`, `name` and `declaration` (`export default function <name>() {`): the error-fix injection inserts its `throw` after the declaration, and both `file` and `name` are the source markers the diagnosis audit looks for |
| `proof`                                    | `screen` (the tab the proof opens), `file`, `row`, `rowLabel`, `subtitle`, `editedSubtitle`                                                                                                                                 |

The app-launch task is "Change the `<screen>` `<rowLabel>` from `<subtitle>` to
`<editedSubtitle>`", proven by the edited `file` and `agent-device wait text`
on `editedSubtitle`. The error-fix proof waits for `subtitle` and the
native-change proof for `row`. The three strings appear once on screen.

The native-change task sets the iOS window accessibility identifier and the
Android application label to `<name> <run-id>`. React Native 0.88 and Expo SDK
58 create the window in the scene delegate, not in `AppDelegate.swift`: the
bare template assigns `window = UIWindow(windowScene: windowScene)` in
`SceneDelegate.swift`, and Expo's `SceneDelegate` subclasses
`ExpoAppSceneDelegate`, so the change overrides
`scene(_:willConnectTo:options:)` there and sets the identifier after `super`.

The Expo fixture commits `ios/` and `android/` from `expo prebuild`: the
native-change task edits them, the control arm's error-fix copy carries
`ios/Pods` and `android` build outputs into them, and the Podfile.lock review
reads `ios/Podfile.lock`.

The bare fixture must not have `expo` in `node_modules`. Stim's fingerprint
treats a project whose `node_modules` holds `expo` as an Expo project, asks
`expo-modules-autolinking` for its modules, and refuses to fingerprint when the
list has no `expo` module, so such a bare app gets no build cache. Some
packages list `expo` as an optional peer (`@react-native-vector-icons/*`); a
lockfile carried over from an Expo app can install it. Check with
`npm ls expo` and `stim ios --plan --json` (its `fingerprint` must be set).

## Exact fixture

`exact/fixture.json`:

```json
{
  "schemaVersion": 1,
  "framework": "exact",
  "platform": "ios",
  "app": "stim-bench-exact",
  "source": "app.contract",
  "product": "Stim Bench Exact",
  "bundleId": "dev.stim.bench.exact",
  "crash": { "source": "app.ts", "anchor": "<one line of app.ts>", "language": "typescript" }
}
```

Exact names the generated Cargo package after the app's folder, so the app sits
in `exact/<app>` and every worktree of the repository keeps that name. The app
implements the standalone native acceptance contract: `native-revision-one`
once in `source`, `Count: 0` and an `Increment` button. The driver reads it with
`node scripts/agent-benchmark/native-driver.mjs prepare|dispatch|collect exact-ios ...`
and `STIM_BENCH_FIXTURE` set to the checkout. The control arm's error-fix copy
never carries `target/` (Exact refuses a copied one; Cargo reuses
`~/.cache/exact`), and the runner `PATH` includes `~/.cargo/bin`.

`crash.anchor` is a line that occurs exactly once in `crash.source`; the setup
inserts the crash statement on the line after it (`panic!` for `rust`,
`throw new Error` for `typescript`). Exact app code cannot end the process at
startup: the anchor is the first statement of a resource the app asks for at
launch, so the error fails that request, the screen shows
`The app failed to start.`, and the token reaches only the device log
(`stim logs --errors --source device`, or `log show` on the simulator).

## Expo agent CLI skills

`STIM_BENCH_EXPO_SKILLS` names the skills directory of the Expo skills plugin
(`plugins/expo/skills` of `expo/skills`), one subdirectory per skill. The runner
installs each subdirectory with a `SKILL.md` as its own skill, and
`EXPO_SKILLS_SHA256` is `directoryDigest` of that directory, exported by
`expo-agent-cli.mjs`.

## Launch-crash design for platforms without JavaScript

The error-fix task is the one the React Native rows use: "The app fails on
launch. Reproduce it and capture the runtime error before inspecting application
source, fix it, and verify the repair." The coordinator commits the crash to a
fixture checkout before dispatch, and neither the category nor the token appears
in the prompt.

| Platform                        | Injected change                                                                             | Where the error surfaces                                                                                |
| ------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Standalone iOS, macOS (SwiftPM) | `init()` in the SwiftUI `App` struct that calls `NSLog` and `fatalError` with the run token | unified log, `simctl launch --console`, stderr of the macOS binary, Stim logs                           |
| Standalone Android              | `throw IllegalStateException(token)` after `super.onCreate` in `MainActivity`               | logcat `FATAL EXCEPTION` with the token and the file and line                                           |
| Exact iOS                       | `panic!` or `throw` after the fixture's anchor line                                         | the device log only (`stim logs --errors --source device`); the screen shows `The app failed to start.` |

The token is `launchCrashToken(runId)`, the same value format as the JavaScript
crash. Proof: the token appears in command output before any command names the
source file (`nativeCrashReproduced`), the source equals the original byte for
byte afterwards (`launchCrashRepair`), only that file differs from the crash
commit, then the existing screenshot and process-identity proof. An injected
native crash changes native source, so each arm builds once more after the fix;
both arms start from the same warm outputs.

The Swift injection was type-checked with `swiftc`. The Exact injection was run
once on a simulator: the screen showed `The app failed to start.` and the token
appeared in `stim logs --errors --source device`. The Kotlin injection, and
whether its logs surface the token, are validated only by a first real run.
