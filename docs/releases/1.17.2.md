# 1.17.2

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the six npm packages. Commits that only changed those apps are not listed.

## New

- **`stim-server --loopback-only`** listens on `127.0.0.1` only and refuses any request that names a remote peer (`X-Forwarded-For`, as `tailscale serve` adds), so phones and other Macs cannot connect. `/health` reports `loopbackOnly: true`, and the flag applies only to serving, not to subcommands. The next Stim Desktop release starts its own server with it and requires stim-server 1.17.2. [5dbd21e9c](https://github.com/appandflow/stim/commit/5dbd21e9ca2885bd0a22e50d7d1fcea71943768b)
- **`stim doctor --json` reports a `lapsed` state and `expiresAt`** for build and device-host requests to remote Macs. A `pending` entry carries `expiresAt`, when the request lapses; `lapsed` means the request expired before approval, while `revoked` means the remote Mac refused or revoked this Mac. `stim doctor --fix` asks again on a lapsed request. [55a59ddce](https://github.com/appandflow/stim/commit/55a59ddceb4975d8981fbabde5b2888f0563df1b)

## Fixes

- `stim-server setup` tells apart Tailscale not installed (a download link), the Tailscale app turned off (turn it on from the menu bar icon), and a CLI-only install that is logged out (`tailscale up`), where it used to say only "Start Tailscale on this Mac". [2db7176c9](https://github.com/appandflow/stim/commit/2db7176c9f1daf0bf2c7991324ba7c534d5e7348)
- `stim-server service update --from <dir>` installs the `.tgz` packages of a client's build. It no longer asks the registry to vouch for Stim's own packages, so an unpublished version installs, and it still checks the registry signature of every dependency they bring from npm. [55a59ddce](https://github.com/appandflow/stim/commit/55a59ddceb4975d8981fbabde5b2888f0563df1b)
- When `npm audit signatures` fails, the error includes npm's own text: its JSON error summary, or its stderr after "did not print a JSON report:". [55a59ddce](https://github.com/appandflow/stim/commit/55a59ddceb4975d8981fbabde5b2888f0563df1b)
- `stim doctor` names a tool that is missing on one side of a toolchain comparison, such as "no CocoaPods there, CocoaPods 1.16.2 here", where it printed "CocoaPods null there". [55a59ddce](https://github.com/appandflow/stim/commit/55a59ddceb4975d8981fbabde5b2888f0563df1b)
- The hosted iOS and Android device status validators in `@stim-cli/core` accept a status without a placement `reason`. [27b518a23](https://github.com/appandflow/stim/commit/27b518a23757990d39744fe9aefb22cec9ab5c5e)

## Docs

- CLI text, `stim guide` topics and the website call a running workspace "active" where they said "live", including the `stim status` memory line. [116af6ee8](https://github.com/appandflow/stim/commit/116af6ee8335d37c922e29c35a71c84bfae4c97a)
- The website's remote Macs and settings pages and `stim guide` cover the `lapsed` state, `expiresAt` and `service update --from`. [55a59ddce](https://github.com/appandflow/stim/commit/55a59ddceb4975d8981fbabde5b2888f0563df1b)
- The website's remote Macs page describes the three Tailscale answers of `stim-server setup`. [2db7176c9](https://github.com/appandflow/stim/commit/2db7176c9f1daf0bf2c7991324ba7c534d5e7348)
- `stim guide settings` names the Desktop path "Remote Macs > Running here" where it said "Phones > Hosted here". [20333b70e](https://github.com/appandflow/stim/commit/20333b70ef09b59837114583dcd3f6b77d253f27)
