# 1.11.0

## New

- `stim status --json` reports each worktree's git state: changed and untracked files, ahead and behind its upstream, and whether the branch is merged. The merged check is cached per worktree, and paths macOS protects are skipped so status never triggers a privacy prompt. [#1230](https://github.com/appandflow/stim/pull/1230)
- A cache miss says why. `ios` and `android` print one line naming the changed native inputs, for example `cache miss: native dependency added: expo-clipboard`, and `status --json` reports `lastBuilds.<platform>.missReason`. [#1228](https://github.com/appandflow/stim/pull/1228)
- `stim status --json` reports each platform's last build, and `ios --plan` / `android --plan` predict whether the next build hits the cache. [#1178](https://github.com/appandflow/stim/pull/1178)
- `android --device-profile <id>` and the `android.deviceProfile` setting choose the owned AVD's hardware profile (default `pixel_6`), such as `pixel_fold` or `pixel_tablet`. Parked emulators are only reused for the same profile. [#1268](https://github.com/appandflow/stim/pull/1268)
- The machine setting `androidEmulatorApp` (`emulator` or `stim-desktop`) boots new owned emulators without a window on macOS and shows them in Stim Desktop. [#1292](https://github.com/appandflow/stim/pull/1292)
- `stim stop --slot default` stops only the workspace's default device. [#1176](https://github.com/appandflow/stim/pull/1176)
- `stim device lock` can lock the workspace's own simulator or emulator. [#1261](https://github.com/appandflow/stim/pull/1261)
- `stim logs --source agent` lists agent-device actions (taps, typing, screenshots) as log records, attributed to the device they drove. [#1179](https://github.com/appandflow/stim/pull/1179)
- `stim-server`:
  - Paired devices granted the `control` scope (`stim-server pair --control` or `stim-server devices grant <id> --control`) can run `reload` and `stop`. Every action is audited, and `stim-server log` prints the audit. [#1187](https://github.com/appandflow/stim/pull/1187)
  - `machine.get` reports the Mac's memory used and CPU usage, and `machine.history` returns the last hour of samples. [#1206](https://github.com/appandflow/stim/pull/1206), [#1253](https://github.com/appandflow/stim/pull/1253), [#1267](https://github.com/appandflow/stim/pull/1267)
  - `build.plan` predicts the next build. [#1189](https://github.com/appandflow/stim/pull/1189)
  - Device frames come from a native helper, compiled on first use, instead of repeated `simctl` screenshots. Clients that decode H.264 receive hardware-encoded video. [#1254](https://github.com/appandflow/stim/pull/1254), [#1265](https://github.com/appandflow/stim/pull/1265)
  - Frames report the lit iPhone Duo panel and the posture of iPhone Duo and Android foldables. [#1234](https://github.com/appandflow/stim/pull/1234), [#1277](https://github.com/appandflow/stim/pull/1277)
  - The status payload also exposes the home folder and the per-volume machine usage used by the phone app. [#1182](https://github.com/appandflow/stim/pull/1182)

## Fixes

- `stim stop` interrupts an `ios` or `android` build it would leave nothing to deploy to, instead of waiting silently for it to finish. A billable remote session is ended without waiting on the build, and any command that waits on the workspace says what it is waiting for. [#1300](https://github.com/appandflow/stim/pull/1300)
- `ios --remote eas` and `android --remote eas` create the remote session after the local build is ready, so a long build no longer leaves the EAS host's daemon idle until it exits. [#1216](https://github.com/appandflow/stim/pull/1216)
- `stim ios` with `iosSimulatorApp` set to `stim-desktop` opens Stim Desktop in the background instead of bringing it to the front. [#1256](https://github.com/appandflow/stim/pull/1256)

## QA

No-QA stable release explicitly authorized by the maintainer on 2026-09-25.
Omitted locally before the version commit: format:check, lint, typecheck, knip,
unit tests, test:e2e, test:runtime, test:compat, and the pre-tag native/manual
matrix. Retained before the version commit: candidate build, CLI and server
version, `guide agent`, and tarball inspection of all six packages. Retained
after push: exact-release-commit CI.

Each included change merged with passing CI. Pull requests record their own
real-tool checks: throwaway simulators and emulators, scratch `STIM_HOME` runs,
and a real `stim stop` interrupting a local iOS compile for #1300. The
`@stim-cli/server` tarball now carries the Swift sources of its frame helper,
which the server compiles on first use.
