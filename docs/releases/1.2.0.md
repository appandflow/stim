# 1.2.0

## New

- Native builds can warm Metro while compilation is still running, reducing the wait before the first development bundle. The optimization is enabled by default and can be configured or disabled through Stim's documented optimization settings. [8a7b70d8c](https://github.com/appandflow/stim/commit/8a7b70d8c)

## Fixes

- Android emulator recovery is more reliable. Stim can reclaim orphaned AVD data, recover an existing owned emulator, detect when an AVD restarts on a different serial, revalidate ownership before installation, restore port forwarding, and continue on the verified serial. Freshly created emulators also receive a longer first-bundle verification window. [cba5f1fd0](https://github.com/appandflow/stim/commit/cba5f1fd0) [748d0053e](https://github.com/appandflow/stim/commit/748d0053e) [750fc98aa](https://github.com/appandflow/stim/commit/750fc98aa) [1704b15da](https://github.com/appandflow/stim/commit/1704b15da)
- New Android emulators use an explicit high-density phone display instead of inheriting an unsuitable default. [28f4a1106](https://github.com/appandflow/stim/commit/28f4a1106)
- Stalled iOS simulator processes are detected earlier, and failure diagnostics report observed host memory pressure without attributing it to the app or claiming it caused the failure. `doctor` recommends the optional SimSlim setup, while Stim continues to require an explicit profile before changing simulator services. [62404f782](https://github.com/appandflow/stim/commit/62404f782)
- Local iOS discovery, boot, installation, Simulator opening, and SimSlim reconciliation now have bounded waits. SimSlim cleanup verifies the owned process identity, handles timeouts and terminal signals, and retains its claim when termination cannot be confirmed. [9f8097583](https://github.com/appandflow/stim/commit/9f8097583)
- `doctor` no longer requires `expo-dev-client`; Expo projects can use Stim without that package when their workflow does not need a development client. [ff786f1e6](https://github.com/appandflow/stim/commit/ff786f1e6)
- `doctor --fix` changes the Claude Code sandbox allowance only when the corresponding diagnostic is present. [772b9b356](https://github.com/appandflow/stim/commit/772b9b356)
- `worktree warm` skips Finder `.DS_Store` metadata and ignored `.idea` directories. [25889af6e](https://github.com/appandflow/stim/commit/25889af6e) [1ddaf82b8](https://github.com/appandflow/stim/commit/1ddaf82b8)

## Docs

- Agent guidance routes common situations to the matching versioned guide topic, and long waits point to the workflow guidance that explains diagnosis and recovery. [d9adbf1cf](https://github.com/appandflow/stim/commit/d9adbf1cf) [1b76f527b](https://github.com/appandflow/stim/commit/1b76f527b)
- Website release-note rendering fences command output that could otherwise be interpreted as page markup. [615800c52](https://github.com/appandflow/stim/commit/615800c52)

## QA

The release owner authorized reusing the completed 1.2 QA campaign instead of repeating the native and manual matrix on the version-only candidate. This is a disclosed deviation from the stable-release gate in `RELEASE.md`; the exact candidate still receives the full local preflight, tarball inspection, and exact-release-commit CI before tagging.

The retained campaign exercised all four native loop rows and all four native cache rows across bare React Native and Expo on iOS and Android. All cache rows and both iOS loops passed. Both Android loops completed with clean teardown but recorded partial launch qualification because a warm invocation was unverified; later manual recovery showed the expected UI. Manual Expo iOS and bare Android work covered launch, UI, induced errors, structured logs, recovery, worktree isolation, and exact cleanup. The Expo Android check covered picker recovery, healthy UI, and a successful bundle response. No test device or automation session remains active.

The fixes merged after that frozen candidate have separate evidence:

- The simulator-memory fix passed 4,219 unit tests, 84 end-to-end tests, final-head CI, two reviews, and a fresh owned iOS 26.5 Expo launch with real spawn and launch calls.
- Android cold-start and serial-recovery fixes passed integrated static, runtime, unit, and end-to-end checks. A real API 36 emulator was restarted on a new serial; status detected it without mutating the registry, and rerunning restored forwarding and produced a verified launch. The exact emulator and worktree were removed.
- The final iOS deadline and cancellation tree passed formatting, lint, build, type checking, unused-code checks, 4,248 unit tests with one existing skip, 84 end-to-end tests, runtime verification, two fresh reviews, and required CI. A fresh owned iPhone 17 / iOS 26.5 simulator completed discovery, boot, install, and a verified Expo launch with empty error logs. Controlled subprocess checks covered timeout, SIGINT, SIGTERM, immediate exit, descendant cleanup, and retained claims. The exact simulator, worktree, and test processes were removed. No SimSlim profile was applied and no OOM condition was induced.

Omitted at the release owner's direction: rerunning the pre-tag native and manual matrix after the version and release-note-only changes. Existing unresolved pool, authenticated remote-device, and physical-phone coverage are not claimed by this release.
