# 1.22.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the twelve npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale` and `@stim-cli/server`). No package publishes for the first time in this release. Commits that only changed those apps, tests, CI or internal structure are not listed.

## Removed (breaking)

- **Custom Expo `buildCacheProvider` plugin modules are no longer supported.** A project whose `expo.buildCacheProvider` names a custom module now gets an unsupported-provider note ("Custom Expo buildCacheProvider plugins are not supported. Use EAS or a Stim cache provider.") in `--plan` output and in `ios` and `android` build progress (`provider not usable: ...`), and falls back as if no provider were configured; the module is never loaded or run. `expo.buildCacheProvider: "eas"` (EAS CLI caching), the local Expo cache adapter and `@stim-cli/cache` providers, including S3, are unchanged. If you use a custom plugin, switch to EAS or a Stim cache provider. (`stim`) [94bb19775](https://github.com/appandflow/stim/commit/94bb19775a6c3ea5095a08f3b4e3cec38d03b576)

## New

- **Completed builds on paired workers are reused instead of rebuilt.** After a local and shared-cache miss, `stim` asks the paired worker for a completed build of the same inputs before placing a build, including when the worker is busy or the caller is idle. A hit skips source upload and compilation; a missing or corrupt archive follows normal placement, and older workers keep their normal build path. Each kind is negotiated by its own server feature and uses the existing authenticated, repository-scoped file cache. (`stim`, `@stim-cli/server`, `@stim-cli/core`)
  - Native Gradle: the worker caches APKs under its own complete inputs (worker toolchain, signing files and environment values) when the build transfers a complete `android.artifactInputs` declaration, and the caller can fetch a completed APK with feature `native-gradle-peer-cache`. Policy flows through `native-gradle-artifact-cache`. The returned fingerprint stays `null`, and worker APKs never enter the caller-key cache. [0bac453be](https://github.com/appandflow/stim/commit/0bac453be302ba7d7cede8b3c39ade9dc92ee0e0), [4fcf220e9](https://github.com/appandflow/stim/commit/4fcf220e98ba5f63bd3da58f6f47ec15528e66ba)
  - React Native and Expo development builds: exact iOS Simulator and Android archive lookup with feature `react-native-peer-cache`, matching the post-mutation native fingerprint, normalized build choices and a compatible toolchain. Release and physical-device builds keep their existing paths. [ac95a793a](https://github.com/appandflow/stim/commit/ac95a793a78dcdd9c0227268cc2b4b484c63b037)
  - SwiftPM macOS apps: reuse of a worker's completed app with feature `swiftpm-peer-cache`, for apps that declare complete, repeatable inputs through `macos.artifactInputs`. [d87f39cab](https://github.com/appandflow/stim/commit/d87f39cab3056d6011235925d95819ac3dcb64d5)
- **Completed SwiftPM macOS apps are reused across worktrees.** `macos.artifactInputs` (project setting, object) with `complete: true` declares pinned inputs that produce a relocatable app, with `ignored`, `outputs`, `localFiles` and `environment` for exact ignored, generated, private or environment inputs. A hit comes from the local build cache or an `optimizations.buildCache` / `cache.provider` `files` provider, is verified, and is re-signed with the receiving workspace's identifier and name before placement or build-slot acquisition. Without the declaration, builds compile as before. `stim macos --plan` reports `cacheHit` for a verified local completed artifact. See `stim guide macos` for what the declaration must cover. [bb4dfc43a](https://github.com/appandflow/stim/commit/bb4dfc43aad80fcbd6c02fac2f1b2b1cc49e1f0f)
- **Build placement ranks workers by reusable dependency installs.** For React Native and Expo, a worker whose existing install matches the requested project, lockfile and package-manager arguments (modules and install marker present) ranks before load. Checkout and build-folder presence, and the unverified hints of older workers, no longer affect ranking. Clients send `dependencies: { project, packageName }` only to servers with the new feature `build-dependency-cache`. Exact completed-artifact hits still come first. (`stim`, `@stim-cli/server`, `@stim-cli/core`) [439c20847](https://github.com/appandflow/stim/commit/439c208478984054fdcc9483505168d962b1f681)
- **Owned simulators and emulators are muted each time Stim boots them.** After a successful boot, Stim sets the volume to 0 and reads it back: `xcrun devicectl device settings audio --device <udid> --volume 0` for iOS simulators, and for Android emulators the media stream only, through a 1.4 KB helper shipped in the CLI (`shim/android-audio.jar`) that Stim pushes to `/data/local/tmp`, runs with `app_process`, removes, and confirms with `cmd media_session volume --stream 3 --get`; this works on Android 14, whose shell ignores the plain volume setter, and needs no host JDK. Stim prints a `device` phase line when the mute is confirmed and a warning, then continues, when it is not. A device that is already running is not touched, so sound turned on with Stim Desktop's per-device toggle lasts until that device next boots. Hosted (device-host) boots are unchanged. [2459e5df3](https://github.com/appandflow/stim/commit/2459e5df3fe6483050ef25f4567a8f304c46ef9e), [289d8701d](https://github.com/appandflow/stim/commit/289d8701df752600b2f2c965a3585106aa27a50b)
- **`stim-server service update --no-wait` and `stim-server setup --no-wait`.** Service updates wait for offloaded builds and hosted sessions to finish by default. `--no-wait` restarts with that work active: shutdown interrupts it, and shutdown verification, health checks and rollback still apply. Setup applies the flag to the service update it runs, and its remedy for a separate update carries it. (`@stim-cli/server`) [c180eb0cf](https://github.com/appandflow/stim/commit/c180eb0cfdbbe7a864337d17e1f54ac1aba71213)
- **In-process APIs on `createStim`.** Each accepts an `AbortSignal` and drains its owned children and claims on cancellation, reporting `STIM_CLAIM_UNAVAILABLE` with recovery paths when cleanup cannot be verified:
  - `plan({ platform: 'ios' | 'android' | 'macos', slot?, signal? })` returns the next configured native build as `--plan --json` reports it, without building or launching. (`stim`, `@stim-cli/cache`, `@stim-cli/cache-s3`) [51c5cd60b](https://github.com/appandflow/stim/commit/51c5cd60b63cd39317dbe4fa3c362221baf2e086)

## Fixes

- **`ios --device` and `android --device` ignore `ios.remote` and `android.remote`.** With either setting at `auto` or a machine name, a physical-device run refused with `STIM_BAD_ARG`. Those settings place owned simulators and emulators, so `--device` no longer reads them. `--device --remote local` now works. `--device` with any other `--remote` still refuses, and the error now names the value passed. [23bbd7bd4](https://github.com/appandflow/stim/commit/23bbd7bd42b6156448100d8b73a315a70ad075b6)
- Build workers recognize an available iPhone by CoreSimulator's device-type identifier instead of its name, so simulators that Stim renamed are found for offers and destination selection; an iPad named "iPhone" stays excluded. (`stim`) [1a747b4c3](https://github.com/appandflow/stim/commit/1a747b4c362e0609b42798547c164a132af28143)
- S3 file uploads reopen the completed file and retry up to three PUT attempts on `ECONNRESET`, with short cancellable delays and conditional writes preserved. (`@stim-cli/cache-s3`) [6c318763b](https://github.com/appandflow/stim/commit/6c318763b34792d74ed33b7a992318bdfaefcc8f)
- The supervisor stays alive and keeps its registrations and hosted gateways when the dev server's shutdown cannot be confirmed, so a later shutdown can retry. Previously a command that survived termination could outlive a supervisor that had cleared its state. [6745ce291](https://github.com/appandflow/stim/commit/6745ce291165da870825f799785537ec1fae3908)
- A successful browser navigation no longer leaves a timeout that delays a standalone caller's natural exit by about one second. [480879f43](https://github.com/appandflow/stim/commit/480879f43b096ffbe246b1f8ce2ab1f860998966)
- `stim status --watch` on macOS stops without per-workspace delays: it shares one recursive workspace watcher, and watches CoreSimulator `device.plist` files instead of each device directory. A real-home probe took 17.8 seconds to exit after SIGINT before and 4.18 seconds after; a 15-device fixture's watcher disposal fell from 1.11 s to 140 ms. [1b5c264c8](https://github.com/appandflow/stim/commit/1b5c264c82c9ca621b87685d1fb93d9855663305), [e60218eb4](https://github.com/appandflow/stim/commit/e60218eb4dbe1400c21fc4a172a58e93e30c7b9a)
- Doctor's setup command, once approved on the worker, prints the instruction to run `stim doctor` again on the requesting machine before `stim-server setup` waits. Ordinary setup and Desktop-generated commands are unchanged. (`@stim-cli/server`, `stim`) [6063465bd](https://github.com/appandflow/stim/commit/6063465bd0a46b05f0c9dbc7cc3cabdb7d2c1f00)

## Migration notes

- Owned simulators and emulators boot muted. Turn sound on per device in Stim Desktop's options (Sound for simulators, Media sound for emulators); it lasts until that device next boots.
- A project that relied on a custom `expo.buildCacheProvider` module must move to EAS (`"eas"`) or a `@stim-cli/cache` provider.

## QA

The maintainer authorized a stable release without the pre-tag QA gate on 2026-10-18 ("Can u do a no qa release regular release, no rc"). This deviates from RELEASE.md section 3, which has no waiver for a stable version; the expedited RC lane is for prereleases only and was not used. The waiver covers only section 3.

Omitted before the tag: all eight rows that `node scripts/release-qa-matrix.mjs v1.21.0` requires (415 changed paths, 210 mapped to a row, 0 unclassified): loop (expo and bare, iOS and Android), logs (iOS, Android), caches (iOS, Android), real-repository, remote-provider, release-build (iOS, Android), android-flavor and launch-evidence (iOS, Android), plus the native suites `test/e2e/native/run-native-e2e.mjs` and `test/e2e/native/run-cache-e2e.mjs`.
