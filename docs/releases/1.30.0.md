# 1.30.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the thirteen npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale`, `@stim-cli/transport-local` and `@stim-cli/server`). No package publishes for the first time in this release. Commits that only changed repository automation are not listed: [#4466](https://github.com/appandflow/stim/pull/4466) (the QA matrix classifies `vitest.global-tmpdir.ts` as test configuration).

## New

- **iOS builds and hosted simulators from a client without Xcode.** A Linux or Windows client with no Xcode and no simulator SDK can now offload an iOS simulator Debug build of a React Native or Expo app to a paired Mac approved for builds, and run it on a simulator that Mac hosts, with `stim ios --remote <mac> --remote-build <mac>`; Metro stays on the client. The worker's Xcode, simulator SDK and CocoaPods are the build's toolchain: offload still requires a Mac with Xcode, a simulator SDK and the runtime, and keeps the build compatibility, CPU and Bundler checks, but no longer compares the client's Xcode, simulator SDK or CocoaPods version, which it does not have. A client that has an Xcode still needs the same one as the worker. The client skips its own `pod install` and leaves it to the worker; prebuild still runs on the client. `stim doctor` on a non-Mac host judges remote Macs for the iOS app of a project with an `ios/` directory or an Expo app, without comparing the client's CPU, and its iOS note names the paired-Mac route next to EAS. Native Xcode apps without React Native still need Xcode on the client. Fixes [#4460](https://github.com/appandflow/stim/issues/4460). [9555fb2ec](https://github.com/appandflow/stim/commit/9555fb2ecd4b0089da78807af9494c245feb174d)
- **Hosted simulators and emulators are muted.** A Mac that hosts simulators and emulators for other machines now mutes each one it boots or adopts, as a local boot does: an iOS simulator through `devicectl ... audio --volume 0` once SpringBoard is up, and an Android emulator's media volume (Android 15 and later), both read back. The mute is best effort: a failure goes to the worker's log and never fails the hosted run, and it is not reported to the client. Only Stim-owned devices are touched, never the host's own volume, and hosted simulators are still never slimmed. This runs in the worker's stim-server. Fixes [#4278](https://github.com/appandflow/stim/issues/4278). (`stim`, `@stim-cli/server`) [6b6dcc23a](https://github.com/appandflow/stim/commit/6b6dcc23a351388790239a093edbad926a85453a)

## Fixes

- **`stim logs` no longer waits on hosted device log copies it cannot use.** A query that cannot return device records, such as `--source metro`, `--source client` or `--source build`, skips the copy of native logs from hosted iOS and Android slots, so it no longer waits for an offline host's connect timeout. A hosted macOS app's copy still runs for every source, because its records keep the host's own sources. `--errors` without `--source` and `--follow` are unchanged. Part of [#4281](https://github.com/appandflow/stim/issues/4281). [2a255af8d](https://github.com/appandflow/stim/commit/2a255af8d8a45b6b9d74830d9d53ba8bdba9160d)

## Migration notes

- **The hosted mute needs a stim-server update on each hosting Mac.** It runs in the hosted worker that ships with stim-server, so a Mac that hosts simulators or emulators for other machines mutes them only after `stim-server service update --release 1.30.0` there. Clients need no update for it.
- **Commit `Podfile.lock` before building iOS from a client without Xcode.** The worker runs `pod install` and fingerprints the checkout again before it compares with the client. When `pod install` changes fingerprinted files there, for example because no `Podfile.lock` is committed or it is stale, the build fails closed with `fingerprint-mismatch`. Run `pod install` once on a Mac and commit what it changed, including the CocoaPods-integrated Xcode project. The client needs `stim` 1.30.0; the worker needs no update for this, since the build request is unchanged.
- **No peer artifact reuse for a client without Xcode.** Such a client sends no peer artifact query, so it never reuses an artifact another machine built; its own local build cache works as before.
- **Build offload is unaffected.** `STIM_BUILD_COMPAT` stays 2: `scripts/build-compat.json` was re-recorded for the client-side toolchain judging without a bump. A 1.29.0 machine and a 1.30.0 machine still offload builds to each other.
- **No new settings, fields or state files.**
- **The hosted admission fixes are not in this release.** [#4470](https://github.com/appandflow/stim/pull/4470) (an unreadable memory sample retried once, macOS sessions counted apart from simulators and emulators, and a preparing iOS session counted once) was not merged by the freeze and ships in a later release. They also run on the worker, so they will need a stim-server update too.
