# 1.39.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the thirteen npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale`, `@stim-cli/transport-local` and `@stim-cli/server`). No package publishes for the first time in this release. The release was frozen at [1fbd9077f](https://github.com/appandflow/stim/commit/1fbd9077f7dda140465b48767ad9bf0fdaa1dea7) ([#4839](https://github.com/appandflow/stim/pull/4839)). Every commit since v1.38.0 has an entry below. No Stim Desktop release ships with this version.

## New

- **`stim share` publishes a running app on a public, password-protected web link.** `stim share ios|android [--control] [--expires <minutes>] [--password <value> | --no-password] [--device] [--slot <name>] [--json]` starts a share, `stim share list` lists them and `stim share stop` ends them. Viewers watch the device in a browser and, with `--control`, tap, type and press buttons; control is off by default. Every share expires (60 minutes by default, 480 at most), carries a random 32-byte link token and, by default, a generated password that is stored only as a digest; `--password` sets one and `--no-password` drops the login with a warning. Shares live in stim-server's memory on their own loopback listener, never on the API port; `stim share` starts a loopback-only `stim-server --share` when no server runs and refuses with the new `STIM_SERVER_NOT_RUNNING` when none can start. Nothing is captured until a viewer watches. New guide topic `stim guide share` and website page. Fixes [#4804](https://github.com/appandflow/stim/issues/4804). (`stim`, `@stim-cli/server`, `@stim-cli/core`, `@stim-cli/transport-tailscale`) [a5cbd9da0](https://github.com/appandflow/stim/commit/a5cbd9da0efe2e76eeab263cfd9b9dfe9aa12749)
- **Shares reach the internet through Tailscale Funnel or your own reverse proxy.** The first share adds a Funnel route on a Funnel port with no other serve entry and the last share removes it; `stim share` is the only Stim path that enables Funnel, and `stim-server setup` and `service` still never do. The new machine settings `share.exposure` (`auto`, `tailscale`, `proxy`; default `auto`, which picks Funnel when Tailscale is installed and logged in), `share.publicUrl` (the https address the proxy serves shares under) and `share.port` (the loopback port in proxy mode, default 7790) let a machine without Tailscale serve shares behind Caddy or another proxy. Proxy mode never runs `tailscale`. Fixes [#4829](https://github.com/appandflow/stim/issues/4829). (`stim`, `@stim-cli/server`, `@stim-cli/core`) [f8e53f1f2](https://github.com/appandflow/stim/commit/f8e53f1f2f5d2df670d4a96880b9fe4e5bdbc1ba)
- **`stim share` shares a device hosted on another Mac.** A workspace whose simulator or emulator runs in a hosted session (`stim ios|android --remote <mac>`) can now be shared from the client; one host frame stream serves every viewer, and the worker gets no new capability or protocol method. Fixes [#4830](https://github.com/appandflow/stim/issues/4830). (`stim`, `@stim-cli/server`) [9ebef2e9b](https://github.com/appandflow/stim/commit/9ebef2e9b810984a04c0b7763b96e4544565b636)
- **The share viewer shows the device frame and a toolbar.** The page draws the device in its frame artwork where Stim has one (iOS today), with hardware buttons and rotation for control shares, a screenshot button, fullscreen and the time left. It carries Stim branding, and its pages, stylesheet and script ship as files under `dist/share-viewer/` with a CSP that allows no inline script or style. Fixes [#4824](https://github.com/appandflow/stim/issues/4824) and [#4834](https://github.com/appandflow/stim/issues/4834). (`@stim-cli/server`) [1d8504541](https://github.com/appandflow/stim/commit/1d8504541f426b2669af51d5834040f16b322c17) [1fbd9077f](https://github.com/appandflow/stim/commit/1fbd9077f7dda140465b48767ad9bf0fdaa1dea7)
- **`stim revive` resumes a workspace after an idle stop.** It restarts Metro, boots the owned simulator or emulator the app last ran on and relaunches the app from the launch's own build cache entry, without building. It checks everything before starting anything and refuses with `STIM_NO_METRO`, `STIM_DEVICE_LOST` or `STIM_NO_RECORDED_BUILD` instead of widening. `stim start` writes an agent-device boot hook so agent-device runs `stim revive --json` instead of booting a shut-down device itself, and `STIM_RELOAD_STOPPED` and `status` name `stim revive` for an idle-stopped workspace. Launches recorded before 1.39.0 carry no cache entry and refuse with `STIM_NO_RECORDED_BUILD`. Fixes [#4791](https://github.com/appandflow/stim/issues/4791). [43e90d81a](https://github.com/appandflow/stim/commit/43e90d81a019911c9c99fe4c9b9085e34d518232)
- **`metro.idleStopMinutes` and `devices.idleShutdownMinutes` default to 15 minutes** (from 60 and 30). Explicit values, including 0, behave as before. Fixes [#4788](https://github.com/appandflow/stim/issues/4788). (`stim`, `@stim-cli/core`) [f9e57b353](https://github.com/appandflow/stim/commit/f9e57b35303cf3d65895d51353c1bf5779223e46)

A scoped `STIM_HOME` refuses it, and a running stim-server keeps responsibility for offload daemons. Fixes [#4665](https://github.com/appandflow/stim/issues/4665). [035615046](https://github.com/appandflow/stim/commit/035615046247b7f3003910198417591f01b98a90)

Load, `concurrency.maxBuilds` and the disk floor still apply. Service logs now carry an ISO time and the reason for each build refusal. Fixes [#4628](https://github.com/appandflow/stim/issues/4628). ## Removed (breaking)

- **`server.gradleDaemonIdleMinutes` is removed.** Daemons of successful offloaded Android builds follow Gradle's own idle policy (normally three hours) instead of a 30-minute Stim timeout; Stim removes only the timeout line it wrote from its owned Gradle homes. Cancellation, revocation and memory-pressure cleanup are unchanged. Refs [#4638](https://github.com/appandflow/stim/issues/4638). (`stim`, `@stim-cli/server`, `@stim-cli/core`) [1cba527e2](https://github.com/appandflow/stim/commit/1cba527e2e83d35a95e3bde7859aac84daba3a44)
- **stim-server no longer serves `status.subscribe` or its `status` event.** Clients read status through the status view methods; the phone app shows an update remedy when a server refuses them. CLI `status --json` and `--watch` output are unchanged. Fixes [#3504](https://github.com/appandflow/stim/issues/3504). (`@stim-cli/server`, `@stim-cli/core`) [aaea20ffe](https://github.com/appandflow/stim/commit/aaea20ffe3ec9b1f74df138a3cba6e1a83e7f893)

## Migration notes

- **Update every offload client and worker together.** `STIM_BUILD_COMPAT` goes from 2 to 5 ([6d0ff9813](https://github.com/appandflow/stim/commit/6d0ff9813bc65b87a2875e50f57cad703532492d), [107ba5d8d](https://github.com/appandflow/stim/commit/107ba5d8d7b5361fb1aa353ed1ed3d1177aef8c4), [f1f2706fd](https://github.com/appandflow/stim/commit/f1f2706fdfb63083535b3edf6059d9db45456600)), so 1.38.0 and older machines cannot offload builds to 1.39.0 machines, or the reverse. On a worker, each linked worktree, repository and selected Node starts a cold area or Gradle home once.
- **Workspaces idle-stop sooner.** With the new 15-minute defaults, a dev server with no reload, console output or Stim command stops after 15 minutes. Set `metro.idleStopMinutes` and `devices.idleShutdownMinutes` to restore the old timing; `stim revive` resumes an idle-stopped workspace.
- **Remove `server.gradleDaemonIdleMinutes`** from machine settings; it is no longer read.
- **Workers no longer cap offloaded builds at one.** Set `server.maxOffloadedBuilds` to 1 to keep the old behavior.
- **Phone apps that still use `status.subscribe` need an update** to read a 1.39.0 stim-server.
- **`stim share` can open a public Tailscale Funnel route** for the life of a share. Set `share.exposure` to `proxy` on machines that must never run `tailscale funnel`.

## QA

Skipping the pre-tag QA gate is the maintainer's standing default from 2026-10-26, and the maintainer approved publishing 1.39.0 without QA on 2026-11-02. This deviates from RELEASE.md section 3, which has no waiver for a stable version; the expedited RC lane is for prereleases only and was not used. The waiver covers only section 3. No section 3 QA round ran on any commit since v1.38.0.

Omitted before the tag, for this candidate: the rows that `node scripts/release-qa-matrix.mjs v1.38.0` requires, and the native suites `test/e2e/native/run-native-e2e.mjs` and `test/e2e/native/run-cache-e2e.mjs`, and `test:compat`. Per-change evidence is in the pull requests.

Run before the version commit, on the candidate (the freeze plus the version bump): `pnpm install --frozen-lockfile`, `release:prep --check`, `build`, CLI `--version` (1.39.0), `--help` and `guide agent`, the licenses regeneration that `release:prep` performs, and pnpm tarball inspection of the thirteen packages. The format, lint, typecheck, knip, RPC and unit checks run in the version pull request and its merge-queue run, per RELEASE.md section 2 step 2. Run after the version commit lands: the release gate of RELEASE.md section 4 step 4 on the exact release commit, and the Release workflow's own gates. The full Windows unit suite runs in `Post-release validation`, recorded, not gated.
