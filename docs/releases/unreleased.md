# Unreleased

## Added

- `stim plugin list` lists the bundled plugins and the plugin `cache.provider` names, and `stim plugin test <plugin>` runs a transport or agent-driver plugin's contract kit with the module in a worker thread. `stim doctor` and `stim settings set cache.provider` now report a cache provider that does not resolve or declares another integer.
- Before a local native compile, Stim estimates the bytes it will write and, when free disk on the project's volume is under that plus `disk.criticalFreeGb`, runs the pressure ladder once (rungs 2 to 8, for at most 60 seconds) and builds regardless, with one stderr warning if the space is still short. The estimate is the median of the project's recent recorded builds, or a default per project type. `stim logs --source builds` records `bytesWritten` and `projectKey` for each build.
- `stim remote update <mac>` updates an approved worker to the newest compatible release on its channel. Use `--channel next` to select prereleases for one update.
- Maintenance and `stim gc` manage checkouts no `stim` command ran in: linked worktrees of known repositories and recognised direct children of the folders that hold them or of the new machine setting `maintenance.discoverRoots` (absolute paths below the home folder; `stim doctor` reports one that is missing or too broad). They follow the registered-workspace rules with extra protection: removal needs full idleness evidence, no process or agent session, no git-ignored file the main checkout lacks, and no tracked-file edit; worktrees outside the folders Stim manages, other tools' homes, the temp directory and home dot-folders are listed and never acted on. A `target/` carrying Cargo's `CACHEDIR.TAG` signature counts as build output. The `gc` payload gains `discovered` and `outside`, and `stim gc --dry-run` lists them.
- A source (main) checkout's `node_modules` and `ios/Pods` are deleted, after those of every linked worktree: once it has had no activity for the new machine setting `idle.sourceDormantDays` (7 by default, `0` never; no Stim command, source file write, git write or commit in the checkout or any workspace in it, registered or not; a `stim worktree warm` copying from it counts as activity) at any level, and at critical in ladder rung 8 while the disk is still under the critical level (`stim gc --pressure critical` always takes it). They were never deleted before. The deletion is recorded; `stim worktree warm` says on stderr that the source checkout has no installed dependencies to copy and since when, and `stim status` and its JSON (`sourceDependenciesCleared`) show it until they are installed again.

- `maintenance.cargoTargetMaxGb` also caps a Cargo workspace root's `target/` (git-ignored, directly in the checkout, with Cargo's `CACHEDIR.TAG`) and the `target/` of in-scope discovered checkouts, with the same guards as an Exact app's. At most 6 discovered targets are measured per size scan, least recently measured first. A target triple directory holding files other than Cargo's own keeps them and loses only its stale profiles, and a build holding any of Cargo's three profile lock files keeps the profile. `stim gc --dry-run` lists each as a `Cargo target` action.
- The Cargo target trim tightens with disk pressure on the volume holding the `target/`: at high it removes every stale profile and all `incremental/` data of every recognised `target/`, at critical it also removes build units that Exact's usage ledger shows no build used for a day (superseded duplicates in `deps/`, `.fingerprint/` and `build/`, keeping one unit per crate name, the most recently used; a target without the ledger, or with one older than 3 days, keeps its units). `stim gc --pressure` applies its level to every `target/`.
- The Cargo target cap measures and trims hourly even while host load defers the maintenance size scan, and the size scan runs anyway after 3 hours deferred. `stim status` and its JSON (`maintenance.deferred`) report the checks host load is deferring and since when.

## Fixed

- A project with two installed versions of one package that its config evaluation loads, and that its lockfile does not vouch for (such as npm lockfile entries without `resolved` and `integrity`), gets a native build-cache key again instead of building uncached with `two fingerprint inputs named npm:<name>/<file> disagree`. Each version is its own input, named `npm:<name>@<version>/<file>`. Fixes [#5508](https://github.com/appandflow/stim/issues/5508).
- `stim worktree remove` and the automatic sweep no longer revert and discard a hand edit to a registered worktree's `ios/Podfile.lock` or `project.pbxproj`. A modified `Podfile.lock` counts as `pod install` churn, and is restored before removal, only when `ios/Pods/Manifest.lock` holds the same text, or when gc deleted `ios/Pods` while they matched and the lock is unchanged since (gc records the lock's hash in the workspace's lightened record). A deliberate `pod update` followed by an install leaves the same evidence, so commit it before removing. A `project.pbxproj` change is always an uncommitted change: `worktree remove` refuses it and the sweep keeps the worktree, or archives it first when it is finished. A tracked file marked `assume-unchanged`, or `skip-worktree` with the file on disk, keeps a registered worktree in the sweep, and `worktree remove` refuses it, naming the file and the `git update-index` command that shows the edit, unless you pass `--force`. A sparse checkout alone does not. Fixes [#5520](https://github.com/appandflow/stim/issues/5520).

## Removed (breaking)

- `stim gc` runs one automatic maintenance pass at the measured pressure level and deletes; `--dry-run` reports instead, and `--pressure <normal|high|critical>` sets the level. `--delete`, `--cache`, `--older-than` and `--worktrees` are gone. The API's `gc()` and `collectGarbage()` take `{ pressure }` instead of `{ olderThan, cache, worktrees, delete }`, and the payload is the level run (`level`, `actions`, `blocked`, `results`, plus the storage sections on a dry run). Stim Desktop deletes a single item through stim-server, and the API exposes it as `deleteGarbageItem({ item })`.
- `idle.dormantDays` defaults to 1. A workspace idle that long is reduced to its minimal size at every level, including a linked worktree's `node_modules` and Pods when `worktree warm` cannot restore the same versions; the next Stim command asks for an install then. gc deletes unused iOS simulator runtimes. At critical, only the stim-daemon (at most hourly, while the disk is still short) and `stim gc` clean the npm, Yarn, pnpm, CocoaPods, Gradle and SwiftPM caches, through their own commands where they have one, never in a `STIM_HOME`-scoped home or from a build's own ladder; `stim gc` with no `--pressure` that measures critical measures free disk again and cleans them only if it is still under the critical level, and `stim gc --pressure critical` always does. A dry run runs no package manager. Gradle and SwiftPM caches are renamed aside to a `.stim-delete-*` sibling and deleted, and a later run finishes a leftover. The ladder deletes `node_modules` and Pods of linked worktrees idle 1 hour at high. `stim worktree remove` parks devices unless the disk level is critical. Defaults change: `disk.criticalFreeGb` 6 to 20 and `disk.minFreeGb` 20 to 40.
- stimd no longer stops a stim-daemon from Stim 1.40 to 1.42. While one holds `~/.stim/daemon/claim` exclusively, stimd does not start and logs "stim-daemon pid <pid> from an older stim holds this home's daemon claim, so stimd cannot start. Stop it with kill <pid>; it also exits on its own after its workspaces stop. If a project pins stim 1.40-1.42, update it to stim 2.0.0 or later there (npm i -D stim@next until 2.0.0 is released; for npx: npx stim@next)", and `stim serve` prints the same line. This recurs while a project or an npx cache still runs a 1.40 to 1.42 copy.
- stim-server no longer probes its port for a stim-server older than 1.43, such as a Stim Desktop 0.x bundle that was never updated. A port another process holds ends the net thread with `port <n> is held by pid <pid>; stop it (kill <pid>), or run stim serve --port <n>.`, and the phone, shares and remote builds wait until it is freed.
- A stimd that starts after an engine switch no longer stops dev servers or device log collectors that a Stim 1.43 build started before it. They keep their port until `stim stop`; `stim start` either reuses such a dev server or reports `Port <n> is held by something else` and asks you to stop the process on that port.
- The stim-ci action no longer explains versions below the one-package release. Set `version:` to 2.0.0 or later, or pin the action to an older ref; a package without `bin/stim.mjs` fails with `stim@<version> has no bin/stim.mjs, which this action runs with ci`, and a `cli-path` that names a `stim-ci.mjs` executable is no longer refused with an explanation.
- The release floors are gone: `packages/core/state/release-floors.json` and the release prep that pinned them. A patch release no longer refuses while a floor is null.
- Removed settings, environment variables and flags are no longer explained by the CLI: a removed setting name is refused or ignored like any unknown one, with no replacement named. The old environment variables and config values that turned a mechanism off still refuse with a remedy. The old names and their replacements are listed in the migration guide ([#5591](https://github.com/appandflow/stim/issues/5591)).

## Changed

- `maintenance.olderThanDays` defaults to 3 (was 7): the age sweep removes workspace build outputs, shared cache entries, parked simulators and emulators, and opt-in idle worktrees after 3 days, and a simulator runtime that simctl recorded as used within 7 days is kept (the runtime window does not shrink below 7 days). Every stage and rung that reduces workspaces takes linked worktrees before source (main) checkouts, longest idle first in each.
- `import('stim')` loads a small `createStim` facade, and Stim's implementation loads on the first operation call. Every client operation now reports a refusal as a rejected promise, including the argument checks that threw synchronously before.
- `stim ci --version` and `stim ci -V` print the CI package version after Stim's pre-command checks run. Under `stim-server`, an option after a subcommand that the subcommand does not define, such as `stim-server devices grant ID --json`, is refused.
- Stim computes its own native build-cache fingerprint. Older cache entries miss once. The first native run of a generated, untracked Expo `ios/` or `android/` whose prebuild record an earlier Stim wrote (Stim 1.40's included) runs `expo prebuild` over it and records it. A local run deletes nothing; an offload worker runs it with `--clean` on its own copy. This happens once per generated worktree, whether or not anything changed. A tracked directory is never regenerated. A record this Stim cannot read (written by a newer Stim, or damaged) refuses with `STIM_PREBUILD_FAILED` and a `mv ios ios-<date>` command. Fixes [#5623](https://github.com/appandflow/stim/issues/5623). `stim doctor` runs project config and autolinking in an isolated child to check fingerprint determinism and worktree parity; run it only in a checkout whose project code you trust. The worker wire protocol is now peer 3 and build compatibility is 6; update an older worker before offloading.
- The private fingerprint replay record keeps `STIM_HOME` and `STIM_RUN_ID`, without sending them as fingerprint inputs to a worker. An embedded-config or dependency read of a private Stim credential, or project environment enumeration while one is present, makes the build uncached; remove the credential from the build environment to retry caching.
- Offloaded builds remove Stim's own access and setup credentials from the worker's build environment. Project build tools can still print the environment values they receive.
