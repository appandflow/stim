# 1.5.0

## New

- `stim guide` and `stim guide agent` open with a STATUS block when doctor is due for a platform in this project, meaning it never ran here, ran more than seven days ago, or ran under another Stim version, and when a newer Stim release exists. Doctor records each run per platform, and the release check reads the npm registry at most once a day; `STIM_NO_UPDATE_CHECK` disables it. [56decdaf3](https://github.com/appandflow/stim/commit/56decdaf3ff4f7e14f797c8db97410003fea9150)
- `stim start --reset-cache` restarts the owned Metro with Metro's own reset, clearing every store in the app's Metro config including the shared transform store, instead of persisting a cache generation in workspace state. The Expo SDK 54 requirement for a reset is gone. [01f290095](https://github.com/appandflow/stim/commit/01f29009502c34278384d32da93127fe3e39f6cb)

## Fixes

- Support bare-repository worktree layouts, where every checkout is a linked worktree beside a bare `.git`. Warm, remove, doctor, storage diagnostics, and status resolve the source checkout as the worktree on the bare repository's HEAD branch, and refuse with the exact Git command to run when HEAD is detached, its branch has no worktree, or that worktree was deleted. [6b5ad313c](https://github.com/appandflow/stim/commit/6b5ad313cf9568ebc183dd5b59cee5cb542f87aa)

## Docs

- Website benchmark details: scenario picker keyed on the run variant, one full-width comparison card, a terminal clamped to the viewport, and a redesigned timeline toolbar with direct scrubbing. [515203498](https://github.com/appandflow/stim/commit/515203498c60add400d43f9a740c8322c665ffa1)

## Migration notes

Doctor now writes to Stim state on every run, so a project appears in `stim status` after `stim doctor` alone. The `--reset-cache` workspace-state generation field is no longer read; existing state needs no change.

## QA

Native compatibility, simulator/device suites, and manual QA are omitted at the user's request on 2026-09-18. The omission is not a native-compatibility pass.

Retained checks: formatting, lint, candidate build, typecheck, knip, unit tests, end-to-end tests, published-runtime checks, candidate CLI version/help/guide, inspection of all five packed tarballs, and CI on the exact release commit before tagging.
