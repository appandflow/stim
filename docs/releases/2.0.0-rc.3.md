# 2.0.0-rc.3

Install `stim@2.0.0-rc.3` to try the third Stim 2.0 release candidate. The optional S3 cache provider is available as `@stim-cli/cache-s3@2.0.0-rc.3`.

## Fixes

- **Build offload works for projects with many fingerprint sources.** On 2.0.0-rc.2, offloading an iOS or Android build of a project with more than about 450 fingerprint sources (a local native module or a committed native directory, for example) failed with `the connection closed (1009 message not sent)` after the source sync, because `build.start` exceeded the 64 KiB message limit, and the build fell back to a local one or, with no local fallback, failed. The client now sends the fingerprint sources in chunks of at most 64 KiB before `build.start`. Only the client needs 2.0.0-rc.3: the offload job runs the client's own Stim build on the worker, so workers on 2.0.0-rc.2 accept it. [0992b670ae](https://github.com/appandflow/stim/commit/0992b670aebb9e8e864d38554cd76c108915b353)
- **Hosted agent control starts with agent-device 0.21.42.** agent-device 0.21.42 refuses a daemon state directory that is or holds a symbolic link, so every hosted iOS and Android agent-device launch failed with `Refusing to use the daemon state directory ... sessions is a symbolic link`. A hosted device's daemon now runs with a real private state directory outside the Stim home. [70884e5922](https://github.com/appandflow/stim/commit/70884e592268313bf35e0535f0dad66c2d3950c1)
- Hosted devices classify the commands and flags agent-device 0.21.37 to 0.21.42 added. `--no-post-gesture-stabilization` on `open`, `scroll`, `swipe` and `gesture`, and `screenshot --screen-mask` and `--capture-backend` are allowed. `audit`, `shake`, `open --device-mode` and `--device-baseline`, and `diff --screen-mask` are refused with a reason; `audit` and `shake` stay refused so hosts on older agent-device releases still start. [474f834e85](https://github.com/appandflow/stim/commit/474f834e8578b1dbfa35875289ef2910cc90c228)
- `stim start --json` interrupted with SIGTERM prints its `STIM_CANCELLED` payload instead of exiting with no output, and a cancelled start whose dev server already answers says that the server was left running and how to stop it. [71cfdc690a](https://github.com/appandflow/stim/commit/71cfdc690a21e944813a5ba009a242f627487422)
- `stim doctor` checks fingerprint parity on npm projects instead of printing "Fingerprint parity could not be checked". [879ac7ba1e](https://github.com/appandflow/stim/commit/879ac7ba1e87fe1f67d776f0447b865942f9034c)
- A `stimd` started by launchd or Stim Desktop finds Homebrew, `~/.local/bin` and Node tools, so it can stop an agent-device daemon and prune a removed project. A failed prune names the error and its remedy in `stim gc` output and the gc log. [e40c6401d1](https://github.com/appandflow/stim/commit/e40c6401d11123d358f6e06169a21f1488f10e71)
- A hosted device refused because the worker could not list its processes reports the exit code, signal, timeout or spawn error. [0fa65078ba](https://github.com/appandflow/stim/commit/0fa65078baea2df71c000da44558b70eda1951e6)
- The `stim worktree remove` refusal leads with committing or pushing the work, lists restore commands only for files whose changes are all unstaged, and prints the commit and a `git branch` command for a detached HEAD with unique commits. The `STIM_MAIN_DIRTY` remedy no longer suggests `git stash`. A successful removal names, on stderr, up to five git-ignored files that differ from the source checkout. [152aaeb4e2](https://github.com/appandflow/stim/commit/152aaeb4e2b1fc0be3e4062e906c873b039e6f09)
- An Exact build offloaded to a worker without the pinned Hermes bundle names the missing target and the Hermes install command. [78d80740c9](https://github.com/appandflow/stim/commit/78d80740c9be85e3479bebbecb73262cdc7fc01f)
- The daemon backs off from a removed checkout that stays in the discovery census instead of probing it on every tick. [fcb43edd54](https://github.com/appandflow/stim/commit/fcb43edd54fff942c72b292b94d139770701a56f)
- Automatic maintenance and `stim gc` reduce idle linked worktrees that have a workspace record but no registered project, and idle discovered source checkouts with no record, instead of keeping the worktrees with `current dependency eligibility could not be checked` and the checkouts as `no longer idle`. The dependencies of such a root come back with the next Stim command in it or with `stim worktree warm`. [934eb3beb3](https://github.com/appandflow/stim/commit/934eb3beb3ec338e751ac79b21312d17e7d72ec1)
- A final `STIM_LOW_DISK` refusal from `start`, `ios` or `android` is recorded in `STIM_HOME/logs/low-disk.ndjson`, without checkout paths or disk usage details. [1f40dbf2ed](https://github.com/appandflow/stim/commit/1f40dbf2edef243556984dd4f04d85e552c5e1b9)
