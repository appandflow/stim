# 1.32.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the thirteen npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale`, `@stim-cli/transport-local` and `@stim-cli/server`). No package publishes for the first time in this release. The release was frozen at [e55955fdf](https://github.com/appandflow/stim/commit/e55955fdf521a407e7880364e92a2e8ac0aed273). One commit since v1.31.0 changes none of the npm packages and has no entry below: [#4512](https://github.com/appandflow/stim/pull/4512) (Stim Desktop shows a paired machine's workspaces, devices and builds read-only, behind the **Paired machines** feature flag that is off by default). It changes only Stim Desktop and the website; the migration notes say how to turn it on. The merge queue landed [#4498](https://github.com/appandflow/stim/pull/4498) (the phone app's Home rows name the machine where an offloaded build or hosted device runs) on `main` after the freeze and ahead of the version commit, so the tagged commit contains it; it changes only the Stim phone app and the website, none of the npm packages. The queue then landed [#4481](https://github.com/appandflow/stim/pull/4481), which does change the npm packages, so it is in this release with its own entry below.

## New

- **Agent control of hosted apps on a local network machine.** For a `local:` entry in `remote.machines`, `stim ios|android --remote` always reported `host.agent` as `none` ("needs a tailnet machine"), because the worker's agent route identifies the client by the Tailscale node `tailscale whois` reports, and a local network peer has none. For hosted iOS and Android Debug runs on a `local:` machine, the workspace's Metro supervisor now listens on a loopback port per hosted session, and the session's `remoteConfig` sets `daemonBaseUrl` to `http://127.0.0.1:<port>/device-host/agent/<session>/` with the unchanged per-session token. Each connection agent-device opens there rides a `device-host` connection the client opens and authenticates itself, through the new `device-host.agent.link` method; the worker accepts a link only for a session whose agent grant belongs to that client's key, and answers any other session with `unknown-session`. The client never accepts a connection from the network, and the worker never trusts an address. Every request on a link must still name the linked session, carry its token, carry no `Origin` or `Sec-Fetch-Site`, and come from a client that still holds `device-host`; failures are rate limited per client key and session. Links are bounded: the relay holds at most 8 local connections, a session holds at most 16 links on the worker and a new one closes the oldest, a link that carries no bytes for 5 minutes between requests is closed, and stopping the session closes its links. The relay reuses its earlier port when it is free, so a remote config written before a supervisor restart still reaches it. The worker advertises the `hello` feature `hosted-agent-link`; against a worker without it, agent control is `none` with the note "`<machine>` runs a stim-server that cannot carry agent control over the local network. Update stim-server there, then retry." Hosted Release runs and hosted macOS apps on a `local:` machine have no relay process and keep `none`, now with that reason. Tailnet machines are unchanged. `stim guide lifecycle` and `stim guide settings`, the `@stim-cli/server` README and the remote machines website page describe it. Fixes [#4508](https://github.com/appandflow/stim/issues/4508). (`stim`, `@stim-cli/server`, `@stim-cli/core`, `@stim-cli/agent-driver`) [e55955fdf](https://github.com/appandflow/stim/commit/e55955fdf521a407e7880364e92a2e8ac0aed273)
- **Idle stop covers hosted sessions, on the client and on the worker.** The idle workspace stop (`maintenance.idleStopHours`, default 6, `0` never) kept every workspace with an iOS, Android or macOS app hosted on another Mac, and nothing on the worker noticed a client that went away, so a hosted session kept its device and capacity slot until a person stopped it. On the client, such a workspace is now a candidate for the idle stop, under the same activity rules. Once the local evidence says idle, Stim asks the host, and stops only when the host reports the session `ready` or `stopped`; `unknown`, an unreachable host or an unreadable placement keeps the workspace, with the reason as the skip. The stop is `stim stop`'s, which ends the session on the worker. On the worker, while its own machine `maintenance.mode` is `on`, stim-server checks every 60 seconds and stops a ready, unparked hosted session whose client has had no authenticated connection and made no agent-device request for its own machine value of `maintenance.idleStopHours`, through the stop a person's Stop and revocation use. Time the server was down or the Mac was asleep is not counted. It pings each device-host connection every 60 seconds and drops one that is still silent at the second check after 180 seconds of silence, about 4 to 5 minutes, so a closed laptop reads as gone. Presence is per client: a client connected for any workspace keeps all its sessions on that worker. A session that is preparing, stopping or unknown, or that another live server owns, is never touched, and a due session is kept, with the reason logged, while native work or native input on it is not provably finished. The reason is written to the server log and to the hosted session journal's new `idleStop` field, beside the new `clientAbsentMs`. `stim guide cleanup`, `agent`, `metro`, `lifecycle`, `macos` and `settings`, the setting's description and the dev server, remote machines, owned devices and settings website pages describe it. Fixes [#4477](https://github.com/appandflow/stim/issues/4477). (`stim`, `@stim-cli/server`, `@stim-cli/core`) [b9aef0dfc](https://github.com/appandflow/stim/commit/b9aef0dfc5173d99fc1b92f832805c7ce6b597ac)

## Migration notes

- **Agent control over the local network needs 1.32.0 on both sides.** The worker's stim-server must advertise `hosted-agent-link`: run `stim-server service update --release 1.32.0` there, or install `@stim-cli/server` 1.32.0. The client needs `stim` 1.32.0, and a workspace whose `stim start` ran on an older `stim` needs `stim stop; stim start`, so that its Metro supervisor runs the relay; until then agent control reports `none` with "The Metro supervisor has no agent relay ready". A 1.32.0 client with an older worker gets `none` and the update note above; an older client with a 1.32.0 worker keeps reporting `none` for `local:` machines, as before. Agent control on tailnet machines needs no update.
- **Stim Desktop: Paired machines.** The Stim Desktop release built from this commit shows a paired machine's workspaces, devices and builds read-only. It stays behind the **Paired machines** feature flag, off by default. To try it:
  1. In Stim Desktop, turn on **Settings > Advanced > Feature flags > Paired machines**. **Settings > Paired Machines** appears.
  2. On the other machine, such as a Linux server where an agent starts workspaces, run `stim-server pair` (`--json` works too).
  3. In **Stim > Settings > Paired Machines**, choose **Pair with a Machine…** and paste everything the command printed. Check the name, endpoint and key fingerprint the sheet shows; Desktop pairs only with the machine whose key has that fingerprint. It accepts a `wss://` endpoint on a `.ts.net` name, or `ws://` to a Tailscale address.
  4. The code works once, for 5 minutes. A pairing made from `stim-server pair` can only read.

  The machine then gets its own sidebar section below this Mac's projects, and **Machines** lists it after the build machines. A pairing lets this Mac see everything the machine's server shows a phone, including workspace paths, logs, changed and untracked text files such as `.env` files Git does not ignore, and live device screens, so pair only with machines you own. **Forget** deletes this Mac's key from the Keychain but not the machine's record; run `stim-server devices revoke <id>` on the machine for that. See the [Stim Desktop page](https://stim.appandflow.com/docs/desktop#pair-with-another-machine).

- **Hosted sessions are now stopped when idle.** With the defaults (`maintenance.mode` `on`, `maintenance.idleStopHours` 6), a 1.32.0 client stops a hosted workspace after 6 idle hours, and a 1.32.0 worker stops a hosted session whose client has been gone for 6 hours. On the worker, the absence count starts when 1.32.0 starts, not from the session's last use. Each side reads only its own settings, and the worker only its machine ones, so a 1.31.0 client still keeps its hosted workspaces while a 1.32.0 worker stops their sessions once the client is gone, and a 1.32.0 client stops its idle hosted workspaces on a 1.31.0 worker. To keep sessions until a person stops them, run `stim settings set maintenance.idleStopHours 0 --scope machine` on that machine; this also turns off the idle stop of local workspaces there. The worker's 60-second pings are WebSocket pings, which a 1.31.0 client answers, so a connected 1.31.0 client keeps its sessions. A worker rolled back with `stim-server service rollback` to 1.31.0 still reads a journal that carries the new `clientAbsentMs` and `idleStop` fields.
- **Build offload is unaffected.** `STIM_BUILD_COMPAT` stays 2, so 1.31.0 and 1.32.0 machines still offload builds to each other.
- **No new settings or state files.** The supervisor's hosted Metro state gains an optional `agentPort` field, the hosted session journal gains the optional `clientAbsentMs` and `idleStop` fields, `maintenance.idleStopHours` now also covers hosted sessions, and stim-server gains the `device-host.agent.link` method and the `hosted-agent-link` feature.
