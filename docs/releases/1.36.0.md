# 1.36.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the thirteen npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale`, `@stim-cli/transport-local` and `@stim-cli/server`). No package publishes for the first time in this release. The release was frozen at [91fcd1d62](https://github.com/appandflow/stim/commit/91fcd1d625f9ff81a23189f887b9119707247f72) ([#4568](https://github.com/appandflow/stim/pull/4568)). Every commit since v1.35.0 has an entry below. Stim Desktop 0.2.15 ships from the same release commit.

## New

- **`stim remote add`, `list` and `remove` manage remote machines from any directory.** Asking a remote Mac for build and device-host approval only worked through `stim doctor --fix`, which refuses outside an app project, and `stim settings set remote.machines '[...]'` replaced the whole list. `stim remote add <machine>` appends the machine under the config lock, asks for build and device-host approval and prints the `stim-server setup` command. `stim remote list` reports both approvals per machine in placement order and completes a pending connection after the person approves. `stim remote remove <machine>` drops the entry, forgets this Mac's credentials for that machine only and prints the revoke command for the worker. Other machines' approvals are kept. The request path is unchanged: `add` runs doctor's own inspectors for the one machine, with no new listener, capability or approval route. Approval remedies now point at these commands. Fixes [#4565](https://github.com/appandflow/stim/issues/4565). (`stim`, `@stim-cli/server`) [91fcd1d62](https://github.com/appandflow/stim/commit/91fcd1d625f9ff81a23189f887b9119707247f72)
- **A missing remote machine is explained when this Mac is signed in to another tailnet.** Credentials of `tailscale` machines now record the tailnet (`name`, `suffix`, `id`) this Mac was on when it first asked the machine for access. When the peer is missing from the tailnet this Mac is on and the credential recorded another one, `stim doctor` reports `peer-wrong-tailnet` and builds and hosted devices refuse with the same message, naming both tailnets and the remedy, instead of `no peer on this tailnet is named <machine>`. A credential that predates the field gets it the next time the machine answers `stim doctor`. A node shared in from another tailnet keeps working. `doctor --json` machine rows carry `tailnet`. Fixes [#4566](https://github.com/appandflow/stim/issues/4566). (`stim`, `@stim-cli/core`) [4ccd9c443](https://github.com/appandflow/stim/commit/4ccd9c443e71094329c0a5a950efc0191ad3c7c3)
- **`@stim-cli/ci`: `build` is the only step that compiles, and `run` installs the build it recorded.** See Removed (breaking) and Migration notes. `stim-ci build` records its app in the checkout's workspace state (`recordedBuilds`, keyed by platform, scheme and configuration or variant), and `stim-ci run` installs that app as built: no fingerprinting, cache lookup, compile or JS swap, then boot, install and launch as before. `--eas-profile` moves from `run` to `build`. The action runs build then run in one step and installs the pinned `@stim-cli/ci` once per runner and version. Fixes [#4573](https://github.com/appandflow/stim/issues/4573). (`@stim-cli/ci`, `stim`) [e6e7339e8](https://github.com/appandflow/stim/commit/e6e7339e8e4da7e5ca24a3e24649a35e79e8d755)

## Removed (breaking)

- **`@stim-cli/ci` no longer builds in `run` and writes nothing unless asked.** This is a breaking change for anyone who calls `stim-ci run`, `stim.run` from the API of `@stim-cli/ci`, or the `stim-ci` GitHub Action. It was approved by the maintainer, who has no external users of the package. [e6e7339e8](https://github.com/appandflow/stim/commit/e6e7339e8e4da7e5ca24a3e24649a35e79e8d755)
  - `stim-ci run` for iOS and Android never compiles. With no recorded build, or with the recorded app removed, it refuses before any device work with `STIM_NO_RECORDED_BUILD` and names the exact `stim-ci build` command to run first. macOS and web `run` are unchanged (macOS still builds itself).
  - `stim-ci build` exports only with `--export <path>` (`exportPath`). Without `--artifacts`, no result, test or diagnostic file is written and no logs are copied; the JSON result still prints.
  - `--eas-profile` is a `build` option and no longer a `run` option.
  - The `--skip-js-swap` flag, the `skipJsSwap` run option, the `jsSwapSkipped` fact and the action's `skip-js-swap` input from [#4571](https://github.com/appandflow/stim/pull/4571) are removed. They were never in a published release.
  - The action's `artifacts` input defaults to empty and `upload-artifacts` applies only when it is set. A new `export` input carries the export path. The action builds then runs in one step for iOS and Android, runs macOS only with `export`, and never builds web.
  - `stim ios` and `stim android` are unchanged: `recordedBuild` is on `StimRunOptions` only, not on the wire protocol.

## Fixes

- **A failed Xcode script phase is named with its real error.** The failure summary used to list the first error-looking lines, which on a Release build with `@sentry/react-native` were Swift fragments and `sentry-cli` xtrace lines, and the real cause (`Auth token is required for this request`) was never shown. The collector now reads past `** BUILD FAILED **` to the `The following build commands failed:` block and puts each failed `PhaseScriptExecution` phase, with its target and the last error lines the script printed, first in the diagnostics, with the `error: <tool> - ` wrapper stripped and xtrace lines dropped. A failed iOS or Android build keeps its transcript as `<log>.failed` (for example `build-artifact-ios.ndjson.failed`), so the next build no longer overwrites it; `stim logs` still reads only the current run. Fixes [#4574](https://github.com/appandflow/stim/issues/4574). (`stim`) [aad239674](https://github.com/appandflow/stim/commit/aad239674f4e9fccacf4b50561a3c6ea548c23d9)
- **The `build.start` wire schema lists every `BuildStartParams` field.** `podsOnWorker`, `iosProjectPath`, `reuseArtifact` and the Android `gradleRoot` and `module` options were missing from the published schema, which has `additionalProperties: false`, so a schema-validating client rejected valid requests. The server's own validation already accepted them, so builds were unaffected. A test now fails when a field is added to the type and not to the schema. Fixes [#4538](https://github.com/appandflow/stim/issues/4538) and [#4563](https://github.com/appandflow/stim/issues/4563). (`@stim-cli/server`) [14db3d5a1](https://github.com/appandflow/stim/commit/14db3d5a1f10248563440787e3bbe319b804d395), [68e164bed](https://github.com/appandflow/stim/commit/68e164bed3a415f37a8455823a29959d13752c56)
- **Stim Desktop bounds the workspace status a paired server's feed keeps.** A paired server could grow Desktop's memory without limit by upserting workspace and worktree paths. The paired feed now holds at most 10,000 entities and 32 MiB of accumulated JSON, drops its held workspaces and unsubscribes when a snapshot or delta passes either limit, and reports `feed-too-large` until the client reconnects or the user refreshes. Paired decodes are coalesced. The local feed has no limits. Fixes [#4527](https://github.com/appandflow/stim/issues/4527). (Stim Desktop) [4d837bf28](https://github.com/appandflow/stim/commit/4d837bf28881ad1c39e4ed0d29ca28ac60ae41f2)
- **Reverted without a net change: rerunning local pods' `prepare_command` after a `node_modules` reinstall.** [#4572](https://github.com/appandflow/stim/pull/4572) ([8cc6b5a60](https://github.com/appandflow/stim/commit/8cc6b5a6008ce6b8bf981cf2770ae7a461c9a11b)) deleted `ios/Pods/Manifest.lock` before a pod install when `node_modules` was newer, as a workaround for one dependency's build script. The maintainer decided Stim should not carry it, and [#4576](https://github.com/appandflow/stim/pull/4576) ([5af2b3c2e](https://github.com/appandflow/stim/commit/5af2b3c2e2ee834d19cfecb9501682968df5182e)) reverted it. 1.36.0 behaves as 1.35.0 here.
- **The unreleased `--skip-js-swap` option for `stim-ci run` is gone.** [#4571](https://github.com/appandflow/stim/pull/4571) ([f1f5ba001](https://github.com/appandflow/stim/commit/f1f5ba0019fb93a3d556bb84cd2b8004e09d8f38)) added it and [#4577](https://github.com/appandflow/stim/pull/4577) removed it, with the recorded-build `run` replacing its purpose. It never shipped in a release.

## Migration notes

- **`@stim-cli/ci` users: run `build` before `run`.** In a script, `stim-ci build --platform ios --project <path> --configuration Release` then `stim-ci run ...` with the same selectors; the last build for a platform, scheme and configuration or variant wins, since architecture and ABI are not run selectors. A `build` that previously ended with an export now needs `--export <path>`, and a job that read result or diagnostic files needs `--artifacts`. Move `--eas-profile` from `run` to `build`. In the GitHub Action, set `export` where a build output is needed and `artifacts` where files are uploaded; both default to off.
- **A recorded build is installed as built.** If the project was edited after `stim-ci build`, `run` installs the stale app. Build again to pick up the edits.
- **No worker update is needed.** `STIM_BUILD_COMPAT` stays 2, so 1.31.0 through 1.36.0 machines still offload builds to each other.

## QA

Skipping the pre-tag QA gate is the maintainer's standing default from 2026-10-26: releases skip it unless the maintainer asks for QA, and the maintainer did not ask for it for this release. This deviates from RELEASE.md section 3, which has no waiver for a stable version; the expedited RC lane is for prereleases only and was not used. The waiver covers only section 3. No section 3 QA round ran on any commit since v1.35.0.

Omitted before the tag, for this candidate: the rows that `node scripts/release-qa-matrix.mjs v1.35.0` requires, and the native suites `test/e2e/native/run-native-e2e.mjs` and `test/e2e/native/run-cache-e2e.mjs`, and `test:compat`. Per-change evidence is in the pull requests: [#4577](https://github.com/appandflow/stim/pull/4577) ran `stim-ci build` and `run` on a real iOS Release app (no recorded build refused with `STIM_NO_RECORDED_BUILD`; a cold build, then a run with `launched: true` and no swap) and did not run Android, the EAS download path in `build` or a GitHub-hosted action run; [#4568](https://github.com/appandflow/stim/pull/4568) ran `remote add`, `list` and `remove` on a real tailnet with a scratch `STIM_HOME` and did not run an approve-then-`list` round trip on a worker; [#4575](https://github.com/appandflow/stim/pull/4575) is verified against a captured `xcodebuild` transcript only, not a live Xcode or Gradle failure.

Run before the version commit, on the candidate (the freeze plus the version bump): `pnpm install --frozen-lockfile`, `release:prep --check`, `build`, CLI `--version` (1.36.0), `--help` and `guide agent`, the licenses regeneration that `release:prep` now performs, and pnpm tarball inspection of the thirteen packages (README and LICENSE in each, version 1.36.0, every internal dependency on exactly `1.36.0`).
