# 1.17.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the six npm packages. Commits that only changed those apps are not listed.

## Behavior changes

- **`devices.idleShutdownMinutes` now defaults to 30** (it was `0`, never). The workspace supervisor shuts down an owned simulator or emulator that has been idle for 30 minutes. Set it to `0` to keep the old behavior. [a783d296c](https://github.com/appandflow/stim/commit/a783d296ce2bc3cb5e95df5c1f9a57c4ebed8b3c)
- **New `devices.reclaimIdleMinutes` setting, default 10.** A run that is waiting for a device slot reclaims the slot of an owned device that has been idle that long, shutting that device down. `0` never reclaims. [ff7831db6](https://github.com/appandflow/stim/commit/ff7831db621a10312ba2b4edb484e24cbae6c593)
- **`concurrency.maxDevices` queues instead of refusing.** At the cap, `stim ios` and `stim android` on owned devices now wait for a slot in first-come order across the Stim home (600 seconds by default). `--wait <seconds>` bounds the wait, and `--no-wait` (or `--wait 0`) refuses at once as before. A workspace's own live device skips the queue, remote targets do not join it, and `stim stop` cancels a queued run. [947ffea70](https://github.com/appandflow/stim/commit/947ffea70f03e8a527e194575b9d6eaa3e2bf66a)
- **`--remote auto`** is no longer refused. `stim ios --remote auto` and `stim android --remote auto` (and `ios.remote` / `android.remote` set to `auto`) run on an approved hosting Mac when this Mac is full or busy, and locally otherwise. `offload.saturationLoad` is also the busy threshold for this placement. [4e298d801](https://github.com/appandflow/stim/commit/4e298d80152f9f898d57b7e5393f20735a5e4406)
- **`worktree remove` guardrails.** It refuses, even with `--force`, a folder a `stim-server service` runs from (`STIM_WORKTREE_SERVICE`); reinstall or uninstall the service first. Run from a subfolder of a source checkout, it reclaims only the project at or above that folder and the projects nested under it, and refuses when none is registered there. [e6a057d20](https://github.com/appandflow/stim/commit/e6a057d203de28d3c7e631d046c3671a836e47ab), [a3baff816](https://github.com/appandflow/stim/commit/a3baff816a2b0ada5d719b0318edd8ab360633f4)
- **Hosted devices are parked.** A hosting Mac parks a client's iOS simulator or Android emulator on stop, within `pool.iosParkedMax` and `pool.androidParkedMax`, and the same client adopts it on its next run. Another client never adopts it. Before this release a stopped hosted device was deleted. [96244088f](https://github.com/appandflow/stim/commit/96244088ff6df69af1f79e8128f6b19580b9556f)
- `android.remote` accepts the same values as `ios.remote`: `eas`, `proxy`, `auto` or a tailnet machine name. [4e298d801](https://github.com/appandflow/stim/commit/4e298d80152f9f898d57b7e5393f20735a5e4406)

## New

**Hosted Android**

- `stim android --remote <machine>` runs an owned Android emulator on an approved hosting Mac, as the iOS and macOS hosting paths do. [ad373a6d9](https://github.com/appandflow/stim/commit/ad373a6d9e209f8785f74d445dd650fd71364796)
- Hosted Android uploads only the files that changed, hands over an Android build the same Mac ran for the client, and pulls logcat back for `stim logs`. [1936627c3](https://github.com/appandflow/stim/commit/1936627c38cef796457838643df00afd4ac4fedf)
- Agents drive a hosted Android emulator with agent-device, and Desktop and the phone app view and control it through stim-server's relay. [ecc07f158](https://github.com/appandflow/stim/commit/ecc07f158a7ed7325a5076130b095b32fa3e6dd7), [e51dccf1f](https://github.com/appandflow/stim/commit/e51dccf1f9a42ed745c14d0625fa58c8b291c022)
- A host counts its own devices in hosted admission. [d3099010f](https://github.com/appandflow/stim/commit/d3099010faea2ec948108d2e6a163abff623fa2d)

**Hosted parking and the hosting Mac**

- Hosted simulators and emulators are parked on stop and adopted by the same client; a parked device keeps its upload store, so adoption uploads only changed files. `stim gc` lists and deletes parked hosted devices. [96244088f](https://github.com/appandflow/stim/commit/96244088ff6df69af1f79e8128f6b19580b9556f), [43395b64a](https://github.com/appandflow/stim/commit/43395b64a0cbd6d6d50dca5cde212ab899c5c39d), [ef79fce38](https://github.com/appandflow/stim/commit/ef79fce38960249aff11f3e19eff014309695b75)
- stim-server lists the hosted sessions on the hosting Mac and lets that Mac's person stop them. [f3bfff5e2](https://github.com/appandflow/stim/commit/f3bfff5e20936971d308cc6b89296a5a853a2204)

**Device slots and capacity**

- `status --json` carries `build.waitingFor` for build and device slot waits, and `stats` records `capacityWaits` and `deviceSlotWaitMs`. [947ffea70](https://github.com/appandflow/stim/commit/947ffea70f03e8a527e194575b9d6eaa3e2bf66a)
- `stats` and `status` record device capacity refusals, so Desktop can suggest a hosted simulator when the device limit is hit. [d9718cfc6](https://github.com/appandflow/stim/commit/d9718cfc642d8f28c541845271057ca14390fb4d)
- Concurrent boots hold `concurrency.maxDevices`: the count and the boot record share one lock, so parallel worktrees no longer exceed the cap. [de96761b5](https://github.com/appandflow/stim/commit/de96761b56aa6992a9f1f19555ec194e39460aa8)

**Setup, guides and status**

- `stim guide tutorial` teaches the first run in a sample app, and `status` reports the tutorial marker. [b4f24c6ae](https://github.com/appandflow/stim/commit/b4f24c6ae504959f7115b540272b51163963398f), [e661190d4](https://github.com/appandflow/stim/commit/e661190d45fece06f51153bbc32d4dc6fa28c39c)
- `stim-server setup` (shipped in 1.16.0) is unchanged in the packages. Desktop's Add build machine wizard and Discovery prompts, which ship with Stim Desktop, build on it, and `stim guide settings` tells agents they never run `stim-server setup` or edit `offload.*` themselves.
- Native macOS agent actions show in `stim logs`. [a6958a216](https://github.com/appandflow/stim/commit/a6958a2160956d90b5948cda814b035983d1a3ae)

**Archives**

- stim-server serves an archived workspace's build history and recordings. [2ee0d97e2](https://github.com/appandflow/stim/commit/2ee0d97e206a9fe57c5712b0f79d63f5b5dfbbb7)

## Migration notes

- If you rely on owned devices staying booted for more than 30 idle minutes, set `devices.idleShutdownMinutes` to a larger value, or `0`.
- A run that waits for a device slot may now shut down another workspace's owned device that has been idle for `devices.reclaimIdleMinutes`. Set it to `0` to disable.
- Scripts that expected `stim ios` or `stim android` to fail immediately at the `concurrency.maxDevices` cap should pass `--no-wait`.
