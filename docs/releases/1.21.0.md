# 1.21.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the seven npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci` and `@stim-cli/server`). Commits that only changed those apps, tests or internal structure are not listed.

## New

- **stim-server runs without a login shell, and `stim doctor` reports the toolchain.** stim-server fills the gaps in the environment it was given: it appends the default Node of nvm, fnm, Volta, mise or asdf, Homebrew, `~/.local/bin`, pnpm's and bun's global directories and the Android SDK tools to `PATH`, sets `ANDROID_HOME` to `~/Library/Android/sdk` when it exists, and sets `JAVA_HOME` to a Homebrew `openjdk` (17, then 21, then the newest), else Android Studio's bundled runtime, when no JDK is installed under `/Library/Java/JavaVirtualMachines`. It never replaces a variable it was given. CocoaPods, in the CLI and in the builds stim-server runs, uses the project's `.ruby-version` Ruby, else rvm's or rbenv's default Ruby, and reads the login shell only when neither exists. A variable that only a shell profile sets, such as a `STIM_*` setting, now reaches a service only through its environment or `--env`. On macOS, `stim doctor` adds a **Toolchain** section (`toolchain` in `--json`) that says where `node`, `ANDROID_HOME`, `JAVA_HOME`, `stim`, `brew` and `adb` come from and how to override each, and names the installed Node that satisfies the app's Node pin, which Metro uses when the `node` on `PATH` does not. (`stim`, `@stim-cli/core` `toolchain` export, `@stim-cli/server`) [edaf8b54c](https://github.com/appandflow/stim/commit/edaf8b54c7f2dbda2752d83d2b5fc35fc44b0389)
- **Metro runs on the Node the app pins.** In the expo-child and command-child modes, when `.nvmrc`, `.node-version`, `.tool-versions` or `package.json`'s `volta.node` pins a Node that an nvm, fnm, Volta, asdf or mise install satisfies and the `node` on `PATH` does not, Stim puts that install first on Metro's `PATH`, and the metro log records a `project_node` event naming it. bare-inproc still runs on the supervisor's Node. [edaf8b54c](https://github.com/appandflow/stim/commit/edaf8b54c7f2dbda2752d83d2b5fc35fc44b0389)
- **stim-server serves status views with per-workspace deltas.** A server that offers them lists `status-views` in its `hello` features. `workspaces.subscribe` sends a snapshot of workspace summaries, unprovisioned worktrees and an archive summary, then only the entries that changed, each event numbered by `seq`. `workspace.subscribe` follows one workspace's full environment, and `machine.subscribe` the machine facts. `builds.history`, `archived.list` (paged, at most 50), `worktrees.list` and `maintenance.get` answer from the server's latest status. `status.subscribe` is unchanged. The summaries, deltas and their size budget are derived in `@stim-cli/core`. (`@stim-cli/server`, `@stim-cli/core`) [319671da7](https://github.com/appandflow/stim/commit/319671da7cb4bf49dde924afa88cf86eda4abcff), [593a490fc](https://github.com/appandflow/stim/commit/593a490fcca22b1874a9e7bad7f464ba20fae3fb), [273683d99](https://github.com/appandflow/stim/commit/273683d99073a56c75a775ce0fa5ae4dd2d08621), [e5492ad03](https://github.com/appandflow/stim/commit/e5492ad036577b6b1b407ee98de3c220282638cf)
- **stim-server runs its status watch in a worker thread from startup**, instead of a `stim status --watch --json` child started by the first subscriber, so a new subscriber gets the latest payload at once. Every status subscriber, see-drivers and paired-device feature shares it. (`@stim-cli/server`) [558ce0ecb](https://github.com/appandflow/stim/commit/558ce0ecb51acc283e806e3e0d1a905f164a05b9)
- **`stim status --watch` follows git and process changes.** It now also reacts to git HEAD, index and ref changes in the worktrees' repositories and to the exit of a recorded supervisor, Metro, build, browser or macOS app process (checked every 2 seconds), and polls simulator state every 5 seconds. A log append updates the log-derived facts within about a second instead of up to 15 seconds later; device activity follows at most every 5 seconds. The first line no longer waits for git, so worktree git summaries can be `null` in it and arrive on the next line. [598598e43](https://github.com/appandflow/stim/commit/598598e43780c18e29e542c5b9e872bf9f6b0af2)
- **`createStim().settings()` and `createStim().stats()`** return the `stim settings --json` and `stim stats --json` payloads, read in the importing process against the client's home and project, without starting a Stim worker. `stats()` does not measure the agent-device and SwiftPM cache usage again; it returns what Stim last recorded. `createStim()` takes an `env` object, defaulting to `process.env`, from which Stim reads its settings overrides. A cancelled read stops its child processes and rejects with `STIM_CANCELLED`. stim-server serves `settings.get` and `stats.get` through them. The types `StimReadOptions`, `StimSettings` and `StimStats` are exported. (`@stim-cli/server` too) [c00641db0](https://github.com/appandflow/stim/commit/c00641db03aa9c6208d9680e08ba9775258b3b42), [50548d4c4](https://github.com/appandflow/stim/commit/50548d4c4a5407194fdc87b2618fc75807daa2ee)

## Fixes

- `stim status --watch` prints no line when only a bookkeeping timestamp changed: each `pullRequest.checkedAt`, `maintenance.lastChecks`, `maintenance.lastPass.startedAt` and `durationMs`, and `maintenance.running.startedAt`. A line that prints carries the current values. [3e91e6e7b](https://github.com/appandflow/stim/commit/3e91e6e7b38ad15f0e9b660c95bf943ef05d5e8d)
- A hosted session that the host stopped before it was ready is reported as stopped, with the host's reason and no `stim stop` remedy, instead of as an unknown state. [09535c548](https://github.com/appandflow/stim/commit/09535c548ddfbf754ab0c5060ad798bfd70c7056)
- A cancelled run stops waiting for a hosted app installation or offer at once instead of finishing the poll. [da0bbdc5e](https://github.com/appandflow/stim/commit/da0bbdc5e23ffa95501cad49cc25b4522f8442ee)
- The client's hosted stop and reserve waits derive from the server's worst case: stop waits up to 280 seconds instead of 180, covering parking and the stop after a failed park, and reserve covers the parked sessions it may inspect and retire before it creates a device. (`@stim-cli/core`, `@stim-cli/server`) [a0edec223](https://github.com/appandflow/stim/commit/a0edec223f68c3c900cace7a873516f7c4ff9f4d)
- A hosted session adopted from a parked one starts a fresh native log instead of serving the earlier session's log and checkpoint. (`@stim-cli/server`) [3e915d7b0](https://github.com/appandflow/stim/commit/3e915d7b09c2c2ba5e775aaccfd51f7599082c6b)
- `stim doctor`'s fingerprint parity check compares an app in a repository subdirectory with the same subdirectory of `HEAD`, instead of the repository root. [951a962d2](https://github.com/appandflow/stim/commit/951a962d296ec077c0998e58521a1aaa6d1ee946)
- `stim worktree remove` bounds the git reads it makes before deleting the branch. When one times out, it keeps the directory and Stim's ownership record, or keeps the branch, says so and exits non-zero with a retry command. [6b5207d94](https://github.com/appandflow/stim/commit/6b5207d9442ac9327b0bc6194cb7c754895e055f)
- `stim android` returns from the run when remote cache work was abandoned, instead of exiting the process from inside it, so programmatic callers get the run's result. [c3c1e22d5](https://github.com/appandflow/stim/commit/c3c1e22d5c7393c2a119eb6f74ebed9dc993ce8c)
- The native Android launch line names the variant `debug` when none was set, instead of `undefined`. [bdc2e08ba](https://github.com/appandflow/stim/commit/bdc2e08baa07f6a0405b7f3f268beae7677b4628)
- stim-server removes `NODE_COMPILE_CACHE` from its environment, so the commands it runs do not write into its compile cache. (`@stim-cli/server`) [76d66de6f](https://github.com/appandflow/stim/commit/76d66de6f0d93c2542d4d0ea2f5ebc884f8292dc)
- Device install, launch, shutdown and inventory steps for simulators, emulators, physical iPhones and the release JS swap tools run asynchronously, so a slow `simctl`, `adb`, `avdmanager`, `devicectl`, `zipalign` or `apksigner` call no longer blocks the process. Output and results are unchanged. ## QA

The maintainer approved this release on 2026-10-11. Pre-tag manual QA is omitted, as with 1.18.0 to 1.20.2. This deviates from RELEASE.md section 3, which has no waiver for a stable version.

`node scripts/release-qa-matrix.mjs v1.20.2` requires all eight rows (294 changed paths at the version commit, 127 mapped to a row, 0 unclassified after the removed `knip.json` was classified in this release). Omitted before the tag: the manual field-protocol rows logs, real-repository, remote-provider, release-build, android-flavor and launch-evidence, and local runs of `run-native-e2e.mjs` and `run-cache-e2e.mjs`. The loop and caches rows rely on the Native E2E workflow instead of local runs.

Run before the version commit: `format:check`, `lint`, `build`, `typecheck`, `knip`, `release:prep --check`, CLI version/help/guide, `licenses:check` in `apps/mobile`, and pnpm tarball inspection of the seven packages. Not run locally, left to CI: `pnpm test`, `test:e2e`, `test:runtime` and `test:compat`. Run after push: exact-commit CI, including the full Windows job, and the Release workflow's own gates.
