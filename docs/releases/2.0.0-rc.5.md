# 2.0.0-rc.5

Install `stim@2.0.0-rc.5` to try the fifth Stim 2.0 release candidate. The optional S3 cache provider is available as `@stim-cli/cache-s3@2.0.0-rc.5`.

## New

- **Opt-in helper that restarts runaway Apple background services.** Stim Host 0.2.0 ships a root LaunchDaemon, `stim-host-helper`, that is off until you turn it on with `stim service install --helper` or the toggle in Stim Desktop preferences, and approve it in System Settings > General > Login Items & Extensions. Every minute it samples a fixed list of services matched by full executable path (`PerfPowerServices`, `mds_stores`, `mdworker_shared`, `photoanalysisd` and `mediaanalysisd`). A service that stays over 150% CPU or 2 GB of resident memory for 10 minutes gets `SIGTERM`, at most once per hour per service, and launchd restarts it. The helper accepts no requests and logs to `/Library/Logs/Stim/helper.ndjson`. `stim service uninstall --helper` removes it, and `stim service status` shows its state. Without a healthy helper, `stim status` and the daemon log name a listed service that is over the limit, with its pid, CPU and memory, and suggest the install command. Stim itself never signals these services. Run `stim service install` first to get Stim Host 0.2.0. [e6adfca77b](https://github.com/appandflow/stim/commit/e6adfca77b89f77ab3d3bf9bf57fd998c169140f) [58c04a00e6](https://github.com/appandflow/stim/commit/58c04a00e61251d9fab5e393224af1f5fd2b3779)
- A service start takes a build slot, the same one native builds wait for, from its start command until it is ready, fails, reaches the readiness deadline or is cancelled. This applies to `stim services start` and to the restart in `stim revive`. A waiting start reports the queue on stderr as builds do. A running service holds no slot, and stop and teardown take none. An interrupted `stim services start` exits 130 with `STIM_CANCELLED`. [aaf6342fbb](https://github.com/appandflow/stim/commit/aaf6342fbba385863083a406369d232484421916)
- A service whose `teardown` names `{id}` and that declares no `orphanTeardown` is also torn down with that command, run from the home folder, once its worktree folder is gone. A `teardown` without `{id}` behaves as before, and an explicit `orphanTeardown` still wins. The Supabase and docker compose examples in `stim guide services` use a single `teardown` line. [8642939e4d](https://github.com/appandflow/stim/commit/8642939e4da1e2887a6ab55d3d038677554516e6)

## Fixes

- An EAS simulator session is ended once it is past the maximum duration recorded when it became ready, including on a machine without `eas-cli`, and `stim status` no longer shows it as a running device. [f934e449b4](https://github.com/appandflow/stim/commit/f934e449b48ab857e981c5da261d49c8adfd8967)
- `stim status` and `stim doctor` name the pid of a stimd that does not answer and the command that ends it, `kill -9 <pid>` or `taskkill /PID <pid> /F` on Windows, to use if it still does not answer after a few minutes. The next `stim start`, `ios` or `android` starts a new stimd that takes over the claims. [f885f8eb49](https://github.com/appandflow/stim/commit/f885f8eb496117eaf649baea772855fc3dbaa95b)
- `stim start` waits for its project and workspace locks no longer than `--wait` allows, and a lock that cannot be taken is reported as the lock error. [640908c8d0](https://github.com/appandflow/stim/commit/640908c8d074796af7157c00afc4d2a157d7212e)
- A `--json` run that throws a coded error before printing anything prints one `{code, message, remedy}` payload on stdout. [45800dc19d](https://github.com/appandflow/stim/commit/45800dc19ddc51bf2e87ab3988cb254660e9428f)
- A command run from a working directory that no longer exists says so instead of reporting a crash. [59dc49ca6e](https://github.com/appandflow/stim/commit/59dc49ca6e481509de7b9c048ff34419d608c868)
- `stim serve` exits 1 when a running stimd refuses it because the port is held. [d2ae4bbbbd](https://github.com/appandflow/stim/commit/d2ae4bbbbddd716fe5cce18078fa92c3ad6af9de)
- After a run on a phone, the workspace's simulator or emulator launch record is cleared, and `stim revive` names the phone command instead of relaunching on the earlier device. [3b55d576ae](https://github.com/appandflow/stim/commit/3b55d576ae750cb6ec7b57fbb03da9d88d7323a4)
- A worktree's activity time is read from its last reflog entry, so a git operation that only rewrites `logs/HEAD` no longer makes an idle worktree look active. [d006e4133d](https://github.com/appandflow/stim/commit/d006e4133de989fc38afef876a923bc37381cc07)
- Automatic maintenance and `stim gc` reduce an idle recorded worktree that sits inside a registered checkout. Such a worktree was kept before. [1a9f6c781c](https://github.com/appandflow/stim/commit/1a9f6c781cb83dcba5fc2840ef7be574549554d7)
- A deleted folder that was recorded under a path with a symbolic link or different spelling is removed from the records by `stim gc`. [ec12f66d24](https://github.com/appandflow/stim/commit/ec12f66d2441d684f5852ace065dec2886a416ee)
- stimd reads each worktree's git files without blocking its event loop, so requests are answered while it scans a machine with many worktrees. [988ef53bfd](https://github.com/appandflow/stim/commit/988ef53bfde218a9a15e6f182e696a081795d5e9)
- The gc log no longer gains a line on every tick for each cleanup target that is kept. [4a24a218ee](https://github.com/appandflow/stim/commit/4a24a218ee59bb970cb177bf7531a15211bc6b75)
- `stim worktree warm` skips the CocoaPods step on Linux and Windows. [637ce8cf62](https://github.com/appandflow/stim/commit/637ce8cf6254fdad209160c51ff139d54f17ed3f)
- `stim worktree warm` no longer prints its line about a missing iOS or Android app when it ran from a macOS app, and the line now says that warm registers nothing in `stim status` there and where to run it instead. [a0e7a82afb](https://github.com/appandflow/stim/commit/a0e7a82afbdca2d33e1677a6357a20c34bf2bca2) [81cf792a08](https://github.com/appandflow/stim/commit/81cf792a08722f49e11c31c30bd0398334fcbe72)
- An iOS or Android launch that ends unverified because the device logs were unavailable prints a next step. [85b5a9b0b9](https://github.com/appandflow/stim/commit/85b5a9b0b9e989d236bc7622ca637ac1c8bbcbb2)
- Plain `stim services` shows a failed teardown and its reason. [9e32f9c758](https://github.com/appandflow/stim/commit/9e32f9c7583e376664a5f4d4a53158833d7234bf)
- The hint for a service that is not the default no longer names the default HTTPS port. [bba4f44489](https://github.com/appandflow/stim/commit/bba4f44489b73c333dbe5bee8a09f6ac7a8496f2)
- `stim engine uninstall` restores write permission on the builds it keeps. [3a73ed9b5a](https://github.com/appandflow/stim/commit/3a73ed9b5a551c7664e0b04a1a31b5bbaa5d3ad3)
- `stim doctor` no longer suggests `git stash` for a main checkout with uncommitted changes, and states both crash-hold counts for a stimd that exited abnormally. [11dbe9359f](https://github.com/appandflow/stim/commit/11dbe9359f639f0f527461cc48cb7b70b7ec6ada) [57e732df4b](https://github.com/appandflow/stim/commit/57e732df4bc80f443e436f0ff693d651f265601b)
