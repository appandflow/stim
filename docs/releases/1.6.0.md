# 1.6.0

## New

- Swift joins the shared Xcode compilation cache automatically. When `xcrun swift` reports Swift 6.4 or newer (Xcode 27) and the project's `react-native` is 0.87 or newer, `stim ios` passes `SWIFT_ENABLE_COMPILE_CACHE=YES` with Swift prefix mappings for the workspace root and DerivedData, so Swift output crosses worktrees like clang output already did. Older toolchains, where prefix-mapped batches crashed swift-frontend, and React Native before 0.87, which disables the explicit modules Swift caching requires, stay off. The pre-build cache note names the outcome (`Swift on`, `Swift on, unmapped`, `Swift off, 6.3 < 6.4`, `Swift off, react-native 0.86 < 0.87`), and the post-build line counts any Swift targets Xcode still excluded for building without explicit modules. `optimizations.ios.swiftCompilationCache` is unset by default; `true` forces the cache on any toolchain, unmapped below Swift 6.4, and `false` keeps it off. [2ece2d34d](https://github.com/appandflow/stim/commit/2ece2d34d439e0b621dd52f6a314a5d4213df7c1)

## Migration notes

Preserve existing Stim state when upgrading. The artifact cache key is unchanged for an unset or `false` `swiftCompilationCache`; an explicit `true` keeps its own key as before. On a Swift 6.4 toolchain with React Native 0.87 or newer, the first `stim ios` after upgrading recompiles Swift targets once to populate the shared cache.
