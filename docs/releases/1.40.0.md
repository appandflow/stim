# 1.40.0

This release covers the thirteen npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale`, `@stim-cli/transport-local` and `@stim-cli/server`). No package publishes for the first time in this release. The release was frozen at [968e31ced](https://github.com/appandflow/stim/commit/968e31ced665e84713084e6ad5c6667d195ae969) ([#4974](https://github.com/appandflow/stim/pull/4974)). [#4979](https://github.com/appandflow/stim/pull/4979) landed between the freeze and the version commit and has an entry below. Every commit since v1.39.0 has an entry below. Stim Desktop 0.3.0 ships with this version at the same commit; it carries the Desktop changes listed under 1.38.0 and 1.39.0 as well as those below, because no Desktop release shipped with either. No Stim Host release ships with this version; `packages/server/host` is unchanged since `host-v0.1.1`. The phone app ships through its own workflow.

## New

- **The stim-daemon runs by default and stops idle workspaces on one clock.** One `stim-daemon` per Stim home, started by `start`, `ios`, `android`, `web`, `macos` and `revive`, ticks every minute while anything runs and every five minutes otherwise. A workspace with no activity for `idle.minutes` (default 15, `0` never) has its Metro stopped (the port stays reserved), its owned simulators and emulators shut down and its regenerable build outputs deleted: DerivedData, Gradle outputs, git-ignored in-tree build directories and the Metro store. `stim revive` brings it back from the build cache. Activity is a Stim command, a Metro bundle or HMR request, an agent-device action, input forwarded by stim-server, `stim device lock`, or, on macOS, keyboard or mouse input in the Simulator, Device Hub or emulator window. Device and app logs no longer count. A workspace with a build, a live agent-device session or lease, or a live web share is never staged (Fixes [#4845](https://github.com/appandflow/stim/issues/4845)). New setting `daemon.mode` (`on`, `report`, `off`; env `STIM_DAEMON`); the daemon is off in CI and on Windows, where supervisors and command-time passes time the idle stop. `stim status` and `stim doctor` show the daemon. Fixes [#4809](https://github.com/appandflow/stim/issues/4809) and [#4823](https://github.com/appandflow/stim/issues/4823). - **A pressure ladder frees disk and memory, and admission queues boots and builds.** The daemon classifies the machine normal, high or critical each tick and, above normal, frees space from the longest-idle workspace first: idle stage, parked devices, shared caches, the dormant stage, `node_modules` and Pods of idle linked worktrees (critical only), then idle Gradle daemons, unpinned Gradle versions, temp leftovers and the worktree trash. A workspace idle for `idle.dormantDays` (default 3) goes dormant and its owned devices are deleted. Every boot and native build waits in a first-in-first-out queue under caps derived from cores and memory, and a waiting run prints its position. `stim status` shows the level, its reasons, the ladder's actions and waiting runs. `disk.criticalFreeGb` (default 6) replaces `maintenance.criticalFreeDiskGb`. ## Migration notes

- **Run the removal steps before the first governed command.** `start`, `ios`, `android`, `web`, `macos`, `revive` and `gc` refuse with `STIM_BAD_ARG` while the environment sets a removed variable that used to change behavior, and while a config layer they read still holds a value that turned something off: `maintenance.mode` `off` or `report`, or `metro.idleStopMinutes` or `devices.idleShutdownMinutes` `0`. Each refusal prints the commands to run, in order, for example `stim settings set daemon.mode off`, then `stim settings unset maintenance.mode`; `stim doctor` rates the same leftovers, and also `maintenance.idleStopHours` `0` until `idle.dormantDays` is set (that key is still read for hosted sessions, so it never refuses).

- **Workspaces idle-stop and clear build outputs after 15 minutes without activity.** The daemon deletes DerivedData, Gradle outputs, git-ignored in-tree build directories and the Metro store of an idle workspace (4.3 GB in the test run), and `stim revive` rebuilds from the cache. A workspace idle for three days (`idle.dormantDays`) has its owned devices deleted; the next `stim ios` or `stim android` recreates them. Set `idle.minutes` or `idle.dormantDays` to `0` to opt out, or `daemon.mode off`.
- **`concurrency.maxBuilds` and `concurrency.maxDevices` at 0 now mean derived, not unlimited.** Builds run `max(1, floor(cores/6))` at a time, boots two at a time, and booted devices `max(2, floor((RAM - 4 GB)/1.5 GB))`. A stim-server worker shares its build cap between its own and offloaded builds, so a worker with fewer than 12 cores (a 10-core Mac mini) runs one build at a time; set `concurrency.maxBuilds` on the worker to raise it. A run waits while every holder ahead of it is alive instead of refusing after a fixed 10 minutes, and refuses with `STIM_AT_CAPACITY` after 90 minutes in all, sooner when a holder cannot be verified; `--wait <seconds>` and `--no-wait` bound it.
- **A home with `STIM_HOME` set owns a device only when its ledger lists it.** The pre-ledger config fallback applies only while `STIM_HOME` is unset, so a scoped home, hosted-session homes and `STIM_HOME=~/.stim` no longer shut down or delete a device they did not create.
- **`start`, `ios` and `android` refuse `STIM_LOW_DISK` only while free disk is still under `disk.hardFloorGb` after the ladder ran.** Memory never refuses. A scoped `STIM_HOME` now runs the model with the same defaults (daemon on, disk floors applied).
- **`STIM_BUILD_COMPAT` stays 5,** so 1.39.0 and 1.40.0 machines can offload builds to each other.
- **stim-server protocol changes are additive behind hello features** (`presence`, `device-clipboard`, `share-view-password`, `share-stop-id`, `hosted-presence`) and one new refusal code, `home-unavailable`, which the phone app and Stim Desktop already retry. Update the phone app and Stim Desktop with the server to use the clipboard, view-only password and per-share stop; older clients keep working without them.
- **The npm `next` dist-tag moves with every merge to `main`.** `latest` is unchanged by it. After 1.40.0 publishes, `next` carries `1.41.0-next.*`.
