# 1.20.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the seven npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci` and `@stim-cli/server`). Commits that only changed those apps, tests or internal structure are not listed.

## New

- **Native Xcode and Gradle apps build through project recipes.** The integration registry gains a native Xcode provider and a native Gradle provider, each with its own planning and doctor checks. Xcode selection reads projects, workspaces, schemes and configuration files; Gradle reports application variants through a checked-in model shim. Both use native process readiness, so a live native Debug or custom-configuration app reports `launched: true` without Metro. Only proven Xcode input closures qualify for whole-artifact reuse; native Gradle is not artifact-cache eligible. `stim guide agent` routes native apps to the new `stim guide lifecycle native-ios` and `native-android` sections. `stim` gains two runtime dependencies for reading Xcode projects, `@xmldom/xmldom` and `xcode`. [82e649b4c](https://github.com/appandflow/stim/commit/82e649b4c29d89f7021c93124b06482e84cfc5fb)
- **Native iOS apps run on hosted simulators.** A hosted iOS session negotiates the host capability `hosted-ios-process` and waits for live process readiness instead of a Metro bundle. A host without it is refused before reservation or upload, with an update-stim-server remedy, and `--remote auto` skips it. React Native modes keep bundle readiness. (`@stim-cli/core` protocol, `@stim-cli/server`) [db536eb72](https://github.com/appandflow/stim/commit/db536eb720455f9c4f8a7cfce324a655ae5ee3c9)
- **Native Android apps run on hosted emulators.** The host capability is `hosted-android-process`. A native Gradle app uses an approved hosted Android emulator without starting Metro, and a host without the capability refuses before admission or APK upload. The delivery reuses verified APK transfer and package, SDK and ABI checks. React Native development still requires Metro. (`@stim-cli/core` protocol, `@stim-cli/server`) [8f1bd25d1](https://github.com/appandflow/stim/commit/8f1bd25d19c26c2ded14a0571cc236ddda504cfd)
- **Native Xcode builds can run on an approved build worker.** The client and worker negotiate the capability `native-xcode-build`. Only the contained, Git-visible inputs of the provider snapshot are transferred, and the worker mirrors them exactly. A required ignored or external input, or an unproven cache identity, refuses and the build falls back to local. The client sends its identity parameters with `build.start`, and the worker refuses early with `identity-mismatch` naming the differing parameter (for example `DEVELOPER_DIR`). `LANG` and `LC_ALL` are no longer part of the artifact key. (`@stim-cli/server`) [85ae2d460](https://github.com/appandflow/stim/commit/85ae2d46033cc4a1ed088c0e11fc5f6e331e2ddb)
- **Native Gradle builds can run on an approved build worker.** The capability is `native-gradle-build`, and the project declares what to transfer with the new project setting `android.offloadInputs`: `{"complete": true, "ignored": [...], "outputs": [...]}`. The worker receives Git-visible source plus the exact `ignored` files, and every AGP-reported build directory the build creates must be listed in `outputs`. External inputs, directory links, submodules, a root `buildSrc` and custom machine properties refuse. An undeclared output directory fails the remote build by name and falls back to a local build. The APK has no Stim artifact cache identity; Gradle's own incremental and configuration caches are kept. See `stim guide lifecycle native-android`. (`@stim-cli/server`) [d96f6531b](https://github.com/appandflow/stim/commit/d96f6531b8f2fcff8ce612a0e15e5dc85b730923)
- **`ios.scheme` names a project's Xcode scheme once.** New project setting (workspace and committed layers). `--scheme` still wins when passed; otherwise `ios.scheme` is used by `stim ios`, `--plan`, the native Xcode doctor and the `stim build` API, so the plan and the run agree on the cache key. An `--eas-profile` build reads only the flag. [3d93ba64d](https://github.com/appandflow/stim/commit/3d93ba64d171b220c61799dec7c39d15f3dc27b2)
- **`ios.projectPath` locates a bare React Native app's Xcode project outside `ios/`.** New project setting (workspace and committed layers; default `ios`), a directory relative to the app. `stim ios`, `ios --plan` and `stim build` refuse with `STIM_BAD_ARG` a path that escapes the app, is absolute, or holds no `.xcworkspace` or `.xcodeproj`, and any value on an Expo app. The path is added to the fingerprint, travels to build workers in the build job, and `worktree remove` restores `Podfile.lock` and the app's own `<name>.xcodeproj/project.pbxproj` churn there. [97ca1663e](https://github.com/appandflow/stim/commit/97ca1663eb6e456f9c8be9552737746c56cbdb25)
- **`android.gradleRoot` and `android.module` build a bare React Native app from a Gradle root outside `android/`.** New project settings (workspace and committed layers). `android.gradleRoot` (default `android`) is a directory relative to the app that holds `gradlew` and `settings.gradle`; it may be outside the app but not the repository. `android.module` (default `:app`) is the app's Gradle project path. With either set, Gradle runs from the root with the qualified task (for example `:packages:rn-tester:android:app:assembleDebug`). Both join the cache key as a hashed `gradleProject` component (`@stim-cli/core` `buildCacheKey`) and travel in the remote build job. `stim android`, `--plan` and `stim build` refuse with `STIM_BAD_ARG` a root outside the repository or without `settings.gradle(.kts)`, a module directory without a build script, a malformed module path, and either value on an Expo app. (`@stim-cli/server` accepts the two fields in `build.start`.) [7480ff5d2](https://github.com/appandflow/stim/commit/7480ff5d2fa62d3fa7d8f4558a47742881ac8a54)
- **`metro.command` starts a project's dev server with its own command.** New project setting (workspace and committed layers): an argv array, run without a shell from the app directory, where `{port}` is replaced with the workspace's reserved port. The supervisor uses a third server mode, `command-child`, ahead of ecosystem detection, runs the command in its own process group, and signals the group on every stop path. Output is logged as `command_stdout` and `command_stderr` events and counts as dev-server activity for `metro.idleStopMinutes`. `stim start` refuses with `STIM_BAD_ARG` an empty argv, a blank program, a missing `{port}`, `--reset-cache`, and Windows. Stim adds no bundle-response reporter to this server, so `stim ios` and `stim android` report the launch as unverified; read `stim logs --source metro`. `start` and the iOS and Android launch facts now report the supervisor's recorded mode. [7fcfebd09](https://github.com/appandflow/stim/commit/7fcfebd09c449fbc62b63f62f8955b10319928fd)
- **`stim.build()` in the public API builds an app without launching it.** It builds Android APKs, iOS simulator apps and macOS apps with the same provider recipes, cache validation and build ownership as `run()`. The result is an owned workspace copy kept until `stim worktree remove`. A build-only result is recorded only in build history and in its own `build-artifact-<platform>.ndjson`, so a running app keeps its last-build record, device record and build log, and cache maintenance protects the newest succeeded build key per platform so a later `run` can reuse it. See `stim guide api`. [7d92c3395](https://github.com/appandflow/stim/commit/7d92c33955c75ab393a76672ada9e5a1d5c18fbb)
- **`stim-ci build` and `buildCI` produce an app artifact without starting a runtime.** (`@stim-cli/ci`) `stim-ci build --platform ios|android|macos` calls the public build API and exports an Android APK (`app.apk`) or an Apple app archive (`app.tar.gz`, with executable modes and symlinks preserved) into `--artifacts`, with `build.json`, `result.json` and `diagnostics.json`. A later `run` in the same job can reuse the build from the same Stim cache and reports `cacheKey` and `cacheHit`. Cancellation waits for the owned build to finish cleanup and never calls workspace `stop()`. New error codes: `STIM_CI_BUILD_FAILED` and `STIM_CI_ARTIFACT_FAILED`. Importing a downloaded artifact across jobs is not supported. [90d4d10d1](https://github.com/appandflow/stim/commit/90d4d10d1197ebf389bcabf209353412303e3198)
- **Memory pressure names the process that holds the memory.** When macOS reports warning or critical pressure, Stim reads `top -l 1 -o mem -n 20` and flags a process at or above the larger of 8 GiB and 25% of RAM, or 2 GiB for `fseventsd` and Watchman. The flagged process is named in the iOS boot warning and failure advice, the Android memory phase line and boot-timeout remedy, `stim doctor` (finding `memory-culprit`, skipped when `STIM_HOME` is set), and the maintenance pressure check, which stores it in `maintenance.pressure.memory.culprits` in `stim status --json` (fields `pid`, `name`, `bytes`, `command`, `note`) and shows it on the plain `status` maintenance line. A command is attached only for processes known to be safe to restart: `sudo killall fseventsd` for `fseventsd`, `stim gc --delete --cache watchman` for Watchman, and `stim gc --delete --cache gradle-daemons` for Gradle and Kotlin daemons. Stim never runs these commands itself. [8549b4ff1](https://github.com/appandflow/stim/commit/8549b4ff1ad94e90c173f602cf4c01c97a5322b4)
- **`stim status --json` reports `doctorRuns`** on an environment: `{ ios?: { at }, android?: { at } }`, the time `stim doctor` last ran for each platform in that workspace; the field is absent until doctor has run. [465eb1c5b](https://github.com/appandflow/stim/commit/465eb1c5bf4b2a32080db83dd2cb7099d0e4e322)
- **`stim guide tutorial`: the "Build on Another Mac" step is removed, the begin prompt is shorter, and a new optional last step deletes the test app.** The new `stim guide tutorial delete` section checks the `stimTutorial` marker in `{base}/app.json`, removes each linked worktree and then `{base}` with `stim worktree remove` (never `--force`), and only then runs `rm -rf "{base}"`. The tutorial version is unchanged. [b92e8bc1c](https://github.com/appandflow/stim/commit/b92e8bc1cdc2afb2253a2b6b7ad92d1da4e94757)

## Migration notes

No command, flag or setting is removed. These behaviour changes need attention.

- **`@stim-cli/server` refuses WebSocket upgrades from web pages.** An upgrade that carries `Sec-Fetch-Site`, or an `Origin` other than the requested host (`http://<Host>` with a loopback host name on loopback, `https://<Host>` through `tailscale serve`), now gets HTTP 403 before the auth-failure limiter, without spending the failure budget. Upgrades without `Origin`, such as Desktop and the CLI, pass. Known gap listed in the PR: an iOS simulator app paired to `ws://[::1]:...` sends `Origin: http://::1:...` and is refused; `127.0.0.1` and `localhost` work. A pending approval `HelloResult` no longer carries `server.home`, which is now optional in the core `HelloResult` type and the JSON schema. Paired phone names are cleaned (control and format characters removed except U+200D, whitespace collapsed, cut to 64 UTF-16 units, empty becomes `Phone`). Previously a web page could fill the shared `'local'` limiter bucket and lock out loopback clients for 60 s, and a page on any tailnet node could request `build` access. [6b69ad01a](https://github.com/appandflow/stim/commit/6b69ad01a50e49861c2d67b24bf35765867ba08f)
- **`android.keystorePassword` no longer reaches apksigner's argv, and Stim state is owner-only.** A literal password is passed as `--ks-pass env:STIM_KEYSTORE_PASSWORD` with the value only in the child's environment; `env:`, `file:` and `stdin` references pass through. Stim replaces those values with `***` in a thrown error, so a failed signing step cannot write the password to the workspace build log, which paired devices with `read` can fetch. `$STIM_HOME`, workspace state directories and each ndjson log directory are created 0700 (an existing wider directory is narrowed when the filesystem allows), `config.json` and `created-devices.json` are written 0600 through a temp file, and new ndjson logs open 0600. `@stim-cli/core` exports `ensurePrivateDir`. Existing log files keep their mode. [8eeac50b8](https://github.com/appandflow/stim/commit/8eeac50b8fe34470977cff6abffe8af7b1838701)
- **`stim doctor` no longer executes `fingerprint.config.js` or the project's `eas-cli`.** When `fingerprint.config.js` or `.cjs` exists, doctor skips both fingerprint checks and reports `Skipped the fingerprint checks: fingerprint.config.js is code`. The project eas-cli version is read from `node_modules/eas-cli/package.json`, and `eas whoami` runs only with an `eas` on `PATH` that is outside the git root by path and realpath, not in a `node_modules/.bin` above the project, and with a known repository root. The parity check's temporary worktree runs with `core.hooksPath` pointed at an empty path. `findBinUpward` stops at the git repository root, which builds also see: a hoisted monorepo that is not a git repository no longer resolves a parent `.bin` shim for `expoBinPath` and `resolveEasCliBin`. Doctor still can run installed packages through `@expo/fingerprint` and `npx react-native config` in the parity check; the PR lists this as open. [e18fbec7c](https://github.com/appandflow/stim/commit/e18fbec7c52c8f091c338e31420d4b2d4c1b94fe)
- **Reclaim no longer stops processes on a workspace's named ports.** `stim gc --delete`, `stim worktree remove` and background maintenance release a reserved named port (8900-8999) without looking up or signalling its listener. `stim ports stop` is unchanged. A server a worktree started with `stim ports get` keeps running after removal; stop it first with `stim ports stop`. Before this change, any process that later bound the port, for example Solr on 8983, was killed. [8c6b3816c](https://github.com/appandflow/stim/commit/8c6b3816c135b82b1fc1c59b1ab9711d4433e666)
- **A package that lists `react-native` only under `peerDependencies` now counts as an app.** In a monorepo, a shared package such as `packages/ui` with such a peer dependency is its own workspace, so `logs`, `stop`, `reload`, `settings` and `worktree warm` run from it act on that package; run them from the app directory. Detection reads only `package.json`, so `metro.command` set at either the committed or workspace scope works in such a package. [680afc64c](https://github.com/appandflow/stim/commit/680afc64c51461f5b6fac20a31004a27514db7af)
- **One-shot `stim status` reads git only for live environments.** Idle environments and unprovisioned worktrees report `worktree.git: null` and no `gitChip`; `stim status --watch` still reads every worktree. [08857a71d](https://github.com/appandflow/stim/commit/08857a71d2870cbd70755ec68208964c82b8d4f1)
- **`stim status --watch --json` prints fewer lines.** A usage figure keeps its previously printed value until it moves by a step: an owner's `cpuPercent` by 5 points, an owner's or environment's `memoryMb` and `capacity.committedMb` by 16 MB. A line is still a complete payload. In a watch line `capacity.committedMb` is held separately from the environments' sum. [88ff46f06](https://github.com/appandflow/stim/commit/88ff46f0603110ec477007684fa9105f933a9397)

## Fixes

- CocoaPods runs with the login shell's Ruby environment when no project `.ruby-version` Ruby is installed. Stim takes `GEM_HOME`, `GEM_PATH` and the Ruby-related `PATH` entries from `$SHELL -lic` (10 s timeout, cached per shell), so the `pod --version` probe, `pod install` and the Bundler environment agree, and remote build placement no longer compares a caller's bundled CocoaPods 1.16.2 against a remote Mac's 1.17.0 and falls back to a local build. An installed `.ruby-version` Ruby, an existing `GEM_HOME`, and Bundler-pinned projects are unchanged. [55f102ca9](https://github.com/appandflow/stim/commit/55f102ca9f62dc5ff721da4f106aa512e6fbbf73)
- Relaunching an iOS app on a simulator whose process state cannot be read (the `launchctl list` probe times out) launches with `simctl launch --terminate-running-process` instead of a separate `simctl terminate`, so a just-booted simulator no longer fails with `STIM_LAUNCH_FAILED` when terminate times out. A dev client in that state launches through `--initialUrl` rather than `simctl openurl`. A known pid still gets a separate terminate. Emulators still launch without stopping anything in that state. [93fbdbf37](https://github.com/appandflow/stim/commit/93fbdbf37a5f3d432c39fb94a5abae6c4b2e0415), [076d8b2dc](https://github.com/appandflow/stim/commit/076d8b2dc987c6d1f59388e8c6e73ca82dcba37c)
- Owned-AVD teardown bounds its `emulator -list-avds`, `adb devices` and `emu avd name` inventory queries and kills a timed-out query child. The budget is 15 s per resolver; a timeout fails the teardown and keeps the device record. [d7a4f3355](https://github.com/appandflow/stim/commit/d7a4f33551128c5b0fc05521884c8c5d4d5ed396), [63170af22](https://github.com/appandflow/stim/commit/63170af22a41ace3297a173704043d3555c0665f)
- Temporary Android build artifacts (the APK copy) are released on every exit, including cancellation and device boot or install failure, in the run, build-only and hosted paths. Stable exports and cached APKs are kept. [723801fcb](https://github.com/appandflow/stim/commit/723801fcb6bec676c691ba7e521b53fbbc6e236a)
- Hosted preparation waits 355 seconds before it is refused, where it gave up after 180 seconds although the host allows its preparation worker 300. A resumed session that starts stopping keeps its separate 180-second stop budget. [c194a510f](https://github.com/appandflow/stim/commit/c194a510fa861c82019a6cd40354913b89aac3b9)
- Hosted Android boot failures include the session device's boot-property and package-manager observations in the preparation and adoption failure notices, without host-wide device inventory. [1a058eb73](https://github.com/appandflow/stim/commit/1a058eb733cf29f2e73a88d8b288496ccc65df06)
- Native Xcode worker offers collect only the Xcode, simulator SDK, CPU and Stim matching data through the negotiated capability `native-xcode-toolchain`, instead of CocoaPods, Bundler and other platforms' SDKs. Older native-build-capable hosts still return the complete report. (`@stim-cli/server`) [48f161a6a](https://github.com/appandflow/stim/commit/48f161a6a601d6c075ca100c1610ef49be044a78)
- Hosted Debug runs that start Metro no longer refuse with `metro.ngrokUrl requires metro.tunnel to be "ngrok"` (`STIM_BAD_ARG`) when no layer sets `metro.ngrokUrl`; an `undefined` `ngrokUrl` left by the hosted overlay counts as unset. [227bddc30](https://github.com/appandflow/stim/commit/227bddc309b1ceb504a299a261e253ca51989746)
- Structured Expo bundle-response records (those with a string `requestId`) skip the one-second log dedup, so a dropped `bundle_response_finished` no longer leaves a request open forever and blocks `metro.idleStopMinutes` from stopping that dev server. [b111e54d7](https://github.com/appandflow/stim/commit/b111e54d726cc5f37ed915e17511b46b4c3b0898)
- `stim status` runs at most six git reads at once (the 3 s timeout starts when a read starts), and `tailscale status --json` for a hosted session is read asynchronously instead of with `spawnSync` on the main thread. Before, a one-shot `status --json` with 147 worktrees and environments spawned 147 child processes at once. [08857a71d](https://github.com/appandflow/stim/commit/08857a71d2870cbd70755ec68208964c82b8d4f1)
- `stim doctor` starts its Watchman, device-host, watched-checkout and build-machine probes together, and the remote Mac toolchain comparison (Xcode, simulator SDK, login-shell Ruby, `pod --version`, simulator runtimes) no longer blocks the event loop. Findings, JSON fields and their order are unchanged. [69044fb11](https://github.com/appandflow/stim/commit/69044fb1118a66928397908d93590e26ce46f781)
- `@stim-cli/server` usage history keeps the 15-second slots filled between status lines, so the phone's 10-minute usage chart has no gaps while `status --watch` prints nothing for a steady workspace. [88ff46f06](https://github.com/appandflow/stim/commit/88ff46f0603110ec477007684fa9105f933a9397)

## QA

The maintainer approved this release on 2026-10-10. Pre-tag QA is omitted, as with 1.18.0 and 1.19.0. This deviates from RELEASE.md section 3, which has no waiver for a stable version.

Omitted before the tag, all eight rows of the matrix (`node scripts/release-qa-matrix.mjs v1.19.0`; 366 changed paths, 162 mapped to a row, 0 unclassified after this release adds a rule for `vitest.reap-children.ts`): loop, logs, caches, real-repository, remote-provider, release-build, android-flavor and launch-evidence, plus the native suites `run-native-e2e.mjs` and `run-cache-e2e.mjs`.

Run before the version commit: `format:check`, `lint`, `build`, `typecheck`, `knip`, `release:prep --check`, CLI version/help/guide, `licenses:check` in `apps/mobile`, and pnpm tarball inspection of the seven packages. Not run locally, left to CI: `pnpm test`, `test:e2e`, `test:runtime` and `test:compat`. Run after push: exact-commit CI, including the full Windows job, and the Release workflow's own gates.
