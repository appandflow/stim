# 1.10.0

## New

- `stim ios` and `stim android` start the workspace's dev server when it is not running (including after an idle stop), through the same path as `stim start`; they no longer refuse with `STIM_NO_METRO`. Release configurations, `*Release` variants, and `--no-metro-check` still skip Metro. JSON results report `devServer: { started, reason }` when a run started it. [#1163](https://github.com/appandflow/stim/pull/1163)
- Disk and memory budgets: before `ios`, `android`, and `start` build or boot anything, Stim checks free disk on the workspace and `$STIM_HOME` volumes and committed memory. Below `budget.minFreeDiskGb` (default 20) it reclaims in a safe order (idle devices, idle dev servers, build outputs of idle workspaces, cache entries unused for 14 days) and reports each step; below `budget.hardFloorDiskGb` (default 5) it refuses with `STIM_LOW_DISK`. `doctor` reports the budget. [#1132](https://github.com/appandflow/stim/pull/1132)
- Idle dev servers stop themselves after `metro.idleStopMinutes` (default 60, `0` disables) with no bundle request, client log, or Stim command, never during a build, a driven device, a device lock, or an open bundle request; `status` shows `stopped (idle)`. [#1138](https://github.com/appandflow/stim/pull/1138), [#1144](https://github.com/appandflow/stim/pull/1144)
- `gc` reports every Stim-managed worktree with a reason, and `gc --delete` removes worktrees whose branch was merged (merge, rebase, or squash) with no uncommitted or unpushed work. With `--older-than N`, `gc --delete` now also removes only parked devices parked at least N days ago instead of emptying the pool. [#1133](https://github.com/appandflow/stim/pull/1133), [#1161](https://github.com/appandflow/stim/pull/1161)
- Device activity: `stim status` reports each device as driven (by agent-device, a `stim device lock`, or a driver process), active, idle, or unknown; `gc` lists idle devices and `gc --idle <duration>` shuts them down. [#1101](https://github.com/appandflow/stim/pull/1101)
- `@stim-cli/server` (`stim-server`), a new read-only server for remote clients: QR pairing with single-use tokens and revocable device tokens bound to a Tailscale node, and live status, logs, stats, settings, and device screenshots over a WebSocket. It powers the Stim mobile app (not yet published). [#1139](https://github.com/appandflow/stim/pull/1139), [#1145](https://github.com/appandflow/stim/pull/1145), [#1150](https://github.com/appandflow/stim/pull/1150)
- `@stim-cli/core` exposes a `state` entry point with the read side of Stim's state (paths, config and workspace state, settings registry, ledgers, logs, payload types). [#1131](https://github.com/appandflow/stim/pull/1131)
- Parked simulators are erased and parked emulators have their user data wiped, shrinking each parked device from about 2 GB to a few MB; adoption now cold-boots and reinstalls. [#1140](https://github.com/appandflow/stim/pull/1140)
- `worktree warm` warns when the carried `node_modules` were installed from a different lockfile (npm, pnpm, Yarn Classic, Yarn Berry), with the install command to run. [#1126](https://github.com/appandflow/stim/pull/1126)
- `guide agent` tells agents to leave the machine clean, and the website documents a Claude Code `SessionEnd` hook that runs `stim stop`. [#1128](https://github.com/appandflow/stim/pull/1128)

## Fixes

- Regenerate a stale, gitignored `ios/` or `android/` before a cache-miss Expo build, so an app built from an old native dir is never stored under the new fingerprint; read the iOS scheme and Android package after regeneration. [#1142](https://github.com/appandflow/stim/pull/1142), [#1148](https://github.com/appandflow/stim/pull/1148)
- `gc` and every boot, shutdown, park, and delete trust only devices Stim created (a new creation ledger, or the exact legacy naming format), never any `stim-*` name. [#1105](https://github.com/appandflow/stim/pull/1105)
- Remote iOS installs on EAS Simulator sessions work again (agent-device refused them under the proxy lease); a failure after a billable session started names the session and `stim stop`. [#1127](https://github.com/appandflow/stim/pull/1127)
- Refuse early when eas-cli is too old: below 21.6.0 for `--remote eas`, below 18.9.0 for `--eas-profile`. [#1095](https://github.com/appandflow/stim/pull/1095), [#1129](https://github.com/appandflow/stim/pull/1129)
- Remote Android launches report the public Metro origin and skip adb-only steps. [#1130](https://github.com/appandflow/stim/pull/1130)
- `stop` and `gc --idle` verify a simulator actually shut down and report failures with a remedy; parking waits for the shutdown to settle before erasing. [#1158](https://github.com/appandflow/stim/pull/1158), [#1156](https://github.com/appandflow/stim/pull/1156)
- `status` lists worktrees with no environment for every registered repository, not only the current one, and no longer lists a worktree whose inner package has an environment. [#1106](https://github.com/appandflow/stim/pull/1106)
- `settings --json` reports environment-provided values with their registry type. [#1152](https://github.com/appandflow/stim/pull/1152)
- The release smoke test waits for npm to serve new versions before failing. [#1109](https://github.com/appandflow/stim/pull/1109)

## QA

No-QA stable release explicitly authorized by the maintainer on 2026-09-25,
although this release changes package boundaries (a sixth package,
`@stim-cli/server`) and the Release workflow, which RELEASE.md assigns to the
full lane. Omitted locally before the version commit: format:check, lint,
typecheck, knip, unit tests, test:e2e, test:runtime, test:compat, and the
pre-tag native/manual matrix. Retained before the version commit: candidate
build, CLI version/help/guide, and tarball inspection of all six packages.
Retained after push: exact-release-commit CI, including its format, lint, build,
typecheck, knip, unit, cross-platform e2e, and published-runtime jobs.

Most included changes were reviewed by a fresh agent (and several by Codex)
and merged with passing CI; some were merged without a fresh review at the
maintainer's request. Pull requests record their own real-tool checks
(throwaway simulators and emulators, scratch `STIM_HOME` runs, real EAS
Simulator sessions for #1127 and #1130). The Release workflow publishes
`@stim-cli/server` for the first time; its name was reserved with a `0.0.0`
placeholder and a trusted publisher.
