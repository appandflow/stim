# 2.0.0-rc.8

Install `stim@2.0.0-rc.8` to try the eighth Stim 2.0 release candidate. The optional S3 cache provider is available as `@stim-cli/cache-s3@2.0.0-rc.8`.

## New

- **`stim remote update <machine> --to <version>` installs exactly that published Stim release on a worker.** Stim checks the version against the npm listing first and refuses an unpublished one with `STIM_BAD_ARG` before it contacts the worker. An empty `--to`, or `--to` together with `--channel`, is also `STIM_BAD_ARG`. The bare command and `--channel` behave as before. For a 2.x worker whose peer is too old, doctor's `outdated` finding, the `peer-too-old` refusal and the "exists only on next" message now name `stim remote update <machine> --to <this machine's version>`. The flag is `--to` and not `--version` because `--version` anywhere after `remote` prints Stim's version. [5a38f7c111](https://github.com/appandflow/stim/commit/5a38f7c111979e409a6268e8992dec874ca3e530)

## Fixes

- The commands `stim worktree remove` prints when it refuses or stops partway can now be pasted into a shell as printed. Every path and branch is quoted for the shell in the restore commands, the `git status` check after git timed out, the `git worktree unlock` hint for a locked worktree, the `git branch -D` retry after a failed branch delete, the `stim worktree remove <path>` retries, the hidden-edit `git update-index --no-skip-worktree` or `--no-assume-unchanged` command, and the bare-repository `symbolic-ref`, `worktree prune` and `worktree add` commands, which `stim worktree warm` prints too. On macOS and Linux a path that needs quoting gets POSIX single quotes. Before, a name such as `app/(tabs)/index.tsx` was printed unquoted and others went in double quotes. On Windows a path gets double quotes, or PowerShell single quotes when it holds `$`, a backtick or a double quote. The restore commands are now `git --literal-pathspecs -C <worktree> checkout -- <paths>` and `git --literal-pathspecs -C <worktree> clean -fd -- <paths>`, so a file named `*` or `*.txt` restores or deletes only that file, and a file name that starts with `-` is not read as an option. When more than five files are listed, the command names five and the next line says `(<n> more not listed; git -C <worktree> status -s shows them all)`, where the command used to end in ` ...`. File names with non-ASCII characters, git escapes, or leading or trailing spaces are printed as they are on disk instead of in git's escaped form. ## Migration notes

- **`collectGarbage()` accepts only `pressure` and `signal`, and always deletes.** Any other option, including the 1.40 `delete`, `cache`, `olderThan` and `worktrees`, now rejects with `STIM_BAD_ARG`. As in earlier 2.0 release candidates, a call with no options, or only `signal`, deletes where 1.40 previewed; change those calls to `previewGarbage()`. [b36f3fe4b1](https://github.com/appandflow/stim/commit/b36f3fe4b13c0823f11733a36d14c865b27b8192)
- **`stim worktree list --json` can report a non-null `realBytes` that is only a lower bound.** Check `partial` before treating it as exact. [4036c4d5ec](https://github.com/appandflow/stim/commit/4036c4d5eccef09f60635bfbea2c143bfc1b1d40)
