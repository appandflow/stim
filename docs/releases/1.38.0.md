# 1.38.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the thirteen npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale`, `@stim-cli/transport-local` and `@stim-cli/server`). No package publishes for the first time in this release. The release was frozen at [e3448775e](https://github.com/appandflow/stim/commit/e3448775e906bbfe132f832c296219313e81baa3) ([#4471](https://github.com/appandflow/stim/pull/4471)). Every commit since v1.37.0 has an entry below. No Stim Desktop release ships with this version.

## New

- **`stim ios --install-runtime` installs a missing iOS simulator runtime.** `stim ios --runtime <version> --install-runtime` installs that iOS version with Xcode on this Mac (`--remote local`) or on the explicitly named, approved remote Mac (`--remote <mac>`), and continues only after `simctl` lists it. The new `ios.autoInstallRuntime` setting defaults to `false`. Installs are serialized per Stim home under an ownership claim and a build slot and need 20 GB free. A hosting client asks for the install through the new authenticated `device-host.runtime.install` operation, which is cancelled on disconnect, revocation or server shutdown. Automatic placement, EAS, proxies and physical phones never install runtimes, and installed runtimes stay shared Xcode components that Stim does not claim or prune. Fixes [#4619](https://github.com/appandflow/stim/issues/4619). (`stim`, `@stim-cli/core`, `@stim-cli/server`) [e4843f023](https://github.com/appandflow/stim/commit/e4843f02377dbb36f66ad1789055002f74d4bf4d)
- **The Stim CI action's `command` is optional.** Without a test command, `stim-ci run` installs and launches the recorded app from clean state, writes `run.json`, cleans up and exits 0 with `test: null`, so a later step can drive the app through the `app-path`, `device-id` and `device-name` outputs. An explicit `--` with nothing after it is still refused. A failure after launch without a command reports `STIM_CI_SETUP_FAILED`. Fixes [#4616](https://github.com/appandflow/stim/issues/4616). (`@stim-cli/ci`) [426838996](https://github.com/appandflow/stim/commit/4268389967134472d8783766e2cd297750954de6)
- **Plain `stim gc --delete` shuts down an unused watchman.** It runs the same reclaim as `--cache watchman`: stale roots without subscriptions or triggers are removed, and the daemon stops only when no client but gc is connected and no root has a trigger. The dry run reports watchman's reclaimable bytes. `--cache all` still leaves watchman alone. Fixes [#4649](https://github.com/appandflow/stim/issues/4649). [a76877ec5](https://github.com/appandflow/stim/commit/a76877ec5812c2ab8641151f44b2ac565010120b)
- **An over-cap Swift compilation cache is emptied whole.** Automatic maintenance and plain `stim gc --delete` now empty the shared compilation cache once it exceeds a non-zero `caches.swiftCompilationCacheMaxGb`, without waiting for the hard disk floor; the dry run reports it as "would be EMPTIED". Emptying refuses while an iOS build holds the cache. Fixes [#4650](https://github.com/appandflow/stim/issues/4650). [b0d000d53](https://github.com/appandflow/stim/commit/b0d000d53360dacdc08a77aff01496c206961332)

## Fixes

Fixes [#4655](https://github.com/appandflow/stim/issues/4655). (`stim`, `@stim-cli/core`) [59d421d62](https://github.com/appandflow/stim/commit/59d421d6238e3018a66c5f05eeb4646711190c54)
- **Native fingerprints ignore git metadata and `.expo` state.** `DEFAULT_FINGERPRINT_IGNORES` adds `**/.git`, `**/.git/**` and `**/.expo/**`, so an app that links its library from `..` keeps the same fingerprint across worktrees, commits and Metro runs. Fixes [#4635](https://github.com/appandflow/stim/issues/4635) and [#4659](https://github.com/appandflow/stim/issues/4659). [045d7eb4e](https://github.com/appandflow/stim/commit/045d7eb4e036243e1d096d1a2b6c188bba04fe1f) [dec2d6075](https://github.com/appandflow/stim/commit/dec2d607501cd787ec878ae8ebd47ba9d7461773)

Otherwise it leaves the directory out with one stderr line. The dependency drift check now finds the nearest lockfile above each carried `node_modules`. Fixes [#4657](https://github.com/appandflow/stim/issues/4657). [e005ccb72](https://github.com/appandflow/stim/commit/e005ccb72080aff5d47655a62a47602074007d33)
- **Removed workspace directories stay removed, and `gc` deletes their leftovers.** Maintenance no longer recreates a removed workspace's directory to write its per-workspace log, and `gc` treats a directory holding only those logs as residue. Fixes [#4651](https://github.com/appandflow/stim/issues/4651). [d1cbffb4e](https://github.com/appandflow/stim/commit/d1cbffb4e855e6260b14b2f3a3228b9c87191621)

Other `stim-*` devices are still not touched. Fixes [#4636](https://github.com/appandflow/stim/issues/4636). ## Migration notes

- **No worker update is needed for builds.** `STIM_BUILD_COMPAT` stays 2, so 1.31.0 through 1.38.0 machines still offload builds to each other. `stim ios --install-runtime --remote <mac>` needs that Mac's stim-server on 1.38.0.
- **`caches.swiftCompilationCacheMaxGb` now defaults to 0 (no cap).** A machine that relied on the previous default of 15 sets it explicitly; with a cap set, `gc --delete` and automatic maintenance empty the whole cache once it exceeds the cap.
- **Plain `stim gc --delete` now stops an idle watchman daemon.** Use `--cache <name>` to limit gc to specific caches.
- **Fingerprints of apps that link their library from `..` change once** because of the new ignores, so their first build after upgrading misses the cache.

## QA

Skipping the pre-tag QA gate is the maintainer's standing default from 2026-10-26, and the maintainer confirmed publishing 1.38.0 without QA on 2026-11-01. This deviates from RELEASE.md section 3, which has no waiver for a stable version; the expedited RC lane is for prereleases only and was not used. The waiver covers only section 3. No section 3 QA round ran on any commit since v1.37.0.

Omitted before the tag, for this candidate: the rows that `node scripts/release-qa-matrix.mjs v1.37.0` requires, and the native suites `test/e2e/native/run-native-e2e.mjs` and `test/e2e/native/run-cache-e2e.mjs`, and `test:compat`. Per-change evidence is in the pull requests.

Run before the version commit, on the candidate (the freeze plus the version bump): `pnpm install --frozen-lockfile`, `release:prep --check`, `build`, CLI `--version` (1.38.0), `--help` and `guide agent`, the licenses regeneration that `release:prep` performs, and pnpm tarball inspection of the thirteen packages. The format, lint, typecheck, knip, RPC and unit checks run in the version pull request and its merge-queue run, per RELEASE.md section 2 step 2. Run after the version commit lands: the release gate of RELEASE.md section 4 step 4 on the exact release commit, and the Release workflow's own gates. The full Windows unit suite runs in `Post-release validation`, recorded, not gated.
