# 1.37.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the thirteen npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale`, `@stim-cli/transport-local` and `@stim-cli/server`). No package publishes for the first time in this release. The release was frozen at [c93f02bc8](https://github.com/appandflow/stim/commit/c93f02bc8a60b10c9c7be77ed84e7a34f4b19101) ([#4606](https://github.com/appandflow/stim/pull/4606)). Every commit since v1.36.0 has an entry below. Stim Desktop 0.2.16 ships from the same release commit.

## New

- **`stim-ci run` starts from clean app state on every run.** `stim-ci run` now sets the new `cleanAppState` run option. Before install, iOS uninstalls every other user app, clears the kept app's defaults and data container and resets the simulator keychain (XCUITest runner apps are kept); Android uninstalls other third-party packages and runs `pm clear` on the app. The running app is stopped before its data is cleared. `cleanAppState` refuses a hosted placement, a remote host, and a device Stim does not own, and a pinned remote is refused before Android placement. Plain `stim ios` and `stim android` still clean only on adoption. Fixes [#4579](https://github.com/appandflow/stim/issues/4579). (`stim`, `@stim-cli/ci`) [c93ccf459](https://github.com/appandflow/stim/commit/c93ccf459b4cba43e975df1e203eecfb7ff93c4b)
- **The `stim-ci` GitHub Action accepts the build selectors `stim-ci` takes.** The action's build step now takes the same selectors as `stim-ci build`; build-only inputs are refused when the action does not build. Fixes [#4580](https://github.com/appandflow/stim/issues/4580). (`@stim-cli/ci`) [d84a43888](https://github.com/appandflow/stim/commit/d84a43888204189b5d03eb591fd211c8d03da14d)
- **The `stim-ci` GitHub Action sets build and run facts as step outputs.** App facts are read on every platform and `cache-hit` is a boolean. Fixes [#4581](https://github.com/appandflow/stim/issues/4581). (`@stim-cli/ci`) [75824543b](https://github.com/appandflow/stim/commit/75824543bc0542beab81e084fe3b30b72b22e549)
- **Stim Desktop: opt-in High stream quality for device viewers.** A preference and a per-viewer quality control stream a device at High. The default stays Standard, a keyframe request is cancelled on resubscribe, and quality is honored for remote owners. (Stim Desktop) [c842988ac](https://github.com/appandflow/stim/commit/c842988ac7ff7aa6b8dbf270eb196bb71330c824)

## Fixes

- **`stim-ci build` always compiles on this machine, and `stim-ci run` follows remote placement.** `stim-ci build` no longer follows remote placement, and `stim-ci run` cleans only local devices. The docs say to build for the remote architecture when `run` can land on a remote Mac. (`@stim-cli/ci`, `stim`) [75f08a2e0](https://github.com/appandflow/stim/commit/75f08a2e0d3f09a8bce606a80f8f65a5b304c560)
- **EXPO_PUBLIC values from other builds stay out of Release JS swaps.** The Release swap's Metro cache is isolated per workspace and keyed on the `EXPO_PUBLIC_*` values, `EXPO_NO_DOTENV` and `NODE_ENV`, so a swap no longer embeds values from an earlier bundle. Fixes [#4585](https://github.com/appandflow/stim/issues/4585). (`stim`) [0b807e0ef](https://github.com/appandflow/stim/commit/0b807e0efe1284c05abbc855b4f31750def56244)
- **Local Release iOS simulator apps build for the host architecture only.** A local non-Debug simulator build used to compile every `ARCHS` value. `stim ios` now passes the host arch to `xcodebuild`, and the cache key ends in the arch; `stim build` and `stim-ci build` keep `--arch all` for a universal app under the unsuffixed key. `@stim-cli/expo-build-cache` keys every iOS simulator configuration on the host arch, matching the CLI. Fixes [#4582](https://github.com/appandflow/stim/issues/4582). (`stim`, `@stim-cli/expo-build-cache`) [144a5ecef](https://github.com/appandflow/stim/commit/144a5ecef576cea5565060901a92093ad04682b1)
- **Each successful build prunes unrecorded per-build app copies.** A successful iOS, Android or macOS build removes the workspace's other `artifacts/<platform>-*` copies that no recorded build points to. Fixes [#4583](https://github.com/appandflow/stim/issues/4583). (`stim`) [f0c187dda](https://github.com/appandflow/stim/commit/f0c187ddaf1b1874245c89504ef44f5be8f21511)
- **`worktree warm` no longer carries Expo Router typed routes.** A source checkout that had not run Metro since a route was added held a stale `.expo/types/router.d.ts`, which failed `tsc` in every warmed worktree. Expo regenerates it on the first `expo start`. Fixes [#4591](https://github.com/appandflow/stim/issues/4591). (`stim`) [48dd8dac1](https://github.com/appandflow/stim/commit/48dd8dac1f071ee9e240034f576aefa835a45375)
- **Tailscale CLI calls work without `TERM`.** Tailscale children get a CLI-safe `TERM` when the caller's is unset or empty; other children keep the caller's environment. (`stim`) [5b4c989e1](https://github.com/appandflow/stim/commit/5b4c989e103a0f888522831bc7c2e24b0d6a583c)
- **An EAS iOS launch reports process verification as unavailable.** `launched` is `'unverified'` with an explanation that the remote adapter accepted the launch, and no local `simctl` or device log remedies are printed. (`stim`) [de25b3e98](https://github.com/appandflow/stim/commit/de25b3e98d40a41a47c0580db8fda33ac44427ae)
- **Stim Desktop streams at Standard when the server cannot send H.264 for High**, including when a relay reports the host refused High. (Stim Desktop) [a8350b64b](https://github.com/appandflow/stim/commit/a8350b64ba63663157b1d789d43efc17598424ff)
- **Stim Desktop linked machines look like the other machine cards**, and the selected card keeps its status dot visible. (Stim Desktop) [32d82488f](https://github.com/appandflow/stim/commit/32d82488f72fd8a6096860fb483b5bf572d9e5aa)
- **Stim Desktop parses fewer timestamps in workspace models**, preserving epoch millisecond log boundaries. (Stim Desktop) [c93f02bc8](https://github.com/appandflow/stim/commit/c93f02bc8a60b10c9c7be77ed84e7a34f4b19101)
- **Test only:** the storage-volume e2e exercises the copy fallback when `clonefile` is available. No shipped behavior changes. [229dafcf4](https://github.com/appandflow/stim/commit/229dafcf4ad363a79fc99fe3fb44189d3beb43c0)

## Migration notes

- **No worker update is needed.** `STIM_BUILD_COMPAT` stays 2, so 1.31.0 through 1.37.0 machines still offload builds to each other.
- **Local Release iOS simulator builds are host-arch only.** A Release simulator app built by `stim ios` runs on this Mac's architecture; use `stim build` for a universal app. Existing Release simulator cache entries under the previous key are not reused.

## QA

Skipping the pre-tag QA gate is the maintainer's standing default from 2026-10-26: releases skip it unless the maintainer asks for QA, and the maintainer did not ask for it for this release. This deviates from RELEASE.md section 3, which has no waiver for a stable version; the expedited RC lane is for prereleases only and was not used. The waiver covers only section 3. No section 3 QA round ran on any commit since v1.36.0.

Omitted before the tag, for this candidate: the rows that `node scripts/release-qa-matrix.mjs v1.36.0` requires, and the native suites `test/e2e/native/run-native-e2e.mjs` and `test/e2e/native/run-cache-e2e.mjs`, and `test:compat`. Per-change evidence is in the pull requests.

Run before the version commit, on the candidate (the freeze plus the version bump): `pnpm install --frozen-lockfile`, `release:prep --check`, `build`, CLI `--version` (1.37.0), `--help` and `guide agent`, the licenses regeneration that `release:prep` performs, and pnpm tarball inspection of the thirteen packages. The format, lint, typecheck, knip, RPC and unit checks run in the version pull request and its merge-queue run, per RELEASE.md section 2 step 2. Run after the version commit lands: the release gate of RELEASE.md section 4 step 4 on the exact release commit, and the Release workflow's own gates. The full Windows unit suite runs in `Post-release validation`, recorded, not gated.
