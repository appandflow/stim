# 1.23.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the twelve npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale` and `@stim-cli/server`). No package publishes for the first time in this release. Commits that only changed those apps, tests, CI or internal structure are not listed.

## New

- **Private Desktop stim-server method `desktop.settings.schema` (feature `desktop-settings-schema`).** It returns the server's registry-derived settings JSON Schema, takes no parameters, and is available only to the Desktop connection that proves the bundled server's private bootstrap key for the same Stim home; phones, other local clients and remote clients are refused. Stim Desktop's Settings editor reads its field definitions from it instead of from schema files of an external CLI installation. (`@stim-cli/server`, `@stim-cli/core`) [8f9ae81a4](https://github.com/appandflow/stim/commit/8f9ae81a42e38c3256ea2047f791350dbba2a5d9)

## Fixes

- **A fingerprint change no longer deletes a gitignored Expo native directory and its Pods.** When `ios/` or `android/` was not generated from the current fingerprint, Stim ran `expo prebuild --clean`, which deleted the directory, including `ios/Pods`, and forced a full `pod install`. It now updates the directory in place with `expo prebuild --no-clean` on Expo SDK 57 and later, whose CLI deletes native folders by default, and with plain `expo prebuild` before SDK 57, whose CLI keeps them and rejects `--no-clean`. On iOS it then runs `pod install` against the existing `ios/Pods`. The build progress line reads `not generated from this fingerprint -> updated in place`. A build offloaded to another machine still regenerates that machine's copy with `--clean`. When the in-place prebuild fails, `STIM_PREBUILD_FAILED` carries a remedy to delete the directory and run again; `stim guide errors`, `stim guide lifecycle` and the build-caches page list the changes that need a fresh directory (a removed config plugin, an Expo SDK or React Native upgrade, an app rename, a plugin that is not idempotent) and `--no-build-cache` for a build already cached under the current fingerprint. [0a0e046d6](https://github.com/appandflow/stim/commit/0a0e046d68658069d5aa5757f0737142d4692b9d)

## Migration notes

- An in-place prebuild does not undo what earlier config wrote into a gitignored `ios/` or `android/`. After removing a config plugin or upgrading the Expo SDK or React Native, delete that directory before the next `stim ios` or `stim android`.
