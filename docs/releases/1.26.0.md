# 1.26.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the twelve npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale` and `@stim-cli/server`). No package publishes for the first time in this release. Commits that only changed those apps, tests, CI or internal structure are not listed.

## New

- **Automatic maintenance shuts down idle devices that have no dev server.** The workspace supervisor already shut down an owned simulator or emulator after `devices.idleShutdownMinutes` (30) without activity, but a device with no supervisor, such as after a Release run or a dev server that exited, stayed booted. A new maintenance check, every `maintenance.idleCheckMinutes` (new, default 5), shuts those down by the supervisor's own idle rules: booted, no driver, native-run lock, lease, viewer or build, and no activity for the workspace's `devices.idleShutdownMinutes`. It re-checks each device before acting, shuts it down through centralized teardown and never deletes it, and `stim status` shows `shut down after <N>m idle`. It skips the workspace of the command that started the pass and plans nothing under a scoped `STIM_HOME`. `stim gc` without `--delete` lists the planned shutdowns in its maintenance plan. Stim does not see a person clicking around Simulator.app, so a simulator with no app logs can shut down while someone looks at it. Refs [#2598](https://github.com/appandflow/stim/issues/2598). [6fe868797](https://github.com/appandflow/stim/commit/6fe86879726d8a1402ed1f22009602f03f32b4cd)
- **The maintenance age sweep removes parked devices and, opt-in, idle worktrees.** The sweep now deletes parked simulators and emulators unused for `maintenance.olderThanDays` (7) through centralized teardown, as `gc --older-than` does; before, maintenance deleted parked devices only under disk pressure. The new machine setting `maintenance.removeIdleWorktrees` (default `false`, env `STIM_MAINTENANCE_REMOVE_IDLE_WORKTREES`) also removes clean, pushed linked worktrees that no Stim command has used for `maintenance.olderThanDays`, even when their branch never merged, with their git-ignored files; it needs `maintenance.removeFinishedWorktrees`. gc's rules still apply: never a dirty or unpushed worktree, the source checkout, or one whose last use is unknown. `maintenance.olderThanDays 0` is now valid and turns the age removals off; before, 0 was rejected. Refs [#2598](https://github.com/appandflow/stim/issues/2598). [368c217c1](https://github.com/appandflow/stim/commit/368c217c1d416c22afb39731a308e5839260be63)
- **A machine-wide log records what gc, maintenance and the budget gate cleared.** Every run that deletes or changes something appends one record per item to `$STIM_HOME/gc/gc.ndjson`: `gc --delete`, `--idle` and `--cache` (trigger `manual`, or `desktop` from Stim Desktop), maintenance actions in `on` mode (trigger `maintenance`, with the pass id), and the budget gate's reclaim steps before `start`, `ios` and `android` (trigger `budget`), including the dev servers it stops. Each record has `kind`, `status` (`done`, `kept` or `failed`), `label`, `id`, `path`, `bytes` and `detail`. Dry runs and runs that only kept things write nothing. The log rotates with `maintenance.logMaxMb` and `maintenance.logRetentionDays`. `stim logs --source gc` reads it from any directory, with `--json`, `--since`, `--grep`, `--tail`, `--follow` and `--errors`; `gc` cannot be combined with other sources and is not part of `--source all`. ## Fixes

- **Fingerprints use `@expo/fingerprint` 0.21's balanced preset.** A native package is now hashed by name and version instead of by its files, which cuts fingerprint CPU on `apps/mobile` from 3.6 s to 1.6 s on iOS and from 5.2 s to about 1.8 s on Android, and lets a same-version pnpm reinstall with different peer suffixes hit the cache. Every cache key moves once (see Migration notes). Patches at the monorepo install root and the `patchedDependencies` hashes in `pnpm-lock.yaml` are hashed, so a patch outside the app's `patches/` still moves the key. A native package's version bump is reported as one `changed` source in the miss line. A hand edit to a native file inside `node_modules/` no longer moves the key; use a patch, or `--no-build-cache --remote-build local`. A project's `fingerprint.config.js` can still choose `strict`. Refs [#4236](https://github.com/appandflow/stim/issues/4236). [1025d319d](https://github.com/appandflow/stim/commit/1025d319daed818e690b5dd29e6a7889318dbb39)
- **A workspace's first `stim ios` or `stim android` reuses a full fingerprint recorded for the same tree.** Each full fingerprint is recorded under a static digest of the tree in `$STIM_HOME/fingerprint-memo/<platform>/`, so a fresh worktree of an already built commit or a new agent session skips the config evaluation and autolinking. The static digest covers the tracked native inputs by git blob id, changed and ignored inputs by content, the config's own sources, `.env` files and the environment variables it reads, every installed package's path, version and native markers, the lockfile and the fingerprint options. A config it cannot read statically, such as one with a dynamic `require` or `fs` access, always takes the full fingerprint. After a hit, a low-priority full fingerprint confirms the record in the background while the app installs; a disagreement prints a `fingerprint` line naming both hashes, writes `fingerprint_memo_stale` to the build log, drops the record, and leaves the run's artifact in place. The run waits at most 3 s for the check. Only the pre-mutation lookup uses the memo; `--no-build-cache` skips it. `gc` prunes the directory with the other caches. Closes [#4209](https://github.com/appandflow/stim/issues/4209), refs [#4236](https://github.com/appandflow/stim/issues/4236). (`stim`, `@stim-cli/core`) [a2399ee5f](https://github.com/appandflow/stim/commit/a2399ee5fedb8939c588ba80973143b57032aa4f)
- **A cached `stim android` proves the installed APK from its signed tail.** Instead of hashing the whole installed APK on the device and the local one in Node (7 to 12 s for a 119 MB APK under load), Stim compares the installed size and the SHA-256 from the v2 or v3 signing block through the end of the file with values recorded beside the cached APK after one `apksigner verify`, in one `adb shell` call. A different size or tail installs at once. The whole-file hash remains for APKs outside a build cache entry, APKs without a v2 or v3 block, a missing `apksigner`, and devices that cannot answer the probe. Android verifies the bytes before the signing block at install, so the only case no longer caught is a rooted write to the installed `base.apk`. Fixes [#4210](https://github.com/appandflow/stim/issues/4210). [b4a48303b](https://github.com/appandflow/stim/commit/b4a48303ba0a9f152a3c77d9731a56cd6deb108c)
- **`stim ios` mutes a running simulator again after SimSlim reboots it.** With `ios.simslim` on or a changed `ios.simslimProfile`, the reconcile on an already-running owned simulator rebooted it and left it at volume 60. Stim now compares SpringBoard's startup pid before and after the reconcile and mutes the simulator when it changed; an `Already slim` run leaves the volume alone, so a Desktop Sound choice survives. When a pid read fails, Stim mutes anyway. The guide and website now say a running simulator is slimmed on the next `stim ios`. Fixes [#4250](https://github.com/appandflow/stim/issues/4250). [a3880edc6](https://github.com/appandflow/stim/commit/a3880edc6bd02a2bf0a0e65876b237e1e24b5b57)
- **`stim ios` skips the SimSlim reconcile on an unchanged profile and boot.** The owned device record now stores `simslimApplied: { profile, springBoardPid }` after a reconcile, and a rerun with the same profile content and the same SpringBoard pid skips `simslim` and its `applying` line, saving about 1 s of the preamble. Any other case reconciles as before. A manual `simslim off` on a running simulator is noticed only after a reboot or a profile change. Fixes [#4289](https://github.com/appandflow/stim/issues/4289). ## Migration notes

- **Update the client Mac and its build workers together again.** `STIM_BUILD_COMPAT` goes from 1 to 2 because every fingerprint key moves. A 1.26.0 machine and a 1.25.x machine report different compatibility versions, so they never offload to each other: automatic placement builds locally, and a named build machine refuses with `STIM_OFFLOAD_REFUSED`. Update a worker's service with `stim-server service update --release 1.26.0`.
- **Every build cache key moves once.** The first `stim ios` and `stim android` of each project, platform and variant after the update misses the cache and builds. Entries stored by earlier versions stay until gc ages them out.
- **A hand edit inside `node_modules/` no longer changes the cache key.** Use a patch, which is hashed, or build with `--no-build-cache --remote-build local`.
- **Automatic maintenance does more by default.** With `maintenance.mode on` (the default outside a scoped `STIM_HOME` and CI), owned devices without a dev server shut down after `devices.idleShutdownMinutes` (30), and parked devices unused for `maintenance.olderThanDays` (7) are deleted. Set `devices.idleShutdownMinutes 0` or `maintenance.olderThanDays 0` to keep them, or pin a workspace with `maintenance.keep`. Idle unmerged worktree removal stays off unless `maintenance.removeIdleWorktrees` is set.
- **New state under `$STIM_HOME`:** `gc/gc.ndjson` and its rotated generation, and `fingerprint-memo/<platform>/`. The owned iOS device record gains `simslimApplied`.
- **stim-server request limits changed.** A local client can run 32 requests per connection instead of 4; a tailnet device is limited to 16 across its connections. Report waits have their own limit of 16 per connection.
- **Stim Desktop 0.2.7 needs this release** for its Automatic Maintenance settings, Cleanup History and the remote machine diagnosis; with an older `stim` those parts ask to update it.

## QA

The maintainer authorized a stable release without the pre-tag QA gate on 2026-10-22, as for 1.16.0 through 1.25.0. This deviates from RELEASE.md section 3, which has no waiver for a stable version; the expedited RC lane is for prereleases only and was not used. The waiver covers only section 3. No section 3 QA round ran on any commit since v1.25.0, so no change in this release has been through QA, including the idle-device shutdown and parked-device age sweep in automatic maintenance, the gc log, the `@expo/fingerprint` 0.21 keys and the fingerprint memo, the signed-tail APK proof, the SimSlim mute and skip, hosted readiness, and the offload changes on a second Mac.

Omitted before the tag, for this candidate: all eight rows that `node scripts/release-qa-matrix.mjs v1.25.0` requires (246 changed paths with the version commit, 93 mapped to a row, 153 with no native effect, 0 unclassified): loop (expo and bare, iOS and Android), logs (iOS, Android), caches (iOS, Android), real-repository, remote-provider, release-build (iOS, Android), android-flavor and launch-evidence (iOS, Android), plus the native suites `test/e2e/native/run-native-e2e.mjs` and `test/e2e/native/run-cache-e2e.mjs`.
