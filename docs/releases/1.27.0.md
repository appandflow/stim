# 1.27.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the twelve npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale` and `@stim-cli/server`). No package publishes for the first time in this release. Commits that only changed those apps, tests or CI are not listed: [#4341](https://github.com/appandflow/stim/pull/4341), [#4346](https://github.com/appandflow/stim/pull/4346), [#4376](https://github.com/appandflow/stim/pull/4376), [#4423](https://github.com/appandflow/stim/pull/4423), [#4424](https://github.com/appandflow/stim/pull/4424), [#4425](https://github.com/appandflow/stim/pull/4425), [#4426](https://github.com/appandflow/stim/pull/4426), [#4427](https://github.com/appandflow/stim/pull/4427), [#4428](https://github.com/appandflow/stim/pull/4428) and [#4439](https://github.com/appandflow/stim/pull/4439), and the Stim Desktop parts of [#4331](https://github.com/appandflow/stim/pull/4331) and [#4332](https://github.com/appandflow/stim/pull/4332).

## New

- **`gc --delete` lightens workspaces that did not run a native build in the last 15 minutes.** A workspace's build outputs (`derived-data/` and the rest under its Stim workspace, and the project's own `android/app/build`, `android/build`, `android/.gradle` and `.build` when git ignores every file in them) are now cleared once no `stim ios`, `android` or `macos` run, cache hits included, has happened there for 15 minutes. The time comes from the workspace's build records, not from its logs, so a dev server that runs all day no longer keeps the outputs; only a native run, a build lock or slot, an active build claim or a running macOS app does. `ios/build` is never cleared, because `pod install` writes codegen output and podspec facades there that only `pod install` recreates. Maintenance at disk pressure level 2 now clears build outputs and build directories by the same rule instead of its 10-minute `maintenance.pressureProtectMinutes` window and full in-use check, and no longer deletes `ios/build`. The shared build cache, the Xcode compilation cache and the Gradle and Metro caches are not touched. The report says `would be LIGHTENED` and lists the in-tree directories; `gc --json` adds `inTreeDirs` to each `workspaceBuildOutputs` entry. Fixes [#4397](https://github.com/appandflow/stim/issues/4397) and [#4413](https://github.com/appandflow/stim/issues/4413). - **Finished worktrees with uncommitted files are archived, then removed.** A linked worktree that is otherwise removable (merged into the default branch or its pull request merged or closed, pushed, not locked or in use) but has uncommitted or untracked files was kept forever. gc and automatic maintenance now write `tracked.patch`, `untracked.tar`, `head.bundle` (the HEAD commits the default branch lacks) and `manifest.json` under `$STIM_HOME/archive/worktrees/<repo>/<branch-or-dir>-<timestamp>/` once the worktree has been idle for `gc.worktreeGraceMinutes` (120), verify the archive, check again just before `git worktree remove --force` that nothing changed, and then remove the worktree. The removal line, the gc log and the maintenance log name the archive and the commands that restore it. Ignored files are not saved. `archive.enabled false`, for the worktree or a project registered inside it, keeps such worktrees as before; `archive.maxAgeDays` (30) and `archive.maxTotalGb` (5, a budget of its own for worktree archives) bound them, and an archive that would not fit or would take free disk under `budget.hardFloorDiskGb` keeps the worktree. Disk pressure level 3 and `stim worktree remove` never archive. Clean worktrees with no commits of their own, detached HEADs included, whose HEAD the default branch contains and which have no open pull request, now count as finished once idle for `max(gc.worktreeGraceMinutes, maintenance.protectRecentHours)`, 2 hours by default, instead of only under disk pressure. A worktree that holds the running `stim` or the `stim` on PATH is in use, and `stim worktree remove` refuses it even with `--force`. `stim guide agent` now tells agents to remove the worktrees they create and keep scratch files outside them. ## Fixes

- **A cached iOS app that dyld cannot bind at launch is removed from the cache.** A Debug simulator app stored by 1.26.0 could hold a Debug `React.framework` and a Release `hermesvm.framework`, so dyld killed it on every launch and every cache hit installed it again. After a fatal launch of a cache hit, Stim now reads the run's crash reports; when one is a dyld `Symbol missing` failure between two images inside the app's own bundle, it removes that cache entry and fails with `STIM_LAUNCH_FAILED`, naming the entry and asking to run again. A missing system library, any other crash and an app built by the same run leave the cache alone. A cache provider's copy cannot be removed; the remedy points at `--no-build-cache`. Hosted and remote devices are unchanged. Fixes [#4412](https://github.com/appandflow/stim/issues/4412). [ef46995f7](https://github.com/appandflow/stim/commit/ef46995f7561e8a7424773de312c3f71aa04f970)

Every `pod install` Stim runs, locally, on a build worker and in `worktree warm --refresh`, now puts a marker back when its pod directory is the one that existed before, and says so in a `pods` note. Fixes [#4377](https://github.com/appandflow/stim/issues/4377). [8ec1967ae](https://github.com/appandflow/stim/commit/8ec1967ae105d6e24b7c95a8e5b63632bade3718)

## Migration notes

- **gc and maintenance clear idle worktrees sooner.** `stim gc --delete` and maintenance at disk pressure level 2 clear the build outputs of a workspace with no `ios`, `android` or `macos` run in the last 15 minutes, even while its dev server runs. `gc --delete` now also deletes `node_modules` and `ios/Pods` of a linked worktree idle for 15 minutes when warm can restore them. Disk pressure level 3 deletes them as before, by its own 10-minute window and whether or not warm can restore them, and records them for restore only when it can. After either, the next `stim start`, `ios` or `android` there runs `stim worktree warm` first. Other commands, such as a test run, find the directories missing until then; run `stim worktree warm` in the worktree. A build Stim did not run, such as a hand-run `gradlew`, leaves no record, so `gc --delete` and level 2 judge its build directory by the last Stim native run alone and can clear it at once.
- **`ios/build` is never cleared** by gc or maintenance; level 2 used to delete it.
- **Dirty finished worktrees are archived, then removed.** Their changes go to a new directory under `$STIM_HOME/archive/worktrees/<repo>/`, named after the branch or directory, a timestamp and a random suffix, and the removal line, `stim logs --source gc` and the maintenance log print the restore commands. The `bundle unbundle` line appears only when HEAD has commits the default branch lacks:

  ```sh
  git -C <repository> bundle unbundle <archive>/head.bundle
  git -C <repository> worktree add --detach <path> <HEAD>
  git -C <path> apply <archive>/tracked.patch
  tar -xf <archive>/untracked.tar -C <path>
  ```

  Set `archive.enabled false` to keep such worktrees instead; that also turns off the workspace history kept on removal. Under a custom `STIM_HOME`, `archive.enabled` already defaults to `false`, so such worktrees are kept there. Ignored files are not archived.

- **Clean detached and no-commit worktrees count as finished after 2 hours** (`max(gc.worktreeGraceMinutes, maintenance.protectRecentHours)`) and are removed by `gc --delete` and automatic maintenance. `gc --worktrees --older-than N` no longer holds them for N days. Use `git worktree lock` on one that must stay.
- **Check for a broken cached iOS Debug app from 1.26.0.** With React Native 0.88's prebuilt core, 1.26.0's `pod install` could drop the build configuration markers and store a Debug simulator app that dyld kills at launch. A 1.27.0 build no longer produces one, but a 1.27.0 machine that offloads to a 1.26.0 worker still can, because the worker runs `pod install`. The first crashing launch of such a cache hit removes the entry; run the command again to rebuild. A provider's copy stays: build once with `--no-build-cache`. A worktree whose markers already read `Debug` over Release binaries is not detected; run `rm -rf ios/Pods/React-Core-prebuilt ios/Pods/hermes-engine ios/Pods/ReactNativeDependencies` and `pod install` there. Update build workers to 1.27.0 too.
- **`remote.buildMode` was replaced by `remote.build`.** `auto` stays `auto`, `force` becomes `remote` and `off` becomes `local`; A leftover key is not an error: runs print that it is not read, `stim doctor` reports it for each file that holds it with the `stim settings set remote.build <value>` command, and `stim settings unset remote.buildMode` removes it from every layer. `STIM_REMOTE_BUILD_MODE` is removed and runs ignore it without a warning; only `stim doctor` reports it. Use `STIM_REMOTE_BUILD` instead, for example `STIM_REMOTE_BUILD=local` where you had `STIM_REMOTE_BUILD_MODE=off`; otherwise the default `auto` applies and builds can go to a remote machine. In 1.26.0 `remote.buildMode` applied only while `remote.build` was `auto`, so if `remote.build` already names a machine, keep it and just unset `remote.buildMode`.
- **The order of `remote.machines` is the placement priority** for builds, devices and macOS apps; set it with `stim settings set remote.machines '["first","second"]'`. Builds no longer prefer the less loaded or warmest machine.
- **`STIM_BUILD_COMPAT` stays 2.** A 1.27.0 machine and a 1.26.0 machine offload to each other. Update a worker's service with `stim-server service update --release 1.27.0` to get the worker-side fixes, including the `pod install` marker fix.
- **Debug iOS simulator builds have no dSYM.** Tools that need a dSYM for a Debug simulator build get none; Release and device builds are unchanged.
- **New state under `$STIM_HOME`:** `builds/builds.ndjson`, `budget-sweep.json`, `archive/worktrees/`, and `workspaces/<id>/lightened.json`. Trash entries written by `worktree warm` carry `kind: warm`. Workspace logs gain `ios_boot` and `springboard_crash_reports` records and copied `SpringBoard-*.ips` files.
- **Stim Desktop 0.2.8 needs this release** for its Builds section and a machine's build list, which read `stim logs --source builds`, and for the Remote Macs order and the Add Machine wizard's build choices, which write placement words 1.26.0 does not know.

## QA

The maintainer authorized a stable release without the pre-tag QA gate on 2026-10-25, as for 1.16.0 through 1.26.0. This deviates from RELEASE.md section 3, which has no waiver for a stable version; the expedited RC lane is for prereleases only and was not used. The waiver covers only section 3. No section 3 QA round ran on any commit since v1.26.0, so no change in this release has been through QA, including gc and maintenance lightening and the dependency restore through warm, worktree archives, the no-own-commit worktree rule, the placement vocabulary and `remote.machines` priority, the build ledger, `STIM_TRACE`, the dyld cache eviction and `pod install` marker restore, the SpringBoard restart, the Debug dSYM skip, and the Linux worker script.
