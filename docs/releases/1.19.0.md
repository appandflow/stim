# 1.19.0

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the seven npm packages, including the new `@stim-cli/ci`. Commits that only changed those apps are not listed.

## New

- **Auto placement can fall back to an EAS Simulator.** New setting `remote.easFallback` (default `false`, machine or project scope). When `ios.remote` or `android.remote` is `auto`, this Mac is at its `concurrency.maxDevices` cap and no Mac in `remote.machines` takes the run, the simulator or emulator runs on a billed EAS Simulator through the existing `--remote eas` path instead of waiting or refusing with `STIM_AT_CAPACITY`. A Mac that is only busy with a free slot never bills. A read-only check runs first (eas-cli and agent-device present, no conflicting flags or EAS session, a reachable Metro origin, `eas simulator:availability`); when it fails, placement behaves as before. The placement record says why EAS was or was not used, and `devicePlacement.decision` can be `eas`. An EAS placement keeps billing until `stim stop`. `--plan` with auto refuses with `STIM_BAD_ARG` when it would use EAS. [abfca8b29](https://github.com/appandflow/stim/commit/abfca8b290c968aa234a0421cada23fef85cefe5)
- **`local` is a reserved value for `ios.remote`, `android.remote` and `--remote`.** It runs the device on this Mac and overrides an `auto` set at a lower layer. A tailnet Mac named `local` can no longer be targeted by `--remote`. [10ff88a79](https://github.com/appandflow/stim/commit/10ff88a79b037d45502cc558c8328f29247baa28)
- **A rewritten `stim guide tutorial` (tutorial version 2)**, which Stim Desktop's tutorial follows. It clones `appandflow/stim-tutorial`, has the agent make a change and a parallel change in two worktrees, then covers live view, agent actions, logs, building on another Mac, an optional pull request to the tutorial repository, and removing the two worktrees. Every tutorial iOS run uses `stim ios --remote local --remote-build local`, so its builds and devices stay on this Mac; the optional machine step builds on the named Mac with `--remote-build`. [2c9b5a259](https://github.com/appandflow/stim/commit/2c9b5a2592792f4cf53299dfc337eb2631e1e199), [10ff88a79](https://github.com/appandflow/stim/commit/10ff88a79b037d45502cc558c8328f29247baa28)
- **New package `@stim-cli/ci` with a `stim-ci` executable.** `stim-ci run --platform ios|android|macos|web -- <test command>` builds and launches the app through the public `stim` API, runs the test command, keeps its exit status, stops the workspace, and keeps structured results and diagnostics in `--artifacts`. A managed GitHub Action in this repository (`.github/actions/stim-ci`) wraps it and uploads those results as a workflow artifact. On GitHub-hosted runners with no explicit home it uses a job-local Stim home and build cache under `$RUNNER_TEMP/stim-ci`. New error codes: `STIM_CI_SETUP_FAILED`, `STIM_CI_TEST_FAILED`, `STIM_CI_TIMEOUT`, `STIM_CI_CANCELLED`, `STIM_CI_CLEANUP_FAILED`, `STIM_CI_DIAGNOSTICS_FAILED` and `STIM_CI_REPORT_FAILED`. See the package README and the website's CI page. [1cf1c7403](https://github.com/appandflow/stim/commit/1cf1c740358648eb88668f6dbd914d30f9ded00b), [808af7c4f](https://github.com/appandflow/stim/commit/808af7c4f7aae7caddcb70f6f5c24857ef7dfc2b), [56317a90d](https://github.com/appandflow/stim/commit/56317a90d98d7b29dd10b45c4cbcfae2d206dd95)
- **Automatic pool members can be turned off.** New machine settings `remote.buildPoolDisabled` and `remote.devicePoolDisabled` list members (`local` or exact `remote.machines` entries) that this Mac's automatic build or device placement skips. Explicit placement and running builds or sessions are unaffected, and each pool must keep one enabled member; when every enabled member is unavailable, Stim refuses instead of using a disabled one. [d6f652965](https://github.com/appandflow/stim/commit/d6f652965bc5c222748f779b6aa6d9837d3356eb)
- **`stim macos --plan --json`** checks the declared packaging inputs without building, launching or contacting a worker, and prints one typed JSON payload, including for refusals. [f6f18f958](https://github.com/appandflow/stim/commit/f6f18f9586c0834b09af50f60399edaff61af0be)
- **`stim doctor` reports worktrees nested in a checkout that Watchman would crawl** (finding `watchman-nested-worktrees`). `stim doctor --fix` adds the worktrees' parent folder, or each worktree, to the checkout's `.watchmanconfig` `ignore_dirs`. Doctor never runs `watchman watch-del`; it prints the command when Watchman already watches the checkout. [8ebe432bd](https://github.com/appandflow/stim/commit/8ebe432bdca02e541cebd947b3a2b8995696ba61)
- **`stim status --json` reports `agentDevice.installed`**, whether `agent-device` is on PATH. [2c9b5a259](https://github.com/appandflow/stim/commit/2c9b5a2592792f4cf53299dfc337eb2631e1e199)

## Fixes

- **Faster port allocation.** Metro and named-port allocation read the OS TCP listener table once (`netstat` on macOS and Windows, `/proc/net` on Linux) instead of probing each candidate. A named port is allocated in about 5 ms where 1.18.0 took 90 ms, or 800 ms with IPv6 listeners. Metro allocation now also detects IPv6-only and LAN listeners, which 1.18.0 missed and could pick an occupied port. When the listener table cannot be read, allocation fails with the new error code `STIM_PORT_INSPECTION_FAILED` rather than guessing, and on Windows `stim ports stop` keeps reservations instead of removing them. [a30008561](https://github.com/appandflow/stim/commit/a30008561be6ac44ff005028a33691d95a888f91)
- **`stim status` no longer piles up `du` processes.** A checkout is measured without the worktrees nested in it, which have their own figures, so `worktreeBytes` for such a checkout is smaller. Only one `du` runs at a time on the machine, at `nice -n 19`, and a failed or timed-out walk is cached for the same period as a success. This removes the load spikes when several `stim status --watch` instances ran at once. [0e25072d2](https://github.com/appandflow/stim/commit/0e25072d2faaabbc9daa535056682861a74a2f32)
- **`stim stop` stops every running copy of a `stim macos` app**, not only the one it recorded, including copies opened from Finder or the Dock. Relaunch and workspace removal do the same, and `gc --delete` refuses while an unrecorded copy runs. A copy whose executable cannot be confirmed refuses the stop with the new error code `STIM_MACOS_OWNER_UNVERIFIED`. The stop waits up to 12 seconds for the supervisor, so a slow-exiting app is no longer left running. [79c7cc590](https://github.com/appandflow/stim/commit/79c7cc59038f997438ef7745fd10e79e04503e48)
- `stim worktree warm` run from a worktree root records the agent on the app workspace it prepares, so Desktop attributes the agent's actions to that workspace. [b04479cfc](https://github.com/appandflow/stim/commit/b04479cfc89cd58740cfa5180920326fc59d8c02)
- Hosted iOS and Android devices report the `device`, `install` and `launch` build phases while they are placed on another Mac, so `stim status`, `stim stats` and Desktop show the step in progress. [de7e8a659](https://github.com/appandflow/stim/commit/de7e8a659fcba7dc3e74d6204f91d9234a1d2281)
- `stim stop` cancels an offloaded build in progress and reports `STIM_CANCELLED` instead of starting another build, reconnect or artifact fetch. [123ed658c](https://github.com/appandflow/stim/commit/123ed658ccce512c611986a7dde84b534c8ff13f)
- A device wait cancelled by `stim stop` no longer starts a reclamation afterwards. [48d99c91d](https://github.com/appandflow/stim/commit/48d99c91d8a434e74580c661727269e0215232e3)
- iOS bundle requests wait for the client lookup before Metro serves them, so a launch is attributed to its workspace instead of racing it. [f741720db](https://github.com/appandflow/stim/commit/f741720dbcf644abd56cb72d7a893f5b4442c0e7)
- Agent log attribution compares exact device and inode IDs of the log file, read as bigint stats, so a replaced log file is not mistaken for the original. [d50226af5](https://github.com/appandflow/stim/commit/d50226af5d490d07c778573ddd324de6c8897c4f) (`@stim-cli/core`)
- The programmatic API infers a run's result type from the requested platform. [d928510ff](https://github.com/appandflow/stim/commit/d928510ff93b06b1a9967d52433026f4fae5ddbb)
- Debug logs (`debug.logs`) record iOS app process inspection outcomes, in-flight native stop phases, and hosted worker cancellation paths (`@stim-cli/server`), without arguments or environment contents. [abf9826d7](https://github.com/appandflow/stim/commit/abf9826d7e45af833157f607afe4ded2e42f45cf), [4679d436f](https://github.com/appandflow/stim/commit/4679d436f87fb9e70c21f367b7e4acf84bda54fd), [463cd44e0](https://github.com/appandflow/stim/commit/463cd44e07dc2d02ebbea760432f0617f0cc8e41)

## QA

The maintainer approved this release on 2026-10-09 ("npm 1.19.0 + Desktop 0.1.19"), to ship origin/main as it stood. Pre-tag QA is omitted, as with 1.18.0. This deviates from RELEASE.md section 3, which has no waiver for a stable version, and from docs/release-recovery.md, which asks for the full lane on the first release that contains a new package (`@stim-cli/ci`).

Omitted before the tag, all eight rows of the matrix (`node scripts/release-qa-matrix.mjs v1.18.0`; 314 changed paths, 106 mapped to a row, 0 unclassified after this release adds rules for `packages/ci`, `.gitattributes` and `.watchmanconfig`): loop, logs, caches, real-repository, remote-provider, release-build, android-flavor and launch-evidence, plus the native suites `run-native-e2e.mjs` and `run-cache-e2e.mjs`.

Run before the version commit: `format:check`, `lint`, `build`, `typecheck`, `knip`, `release:prep --check`, CLI version/help/guide, `licenses:check` in `apps/mobile`, and pnpm tarball inspection of the seven packages. Not run locally, left to CI: `pnpm test`, `test:e2e`, `test:runtime` and `test:compat`. Run after push: exact-commit CI, including the full Windows job, and the Release workflow's own gates.
