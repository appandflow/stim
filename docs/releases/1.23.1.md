# 1.23.1

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the twelve npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/cache-s3`, `@stim-cli/agent-driver`, `@stim-cli/agent-driver-agent-device`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci`, `@stim-cli/transport`, `@stim-cli/transport-tailscale` and `@stim-cli/server`). No package publishes for the first time in this release. Commits that only changed those apps, tests, CI or internal structure are not listed.

## Fixes

- **An offloaded build runs the project's own Node code on the Node the project pins.** The build worker puts the Node that `.nvmrc`, `.node-version`, `.tool-versions` or `package.json`'s `volta.node` pins, in the app's directory or the nearest one above it in the checkout, first on `PATH` before the dependency install, prebuild, pods and xcodebuild, and logs the Node it builds on on the `deps` line. On iOS it writes that Node as `NODE_BINARY` in the project's `.xcode.env.local`, which React Native's Xcode script phases read. Before, those steps ran on the worker's own `node`, so a project pinning another major could fail to install or build on the worker. A warm Gradle daemon keeps running React Native's Node steps on the Node it started with ([#4081](https://github.com/appandflow/stim/issues/4081)). The worker's dependency marker names the pinned Node's major, so a change of major reinstalls the dependencies and an install made under another major is not ranked as reusable. When no installed Node fits the pin, the steps run on the worker's `node` and a `deps-failed` or `prebuild-failed` reason names the pin and that Node's version. (`stim`, `@stim-cli/server`, `@stim-cli/core`) [3b5309620](https://github.com/appandflow/stim/commit/3b530962004a9af74d908c74cf22177c0fb9091f)
- **Pinned Node discovery finds linked Homebrew `node` and `node@NN` installs, and falls back within the pinned major.** This applies to Metro's Node and to the build worker. When no install has the exact version the pin names, Stim takes the newest installed Node of the pinned major that is not older than the pin, such as Homebrew's `node@22` at 22.23.2 for a `22.22.0` pin, and keeps a `node` on `PATH` that meets the same rule. The Metro log, the worker log and `stim doctor` say when a fallback was used, and `stim doctor --json` adds `match` (`"exact"` or `"major"`) to `toolchain.projectNode`. (`stim`, `@stim-cli/core`) [3b5309620](https://github.com/appandflow/stim/commit/3b530962004a9af74d908c74cf22177c0fb9091f)
- **An owned iOS simulator stays muted after boot.** SpringBoard sets its default volume while it starts, a few seconds after `simctl bootstatus -b` returns on a warm boot, so the mute Stim applied and confirmed right after boot was undone and the simulator played sound at volume 60. Stim now waits up to 30 seconds for SpringBoard's `com.apple.springboard.finishedstartup` state before it sets and confirms volume zero. When that state cannot be read or SpringBoard does not finish in time, startup prints the existing could-not-mute warning instead of `simulator muted`. [f349af1da](https://github.com/appandflow/stim/commit/f349af1dafd2069f20fc01c6ef7b6a994fac1696)

## QA

The maintainer authorized a stable release without the pre-tag QA gate on 2026-10-20, as for 1.22.0 and 1.23.0. This deviates from RELEASE.md section 3, which has no waiver for a stable version; the expedited RC lane is for prereleases only and was not used. The waiver covers only section 3.

Earlier on 2026-10-20, a full section 3 QA round ran against `main` at [c132bb118](https://github.com/appandflow/stim/commit/c132bb118b3d0d396505f7f0b20559e0dd465912), with v1.21.0 as the regression baseline: all eight rows of `node scripts/release-qa-matrix.mjs v1.21.0`, on Expo and bare fixtures, Word-Darts and tlon-apps, with janics-mac-mini as the remote worker. It found no regression from v1.21.0. It filed [#4075](https://github.com/appandflow/stim/issues/4075) (the iOS simulator mute did not hold, a 1.22.0 claim) and pre-existing issues [#4069](https://github.com/appandflow/stim/issues/4069) (HIGH: a hosted iOS Debug Expo dev-client app never loads JS, still open and not addressed by this release), [#4070](https://github.com/appandflow/stim/issues/4070), [#4071](https://github.com/appandflow/stim/issues/4071), [#4072](https://github.com/appandflow/stim/issues/4072), [#4073](https://github.com/appandflow/stim/issues/4073) and [#4074](https://github.com/appandflow/stim/issues/4074). That round did not cover either change in this release: both fixes above landed after c132bb118, and the mute fix for #4075 was not exercised by it.

Omitted before the tag, for this candidate: all eight rows that `node scripts/release-qa-matrix.mjs v1.23.0` requires (27 changed paths, 11 mapped to a row, 16 with no native effect, 0 unclassified): loop (expo and bare, iOS and Android), logs (iOS, Android), caches (iOS, Android), real-repository, remote-provider, release-build (iOS, Android), android-flavor and launch-evidence (iOS, Android), plus the native suites `test/e2e/native/run-native-e2e.mjs` and `test/e2e/native/run-cache-e2e.mjs`.
