# 1.20.2

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the seven npm packages (`@stim-cli/core`, `@stim-cli/cache`, `@stim-cli/metro`, `@stim-cli/expo-build-cache`, `stim`, `@stim-cli/ci` and `@stim-cli/server`). Commits that only changed those apps, tests or internal structure are not listed.

## New

- **`workspace.hidden` hides a workspace in Stim Desktop and the phone app.** New boolean setting, workspace scope only, default `false`: `stim settings set workspace.hidden true` from the workspace. `stim status --json` then reports `hidden: true` on that environment. The next `start`, `ios`, `android`, `web`, `macos`, `reload` or `worktree warm` in the workspace clears it, and `worktree remove` drops it with the workspace. (`@stim-cli/core` setting and status type) [1186ed44d](https://github.com/appandflow/stim/commit/1186ed44da030f10511967a69376bd21fce6a921)

## Fixes

- **Security:** on a checkout without its own dependencies, such as a fresh worktree or a hoisted monorepo app, `stim doctor` skips the fingerprint parity check and says why when Expo packages resolve from outside the app, or when the check would need `npx react-native config` (Android, or a project without an `ios` directory). Before, that check could run project code that doctor does not install or own. The linked-library check can still run installed Expo packages on the main checkout, as a build does. [26a22d93c](https://github.com/appandflow/stim/commit/26a22d93ca4aa16f111f4207c9677a6113efd915)
- `stim gc` lists stale entries of the machine EAS session ledger (`~/.stim/machine/eas/sessions.json`) under "Stale EAS ledger entries": an entry whose id is not a UUID and whose absolute workspace root is missing on a mounted volume, such as ids written by a test fixture. A valid id, an existing root, or a root on an unmounted volume keeps the entry. `stim gc --delete` re-checks each entry and removes it under the ledger lock without contacting EAS. `gc --json` adds `sections.staleEasLedgerEntries` with `id` and `workspaceRoot`. [2b0e36d5b](https://github.com/appandflow/stim/commit/2b0e36d5b455bfc8efeb80ecc51c10032d5cb6df)
- Every child process Stim starts has a time budget. Git calls default to 10 seconds, read-only ones run with `--no-optional-locks`, and asynchronous reads run at most six at a time. The git reads that gate `stim worktree remove` get 60 seconds; when one times out, removal refuses before any teardown with `a git safety check timed out` instead of treating a registered worktree as a plain folder. `stim gc` reports a worktree whose unpushed commits or initialized submodules could not be checked as skipped with that reason. [5f56cc4dc](https://github.com/appandflow/stim/commit/5f56cc4dc15034b47d493307f9ef9f24bdb5b14f), [bbb96cb96](https://github.com/appandflow/stim/commit/bbb96cb96bc8dee34805f5ded619fbf06dafcf0b)
- `stim status --json` reports a workspace whose macOS app is running or orphaned as `stage: running`, from the app's build end when no Metro supervisor runs. Stim Desktop and the phone app now show the stage, app presence and git chip that stim reports instead of computing their own. (`@stim-cli/core`) [14c46bf48](https://github.com/appandflow/stim/commit/14c46bf488c04355b3524070f1de22f06b006522)
- The Release workflow refuses to publish a tag whose commit is not on `main`. This changes the release process, not a package. [2bbf06e69](https://github.com/appandflow/stim/commit/2bbf06e694d76f3d7703c943a3fd4e4ff6da9215)

## Docs

- `stim guide tutorial run` has the agent check the change by picking a size (`size-s`, `size-m` or `size-l`) instead of typing a name. [e50e7b25b](https://github.com/appandflow/stim/commit/e50e7b25b8d9b794006521a677b1385350f26b56)
- `stim guide macos` has the agent wait until `lsappinfo` lists the app's recorded pid before `agent-device open`, because `stim macos` can return before macOS LaunchServices lists the app, and opening it then starts a second copy without Stim's launch arguments. [a3a4c9fd6](https://github.com/appandflow/stim/commit/a3a4c9fd6e2f8d0dac2ead69517ef15334e31c06)

## QA

The maintainer approved this release on 2026-10-10. Pre-tag QA is omitted, as with 1.18.0 to 1.20.1. This deviates from RELEASE.md section 3, which has no waiver for a stable version.

Omitted before the tag, all eight rows of the matrix (`node scripts/release-qa-matrix.mjs v1.20.1`; 193 changed paths, 50 mapped to a row, 0 unclassified): loop, logs, caches, real-repository, remote-provider, release-build, android-flavor and launch-evidence, plus the native suites `run-native-e2e.mjs` and `run-cache-e2e.mjs`.

Run before the version commit: `format:check`, `lint`, `build`, `typecheck`, `knip`, `release:prep --check`, CLI version/help/guide, `licenses:check` in `apps/mobile`, and pnpm tarball inspection of the seven packages. Not run locally, left to CI: `pnpm test`, `test:e2e`, `test:runtime` and `test:compat`. Run after push: exact-commit CI, including the full Windows job, and the Release workflow's own gates, including its new tag-on-main check.
