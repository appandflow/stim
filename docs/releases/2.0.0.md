# 2.0.0

Stim 2.0 is the one-engine release. One `stim` package and one resident `stimd` per Stim home run what 1.40 split across `stim`, `stim-server`, `stim-ci` and per-workspace supervisors, and `stim gc` now deletes instead of only reporting. Everything after Known issues is the complete reference.

## Highlights

- **One `stimd` per Stim home** runs Metro, tunnels, device logs and maintenance.
- **One package.** `stim serve`, `pair`, `pairings`, `service`, `setup` and `ci` replace the `stim-server` and `stim-ci` binaries.
- **Cleanup that acts.** `stim gc` deletes at the measured disk pressure level, and `stim worktree list` shows what cleanup will do with each worktree.
- **Builds.** Stim computes its own build-cache fingerprint, and `stim ios` runs Exact apps.
- **Project tooling.** `stim services` runs per-worktree databases and API servers, and `stim test` runs tests under a machine-wide slot.
- **A stable contract within 2.x.** `--json` payloads and API results only gain fields and enum values.

## Before you upgrade

Removed (breaking) has the details and the smaller breaks.

- **`stim gc` deletes, and its 1.40 flags are gone.** Preview with `stim gc --dry-run`.
- **`collectGarbage()` in the JavaScript API always deletes.** Call `previewGarbage()` where a 1.40 call only previewed.
- **Cleanup defaults are stricter, and `ios.simslim` is on.** To keep a 1.40 value, run `stim settings set <key> <value> --scope machine` before the first 2.0 command that starts `stimd`.
- **`stim-server`, `stim-ci` and eleven `@stim-cli/*` packages are gone.** Use the commands above, import from `stim`, and remove `@stim-cli/metro` and `@stim-cli/expo-build-cache` from the project.
- **Update everything that talks to `stim`:** Stim Desktop, the phone app, each service, each offload worker, `@stim-cli/cache-s3` and the `stim-ci` GitHub Action.
- **Removed settings and environment variables** are mostly ignored; a few make commands refuse and print the fix. `stim settings` and `stim doctor` list them.
- **`fingerprint.config.js`:** only `extraSources` still changes the build-cache key, and only while `cache.fingerprintInputs` is unset.
- **Save manual edits in an untracked, generated Expo `ios/` or `android/`.** The first 2.0 run prebuilds it once.

## Upgrade

1. With 1.40 still installed, run `stim status`, then `stim stop` in each running workspace, in each Stim home.
2. Run `npm install --global stim@2.0.0`, or move the project's `stim` pin.
3. Before any other command, run `stim guide agent`, `stim settings` and `stim doctor`, and settle what they report.
4. Stop the 1.40 daemon with the command `stim status` prints. It blocks 2.0 until you do.
5. Update everything listed above. For each service, run `stim service install` with its existing options.
6. Update project files and scripts. Migration notes has a `git grep` for them.
7. Run `stim doctor` and `stim guide agent` until STATUS is clear. Expect one cold native build per fingerprint.

Or paste this into your coding agent:

```text
Upgrade this machine and project from Stim 1.40 to 2.0 by following https://stim.appandflow.com/docs/migrate-to-2. First list the workspaces `stim status` shows under 1.40. Once I confirm, stop them, install stim 2.0 the way 1.40 was installed, run `stim guide agent` and work through that page's "For agents" section in order. Ask me before you stop a process, change an environment or a default, edit ~/.stim/config.json, reinstall a service or update another machine. Finish with `stim doctor` and tell me what you changed and what is left.
```

## Known issues

- A stimd that holds its claim but does not answer is reported, not replaced ([#5774](https://github.com/appandflow/stim/issues/5774)).
- `stimd` does not restart by itself ([#5579](https://github.com/appandflow/stim/issues/5579), not planned).
- A worker restart cancels its offloaded builds ([#5588](https://github.com/appandflow/stim/issues/5588), not planned).
- `stim worktree warm` can carry a workspace package's stale build output, such as `dist` ([#5853](https://github.com/appandflow/stim/issues/5853)).
- An EAS Simulator session can run to its duration cap when `stim` is killed hard while creating it ([#6493](https://github.com/appandflow/stim/issues/6493)). Stop it with `eas simulator:stop --id <id>`.
- On Windows, a killed fingerprint evaluation leaves its workspace claim behind ([#6454](https://github.com/appandflow/stim/issues/6454)). `stim stop` prints the `Remove-Item` command to run once the pid it names is gone.

## Migration notes

The steps under Upgrade, with what each one needs. Do them in order on each machine. The [upgrade guide](https://stim.appandflow.com/docs/migrate-to-2) explains each one, and its [For agents](https://stim.appandflow.com/docs/migrate-to-2#for-agents) section is the checklist an agent follows after the install.

1. **With 1.40 still installed, stop your workspaces.** Run `stim status`, then `stim stop` in each running workspace, in each Stim home you use. Keep the same `STIM_HOME`.
2. **Install 2.0:** `npm install --global stim@2.0.0`, or move the project's `stim` pin or `npx stim@...` to 2.0.0.
3. **Settle settings before any 2.0 command other than `status`, `settings`, `doctor` and `guide`,** because most others start `stimd`. Run `stim guide agent`: its STATUS line names what an earlier Stim left behind. `stim settings` and `stim doctor` list the leftover keys, and the refusals print the `stim settings` commands to run, each scoped to the layer that holds the key. Decide now whether to keep any 1.40 default (see Removed (breaking)), because the first `stimd` runs cleanup under the values then in force.
4. **Stop the 1.40 daemon.** `stim status` prints `Daemon: pid <n> from an older stim holds the daemon claim` with the stop command. Check the pid, then run it.
5. **Update everything that talks to `stim`:** Stim Desktop, the phone app, every service (`stim service install` with its existing options), and then every offload worker, as `stim doctor` prints it (see Removed (breaking)).
6. **Update project files and scripts.** From the repository root, `git grep -nE '@stim-cli/|stim-server|stim-ci|stim gc|gc\(|"stim": *"'` finds most of what to change; also check the JavaScript API renames and subpath imports. Removed (breaking) says what each becomes.
7. **Check and build.** Run `stim doctor` (only in a checkout whose project code you trust: its fingerprint checks evaluate project configuration) and `stim guide agent` until STATUS is clear. Expect one cold native build per fingerprint, since 2.0 uses new cache keys. A monorepo whose Node version is pinned only at the repository root (`.nvmrc`, `.node-version`, `.tool-versions` or `volta.node`) now fingerprints under that Node, the one Metro runs, and `stim doctor` reports the pin: expect one more cache miss there, and with a root pin older than Node 22.15 an app config that loads a script as a module gets no cache key, so the build runs uncached and `stim doctor` says to use Node 22.15 or later. Save manual edits in an untracked, generated Expo `ios/` or `android/` first: the first 2.0 run prebuilds it once. If a worktree warmed by 1.40 reports a lockfile newer than its npm install stamp, run `npm install` in the directory the warning names.

A Chrome started by a 1.x `stim web` keeps its old log writer, so `stim logs` shows each web line twice until that workspace is stopped and started again. Metro continues across the upgrade: the live 1.40 to 2.0 checks kept the original Metro process and verified the same bundle on macOS, Linux and Windows ([results](https://github.com/appandflow/stim/issues/5590#issuecomment-6888597398)). `stim guide agent`'s STATUS line, the leftover refusals and the matching `stim doctor` findings link to the For agents section, and the line clears once nothing is left.
