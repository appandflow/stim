# 2.0.0

This release covers the two published npm packages, `stim` and `@stim-cli/cache-s3`. The other eleven `@stim-cli` packages that 1.40.0 published are bundled into `stim` and no longer publish (see Removed (breaking)). The base is v1.40.0, the last stable release, and this list covers the commits after it up to `b1338aef9`. Stim Desktop and the phone app ship through their own workflows; their changes are listed where they belong to a feature below. Every commit since v1.40.0 has an entry in this file.

To upgrade, read the [Stim 2.0 upgrade guide](https://stim.appandflow.com/docs/migrate-to-2). It has the step order, the commands and the tables of old and new names. Migration notes below say who is affected.

## New

- **One resident `stimd` per Stim home runs the long-lived work.** `stimd` runs the dev server (Metro), the managed tunnel, device log streams, and the observers of owned Chrome and macOS apps, and runs the maintenance passes. The dev server supervisor and the per-workspace collectors are gone. A command that needs one of these services starts `stimd` whatever `daemon.mode` says; `daemon.mode` now governs only the automatic passes. `stimd` keeps its device log streams and dev server output across a crash, an update and a restart, a command in flight reconnects once, a `stimd` of another build is handed over to, and every exit is recorded with its cause. A `stimd` that crashes repeatedly is held back, and `stim status` and `stim doctor` show that. ## Migration notes

The [Stim 2.0 upgrade guide](https://stim.appandflow.com/docs/migrate-to-2) has the step order and the tables of old and new names. The breaking changes above say who is affected.

- **Stop workspaces on 1.40 before installing 2.0.** Run `stim stop` in each running workspace, in each Stim home you use, and keep the same `STIM_HOME`. A Chrome started by a 1.x `stim web` supervisor keeps that supervisor's log writer and 2.0 attaches its own, so `stim logs` shows each web line twice until the workspace is stopped and started again. Update Stim Desktop, the phone app and every worker.
- **Expect one cold native build per fingerprint.** The 2.0 fingerprint uses new keys, so a build whose only cache entry came from 1.40 misses once. An untracked, generated Expo `ios/` or `android/` with a prebuild record from an earlier Stim runs `expo prebuild` once per generated worktree, so save manual edits first. A tracked directory is never regenerated. A record this Stim cannot read refuses with `STIM_PREBUILD_FAILED` and a `mv ios ios-<date>` command. The worker wire protocol is peer 3 and build compatibility is 6.
- **Update Stim Desktop together with `stim` 2.0.** Stim Desktop 0.3.0 cannot connect to a 2.0 engine.
- **Run `stim doctor` only in a checkout whose project code you trust.** Its fingerprint checks now evaluate project configuration, including `fingerprint.config.js`, and autolinking in an isolated child process.
- **Metro continues across the upgrade.** The live 1.40 to 2.0 checks kept the original Metro process and verified the same bundle on macOS, Linux and Windows ([results](https://github.com/appandflow/stim/issues/5590#issuecomment-6888597398)). Upgrades with paired clients and mixed-version app and engine combinations are still being verified in [#5593](https://github.com/appandflow/stim/issues/5593).

### Known limits

These items were closed or deferred before 2.0, and a 2.0 user can meet them.

- **A stimd that holds its claim but does not answer is reported, not replaced** ([#5774](https://github.com/appandflow/stim/issues/5774), still open; not a 2.0 gate by maintainer decision of 2026-11-17). `stim status` and `stim doctor` say `did not answer within 3 s` with the pid (finding `stimd-not-answering`, `daemon.unanswered` in `--json`), and neither stops the process. A command that needs the daemon refuses with `STIM_DAEMON_UNAVAILABLE` after about 60 seconds for a stopped stimd and about 10 seconds for a deleted socket file. Follow the remedy `stim doctor` prints and check the pid before you stop it. A stimd that is only slow under load can stall for 90 seconds, so do not stop one on a single probe.
- **`stimd` does not restart by itself** ([#5579](https://github.com/appandflow/stim/issues/5579), closed as not planned). The 2.0 stimd records every exit and holds back after repeated crashes, and `stim doctor` reports the abnormal exits of the last day, but nothing on the plain CLI path starts a new one until the next command that needs it.
- **A worker restart cancels its offloaded builds** ([#5588](https://github.com/appandflow/stim/issues/5588), closed as not planned). A build running for another machine is tied to the worker's stimd. When that stimd exits or is replaced during the build, the client's attach finds no job and restarts the build from the start, up to twice, then reports `offload-failed`. An engine update waits for running builds to drain; a crash or a forced restart does not. Retry the build after the worker is back.
