# 1.3.0

## New

- Run multiple simulators, emulators, and physical devices per workspace with `--slot <name>`. Reuse named assignments, inspect per-slot logs, and stop one slot while preserving Metro and sibling devices. There is no fixed slot count; configured caps and host resources still apply. [c531b2ad0d](https://github.com/appandflow/stim/commit/c531b2ad0d)
- Download compatible EAS development builds with `--eas-profile <name>` for local or remote targets. Missing builds produce an explicit EAS build command; Stim does not start a cloud build automatically. [18613c83fe](https://github.com/appandflow/stim/commit/18613c83fe)

## Migration notes

Existing assignments remain in the default slot. Preserve ownership state when upgrading; do not delete it. Use a slot-aware CLI consistently while named assignments exist, since older versions cannot manage them.

Slots share Metro and compatible build caches. Shared Metro events cannot verify an individual slot's Debug launch, so it may be reported as `unverified`; inspect the intended device before claiming success. Reload remains platform-wide, and named remote sessions are unsupported. Physical-device signing and lease requirements still apply. The parked-device pool policy is unchanged.

## QA

All iOS and Android loop/cache jobs passed in the [full native run](https://github.com/appandflow/stim/actions/runs/34726498315). Its Expo pool timeout led to the idle-workspace fix; both corrected pool jobs then passed in the [focused run](https://github.com/appandflow/stim/actions/runs/34728590028), using the unchanged standard runners. Local bare/Expo iOS loop, cache, and pool suites passed, including three simultaneous simulator slots and concurrent build-cache races. The final combined source passed 4,332 unit tests (one skip), 87 end-to-end tests, build, type, lint, runtime, and website checks.

The release owner authorized reusing the completed feature QA rather than repeating it for the version-only release candidate. Packaging inspection, CLI version/help/guide checks, and exact-release-commit CI remain required before tagging. Physical-device installs and authenticated EAS downloads were not exercised in this campaign; their command and lease paths have regression coverage.
