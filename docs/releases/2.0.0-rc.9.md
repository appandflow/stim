# 2.0.0-rc.9

Install `stim@2.0.0-rc.9` to try the ninth Stim 2.0 release candidate. The optional S3 cache provider is available as `@stim-cli/cache-s3@2.0.0-rc.9`.

## New

- `stim worktree add [-b <branch>] <path> [<commit-ish>]` creates a linked worktree with the path, `-b <branch>` and commit of `git worktree add`, no other option of it, and warms it, so `git worktree add` followed by `stim worktree warm` becomes one command. `stim worktree warm` stays for a worktree something else created. On macOS and Linux, with the new path on the source checkout's volume and a file system that clones (APFS, btrfs or XFS), it clones the source checkout, tracked and ignored files together, and git rewrites only the tracked files that differ from the commit: this saves disk, not time. On a checkout with 3.9 GB of `node_modules`, a new worktree 50 commits behind took 9 MB of private disk instead of 113 MB, and none at the source checkout's own commit, in about the same time as the two commands. The source checkout's uncommitted edits, staged changes and untracked files do not come along, and submodule folders start empty. Anywhere else, when the source index marks a file assume-unchanged or skip-worktree, or when the clone fails, git creates the worktree and the warm copies into it, and the command prints which way it took and why (`unsupported`, `cross-device`, or `failed` with the errno name). The tracked files are the same either way, in bytes, permission bits, names and extended attributes: a cloned file is kept only when it is exactly what `git worktree add` writes, and git writes the rest, such as a file a filter, `ident`, an encoding or a line-ending rule converts. A cloned file keeps only its modification time, usually a file flag such as `hidden`, and macOS's `com.apple.provenance` attribute from the source checkout. The plain path is also taken with a git older than 2.41, under `core.autocrlf=true`, `core.eol=crlf`, `core.symlinks=false` or `attr.tree`, for two tracked paths that differ only in case, and for a tracked folder spelled another way on disk. [#6551](https://github.com/appandflow/stim/issues/6551) The API gains `addWorktree({ path, branch, commitish })`. - Stim clones with the prebuilt binary of `cow-clone`, a new dependency of `stim`, instead of a C helper compiled with the Xcode Command Line Tools on first use. `stim worktree warm` and `stim worktree add` no longer need the Command Line Tools to clone on macOS, and they now clone on Linux (btrfs, XFS), file by file, where they copied before. On Windows `stim worktree warm`, and the warm inside `stim worktree add`, clone the ignored folders on ReFS and a Dev Drive, and links in a cloned folder that pointed into the source checkout point into the worktree, as they do after a copy. `stim worktree add` still lets git check out the tracked files on Windows, because git there writes through the junctions a clone keeps ([#6554](https://github.com/appandflow/stim/issues/6554)). On a file system that cannot clone, warm copies with `cp -R` as before; it no longer tries `cp -Rc` first. A cloned ignored folder keeps each file's mode and modification time, where a copy applies the umask and the current time. An old `stim-clonefile-*` binary under `$STIM_HOME/helpers` is no longer used and can be deleted.
