# 1.9.0

## New

- `stim status --watch` streams status: with `--json` it prints one complete payload per line, immediately and then on every change, and never repeats an identical payload. It reacts to Stim state changes, `adb track-devices`, and simulator state, and exits cleanly on SIGINT, SIGTERM, or a closed stdout. [#1080](https://github.com/appandflow/stim/pull/1080)
- `stim status` reports the build in progress for each workspace: platform, slot, phase (`prepare`, `cache-lookup`, `wait`, `prebuild`, `pods`, `compile`, `install`, `launch`), elapsed time, and an estimate from the median of comparable previous runs. A build whose process is gone shows as `stale`. [#1078](https://github.com/appandflow/stim/pull/1078)
- `stim settings` reads and writes settings by scope: `stim settings --json` lists every setting's effective value, origin layer, and per-layer values; `get`, `set`, and `unset` take `--scope machine|workspace|repo|committed`. One registry now defines every setting, and the package ships a JSON Schema (`dist/settings.schema.json`) that `.stim.json` can reference with `"$schema"`. [#1079](https://github.com/appandflow/stim/pull/1079)
- `stim status` lists each workspace's remote EAS Simulator sessions with their preview URL; plain `status` marks them billable. [#1077](https://github.com/appandflow/stim/pull/1077)
- `stim gc --json` prints the report as JSON, and `gc` reclaims workspace build outputs, orphaned workspace directories, and finished worktrees. [#1043](https://github.com/appandflow/stim/pull/1043), [#1021](https://github.com/appandflow/stim/pull/1021)
- `iosSimulatorApp: "stim-desktop"` and `stim ios --simulator-app stim-desktop` open owned simulators in Stim Desktop instead of Device Hub. [#1057](https://github.com/appandflow/stim/pull/1057)
- `stim ios --device` installs on Wi-Fi-paired iPhones. [#1020](https://github.com/appandflow/stim/pull/1020)
- Owned Android emulators boot with their gRPC endpoint enabled on `127.0.0.1` (console port + 3000) with token authentication, so tools can stream frames from headless emulators. [#1064](https://github.com/appandflow/stim/pull/1064)

## Performance

- `stim status` is about 20 times faster (about 3.3 s to 0.18 s on a machine with 21 workspaces): error counts come from a per-workspace index that reads only newly appended log bytes, and device, git, and port lookups run once per call and in parallel. The first run after upgrading builds the index. [#1081](https://github.com/appandflow/stim/pull/1081)
- Workspace NDJSON logs are capped, and the timeline is read once per query. [#995](https://github.com/appandflow/stim/pull/995)

## Stim Desktop

The repository now contains Stim Desktop (`apps/desktop`), a macOS app for supervising Stim workspaces: live iOS and Android frames with take-over input, projects, logs, build progress, resource usage, settings, and cleanup actions through the CLI. It is not part of the npm packages and is not distributed yet; build it with `apps/desktop/scripts/bundle.sh`. [#1047](https://github.com/appandflow/stim/pull/1047)

## QA

No-QA stable release explicitly authorized by the maintainer on 2026-09-25.
Omitted locally before the version commit: format:check, lint, typecheck, knip,
unit tests, test:e2e, test:runtime, test:compat, and the pre-tag native/manual
matrix, which `scripts/release-qa-matrix.mjs v1.8.0` marks fully required (8 of
8 rows). Retained before the version commit: candidate build, CLI
version/help/guide, and tarball inspection. Retained after push:
exact-release-commit CI, including its format, lint, build, typecheck, knip,
unit, cross-platform e2e, and published-runtime jobs.

Unlike earlier no-QA releases, most changes from #1047 onward were merged
without a review and before their CI finished, at the maintainer's request.
Main CI was restored to green in #1086 and #1084 before this release.
Individual pull requests record their own real-tool checks (throwaway
simulators and emulators, a scratch Expo app build for build progress, a
scratch `STIM_HOME`); the native E2E suites were not run against this version.
A real EAS Simulator session was not exercised: #1090 tracks an early refusal
for eas-cli versions without simulator commands.
