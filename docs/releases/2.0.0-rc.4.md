# 2.0.0-rc.4

Install `stim@2.0.0-rc.4` to try the fourth Stim 2.0 release candidate. The optional S3 cache provider is available as `@stim-cli/cache-s3@2.0.0-rc.4`.

## New

- **Workspace services.** A project declares its databases, API servers and workers once, in the `services` setting of its committed `.stim.json`, and each workspace runs its own copy on its own named ports. `stim services start` starts them, dependencies first. `stim services` lists them, `stim services env` prints their environment as shell exports, and `stim services stop` stops them. A service without a `stop` command is a process Stim supervises, with its output in the workspace's `logs/service-<name>.log`. A service with a `stop` command (a `docker compose` or local database stack, for example) is run through its `stop`, `teardown` and `orphanTeardown` commands. Stim stops running services once the workspace has been idle for `idle.minutes`, `stim revive` starts again what it stopped, and `stim worktree remove` tears them down before anything else; a failed teardown refuses the removal and keeps the worktree, and `stim status` shows the command to run by hand. While a service runs, its ports are reversed to the workspace's devices. `stim status` lists started services, and `stim test` passes their environment to the test command. `stim start` does not start services. Run `stim guide services` for the setting's fields and worked examples, or see [Workspace services](https://stim.appandflow.com/docs/dev-server-and-logs#workspace-services). [2e02bc41c0](https://github.com/appandflow/stim/commit/2e02bc41c0a37079ca10fca7da939901319cc3c3)
- The machine setting `concurrency.testWorkers` (environment `STIM_TEST_WORKERS`) fixes the worker count `stim test` passes to Jest, Vitest or `node --test`. The default, `0`, derives the count as before; a fixed count is not reduced under load. [7726205dfb](https://github.com/appandflow/stim/commit/7726205dfb14b62f0d4655262de817312c889668)

## Fixes

- A hosted iOS or Android agent-device launch that fails no longer blocks the device until stimd restarts. Each launch gets its own agent-device state, and the next launch first retires the previous one. [e2fff3d64d](https://github.com/appandflow/stim/commit/e2fff3d64d4bc8e164215273c419c99696768753)
- Retiring an earlier hosted launch, and reclaiming a workspace with `stim worktree remove` or `stim gc`, wait out agent-device 0.21.42's forced daemon stop (75 s after SIGTERM) instead of giving up after 20 s and keeping the claim or the workspace. [8db20ca45a](https://github.com/appandflow/stim/commit/8db20ca45af21ca12c95b7096154b31c649d5267) [eb6d40148b](https://github.com/appandflow/stim/commit/eb6d40148bdca4dff15203bf2029e8a228972cd8)
- `stim gc` and automatic maintenance list, count and remove each hosted agent-device launch directory that has been idle for 24 hours and whose daemon agent-device reports stopped, and `stim gc --dry-run` shows them. gc never stops a daemon. [c191ca825f](https://github.com/appandflow/stim/commit/c191ca825f747585fbb9af4efdee903e4d1114a1)
- The hosted agent-device state that a 2.0.0-rc.3 server left in its temporary directory is retired by the first launch in that hosted session after the upgrade, and removed by `stim gc` once it has been idle for 24 hours and its daemon is stopped, instead of running beside the new launch or staying forever. [3d732663c9](https://github.com/appandflow/stim/commit/3d732663c97fc4ef13909dacab3c2d85c3abfc64)

## Migration notes

- **Hosts upgrading from 2.0.0-rc.3.** If an rc.3 server exited without stopping its hosted agent-device daemon and that daemon still runs, it keeps that hosted session's claim, so agent control does not start in that session. The hosting Mac's server log reports the agent-device daemon claim as held by another process or as unresolved, and an unresolved claim comes with the command that clears it once the daemon is gone. This lasts until agent-device's idle reaper ends the daemon once its lease expires, or until that command is run. The next launch in that session then retires the daemon. [3d732663c9](https://github.com/appandflow/stim/commit/3d732663c97fc4ef13909dacab3c2d85c3abfc64)

For upgrade steps, see the [Stim 2.0 upgrade guide](https://stim.appandflow.com/docs/migrate-to-2).
