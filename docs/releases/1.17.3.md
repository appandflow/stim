# 1.17.3

Stim Desktop and the Stim phone app ship through their own workflows; this release covers the six npm packages. Commits that only changed those apps are not listed.

## Behaviour changes

- **Automatic maintenance is on by default.** `maintenance.mode` defaults to `on` where it was `report`. A background pass, started by CLI commands and `stim status --watch` when a check is due, now removes what `stim gc --delete` removes: orphaned workspace directories and stale cache registrations, build outputs of idle workspaces, least recently used build-cache and Metro entries over their caps, the age sweep, the Swift compilation cache (emptied whole, only below the hard free-disk floor), and linked worktrees whose branch is merged or whose pull request was merged or closed. Worktree removal follows gc's finished-worktree rules, including the `gc.worktreeGraceMinutes` grace period (default 120 minutes), so a worktree that changed recently is kept; gitignored files do not count as changes, and a worktree with uncommitted or untracked files, unpushed commits, a running dev server, a booted owned device or a `maintenance.keep true` pin is kept. Every action is logged (`stim logs --source maintenance`, `stim status --json`). Turn it off with `stim settings set maintenance.mode off`, or keep only the plan and the log with `stim settings set maintenance.mode report`; `stim settings set maintenance.removeFinishedWorktrees false` turns off only worktree removal. A scratch or test home (`STIM_HOME` set) and CI force it `off` unless `STIM_MAINTENANCE` is set, even over a configured `maintenance.mode`. [888d4f45b](https://github.com/appandflow/stim/commit/888d4f45b9a6246ac25330ad8cd24ded2b7d81df), [b925c4639](https://github.com/appandflow/stim/commit/b925c4639bfcf2a7b315f314a6a9dfea5e046cfa)
- **`stim-server setup` approval prompts default to Yes.** Each per-grant question reads `[Y/n]`. Enter, `y` and `yes` approve; `n`, `no` and any other answer decline. Keys typed ahead before the prompt appears are discarded, so an Enter pressed earlier does not approve a grant. `--yes` and the no-terminal refusal are unchanged. [422f5ba35](https://github.com/appandflow/stim/commit/422f5ba35c0d77af172a1b4f4f6cb533afaf32e6)

## New

- **`stim` exports a programmatic API.** `import { createStim } from 'stim'` gives a client with `run`, `stop` and `diagnostics` that call the same lifecycle operations as `stim ios|android|macos|web`, `stim stop` and `stim logs`, in a bundled worker, with typed results, `StimError` failures and `AbortSignal` cancellation. See the website's Programmatic API page. [d90965a5b](https://github.com/appandflow/stim/commit/d90965a5be05e722f572c7a05b92b5b54acbdf7f)
- **Automatic maintenance acts under `maintenance.mode on`.** New settings: `maintenance.worktreeCheckMinutes` (15), `maintenance.sweepHours` (24), `maintenance.olderThanDays` (7), `maintenance.protectRecentHours` (2), `maintenance.removeFinishedWorktrees` (true), the project setting `maintenance.keep` (pins a workspace so a pass never clears its outputs or removes its worktree) and `caches.ccacheMaxGb` (5). `stim status --json` maintenance data gains `worktree` and `sweep` entries in `lastChecks`, and plan actions carry `dir`, `olderThanDays` and `check`; `lastPass.mode` can be `on` with the bytes freed. `stim status` and `stim gc` print an "Auto maintenance (on)" line with the action count and space freed. Disk-driven steps stop once free space is back above the floor. [b925c4639](https://github.com/appandflow/stim/commit/b925c4639bfcf2a7b315f314a6a9dfea5e046cfa)
- **`--plan` works with `ios.remote` or `android.remote` set to `auto` or a Mac name.** Instead of refusing with `STIM_BAD_ARG`, the plan asks that Mac for its device (a read-only probe, nothing reserved) and reads the architecture or ABI from it. With `auto` it repeats the placement decision a run would make now. `--json` gains `placement`, for example `on janics-mac-mini` or `this Mac; auto may use janics-mac-mini`, and the plain output prints a `placement` line. `eas`, `proxy` and a Mac that does not answer still refuse with `STIM_BAD_ARG`. [e0edecf04](https://github.com/appandflow/stim/commit/e0edecf044944da4a05f1d71a0d1f4b16e435055)
- **`build.offer` reports memory** (`@stim-cli/server`, `@stim-cli/core`). The capacity block gains `memoryUsedBytes` (Activity Monitor's Memory Used) and `memoryTotalBytes`; they are omitted when the worker cannot read its memory, and absent from an older stim-server. `stim doctor --json` carries them for each remote Mac. [2a6af4023](https://github.com/appandflow/stim/commit/2a6af40232bff4cc05fc2551a7b480d0ab9b2ec7)
- **`stim macos` builds record their launch time and compile step count.** `environments[].builds.macos` in `stim status --json` includes `launch` in `phases` once the launch step finishes, and `compileSteps`, SwiftPM's step total. [494cd2d54](https://github.com/appandflow/stim/commit/494cd2d54e0076802f61ab6204193d94740e7ff2)
- **`stim doctor --json` gives the finding for a directory that is not a React Native or Expo app the code `not-an-app`.** [c9b8f12ce](https://github.com/appandflow/stim/commit/c9b8f12cee56ca9d2a3a7b33ca81713d5a189bfb)

## Fixes

- `stim worktree warm` moves a carried `ios/Pods` to the worktree's path, so the first `stim ios` skips `pod install`. When `Podfile.lock` and the carried `Pods/Manifest.lock` differ only by checksums of podspecs that embed the source checkout's path (the precompiled ExpoModulesCore), warm rewrites the source path in `Target Support Files`, `Pods.xcodeproj`, `Local Podspecs` and absolute symlinks and makes `Manifest.lock` match. When the locks already match but Pods still name the source path, warm applies the same rewrite. If carried `node_modules` do not match the worktree's lockfile, another file still names the source path, or the move fails, `stim ios` still runs `pod install`: when the locks matched, warm deletes `Pods/Manifest.lock` to force it, and when they differed, the differing `Manifest.lock` stays. Warm never edits `Podfile.lock`. [82ee9c46c](https://github.com/appandflow/stim/commit/82ee9c46c256b228c7daa11b5886d285acb82f7e), [33797014c](https://github.com/appandflow/stim/commit/33797014c8d8fdc9aa141385d91a52b05c60ba68)
- `stim ios` lists simulators once for the budget gate, the capacity check and device setup, and lists them again only after a budget reclaim, instead of once for each. [a76467c6e](https://github.com/appandflow/stim/commit/a76467c6e5d4c2c7a6f000b5cbb14c8cdebf92c7)
- The CocoaPods version that `stim doctor`, a build offload and `build.offer` compare is read in the project's Ruby environment (its `.ruby-version`, with a UTF-8 locale), the one `pod install` uses, instead of the machine's default Ruby. `build.offer` takes an optional `rubyVersion`, and the worker caches its toolchain report for 60 seconds per Ruby version. [05ebc115d](https://github.com/appandflow/stim/commit/05ebc115d3ba968ca43bde35bbde1d1cff97d45f)
- stim-server (`@stim-cli/server`) answers a client's `hello` with its host health probe running alongside the identity check, not after it, and reads `tailscale status` without blocking the event loop in `serve`, `pair` and `service`. [93a418c2d](https://github.com/appandflow/stim/commit/93a418c2d64d93d13c40d46bdc731d6a6a3600b6)
- The hosted relay waits 20 seconds, where it waited 10, for a hosted Mac to answer a request. When it does not, the error reads "the host was busy or slow: it did not answer `METHOD` within 20 seconds", where `METHOD` is the request's method name. [93a418c2d](https://github.com/appandflow/stim/commit/93a418c2d64d93d13c40d46bdc731d6a6a3600b6)
- Phone push notifications are quieter. stim-server notifies "Agent stopped" once per workspace per run, where a run ends when the workspace goes idle, and notifies at most one needs-attention item per workspace per run, which starts over when the workspace stops being idle or has no item left. A pull request that became ready or merged keeps its own notification. In the phone app, Work started defaults to Off. [30195c49e](https://github.com/appandflow/stim/commit/30195c49e24cea1fded6756212718b0ffc9da5d7)

## QA

Pre-tag QA is omitted by the maintainer's explicit decision on 2026-10-08 ("release now"). The maintainer QAs right after the release, as with 1.17.2. This deviates from RELEASE.md section 3, which has no waiver for a stable version.

Omitted before the tag, all eight rows of the matrix (`node scripts/release-qa-matrix.mjs v1.17.2 --until <head>`; 330 changed paths, 71 mapped to a row, 0 unclassified): loop, logs, caches, real-repository, remote-provider, release-build, android-flavor and launch-evidence, plus the native suites `run-native-e2e.mjs` and `run-cache-e2e.mjs`.

Run before the version commit: `format:check`, `lint`, `build`, `typecheck`, `knip`, `release:prep --check`, CLI version/help/guide, `licenses:check` in `apps/mobile`, and pnpm tarball inspection of the six packages. Not run locally, left to CI by the maintainer's decision of 2026-10-08: `pnpm test`, `test:e2e`, `test:runtime` and `test:compat`. Run after push: exact-commit CI, including the full Windows job, and the Release workflow's own gates.
